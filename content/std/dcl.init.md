[dcl.init] 是整本标准里被抱怨最多的条款之一：`T x;`、`T x{}`、`T x()`、`T x = v`、`T x(v)`、`T x{v}`、`T x = {v}` 看上去只是写法不同，结果却可能是"未初始化"、"清零"、"调用 `initializer_list` 构造函数"、"根本不是变量而是函数声明"。
但这些结果并不是随意的：它们全都由本节 ¶15 的**一条决策流程**决定，而流程中用到的几个"基本动作"（零初始化、默认初始化、值初始化）也都在本节定义。读懂本节，其余四个子条款就只是这条流程的分支展开：

## 适用范围与语法（¶1）

¶1 本节描述的初始化过程适用于**所有**初始化，不论语法位置：变量声明里的初始化器只是最显眼的一种，函数实参初始化形参（[[expr.call]]）、`return` 初始化返回值（[[stmt.return]]）、`throw` 初始化异常对象，都是"初始化"，都走同一套规则。

这一点是理解后文的钥匙：`f(x)` 中形参的初始化、`return x;` 中返回值的初始化，和 `T p = x;` 是**同一回事**——都是拷贝初始化（¶13）。所以 `explicit` 构造函数不能用于隐式传参，原因和不能用于 `T p = x;` 完全一样。

初始化器的语法可以整理成四种基本形式（外加 C++20 的指派初始化器）：

| 写法 | 文法 | 名称 |
|---|---|---|
| `T x = expr;` | *brace-or-equal-initializer* → `= initializer-clause` | 等号形式 |
| `T x = { … };` | `= braced-init-list` | 等号 + 花括号 |
| `T x( … );` | `( expression-list )` | 圆括号形式 |
| `T x{ … };` | *braced-init-list* | 花括号形式 |
| `T x{ .m = … };` | *designated-initializer-list* {{c++20}} | 指派初始化器 |

几个文法细节值得注意：

- *braced-init-list* 允许尾随逗号 `{1, 2, 3,}`，也允许空 `{}`。
- *initializer-clause* 后可以跟 `...`，即包展开（¶17）。
- *designated-initializer-list* 的文法是"先若干普通子句、再若干指派子句"（`initializer-list , designated-only-initializer-list`）。这是当前草案为支持**基类的指派初始化**而放宽的文法；在 C++20/23 中只允许"全指派"。即使在当前草案中，前面的普通子句也只能用来初始化**基类子对象**（[[dcl.init.aggr]] ¶4.1），所以 `A{1, .y = 2}` 这种"普通成员 + 指派成员"的混用仍然非良构。
- `()` **不是**合法的 *initializer*：`T x();` 声明的是函数（见 ¶15.4 的注）。

注 1 说：即使某个上下文的文法只允许 *brace-or-equal-initializer*（例如类内的默认成员初始化器不能写圆括号），本节规则照样适用。

## 初始化器可以是任意表达式（¶2–¶4）

¶2 除了 `constexpr` 变量（要求常量表达式，见 [[dcl.constexpr]]），变量的初始化器可以是由字面量、**此前声明过**的变量和函数构成的任意表达式，**与存储期无关**。这是 C++ 与 C 的一处显著差异：C 要求静态存储期对象的初始化器是常量表达式，C++ 允许

```cpp run ok
int f(int x) { return x * 2; }
int a = 2;
int b = f(a);   // 命名空间作用域变量，用函数调用初始化：C 中非法，C++ 中合法
int c(b);
int main() { return c == 4 ? 0 : 1; }
```

代价是**动态初始化**以及随之而来的"静态初始化顺序灾难"——见 [[basic.start.dynamic]]。

¶3（注）默认实参受更多限制，见 [[dcl.fct.default]]。¶4（注）静态存储期变量的初始化顺序见 [[basic.start]] 与 [[stmt.dcl]]。

## 三个基本动作：零初始化、默认初始化、值初始化（¶5–¶9）

¶15 的决策流程最终会落到几个"原子动作"上。它们的名字很像，但含义差别很大：

| 动作 | 直觉 | 对 `int` | 对有用户提供默认构造函数的类 | 对没有用户提供默认构造函数的类 |
|---|---|---|---|---|
| 零初始化 | 按位清零（概念上） | `0` | 所有成员清零，**不**调用构造函数 | 同左 |
| 默认初始化 | "什么都不写"时发生的事 | **不初始化** | 调用默认构造函数 | 调用（隐式）默认构造函数，标量成员不初始化 |
| 值初始化 | "写了空括号"时发生的事 | `0` | 调用默认构造函数 | **先清零**，再调用默认构造函数 |

### 零初始化（¶5）

¶5 **零初始化**（zero-initialize）类型为 `T` 的对象或引用：

- ¶5.1 {{c++26}} `T` 是 `std::meta::info`（静态反射，[[P2996R13]]）：初始化为**空反射值**（null reflection）。`meta::info` 是标量类型，但"把整数 0 转换为 `meta::info`"没有意义，所以单独列出。
- ¶5.2 其他标量类型：初始化为"整数字面量 `0` 转换为 `T`"的值。注意措辞——不是"所有位为零"！对指针，这得到**空指针值**（脚注指向 [[conv.ptr]]）；对成员指针，得到空成员指针值。在 Itanium ABI 上，空的数据成员指针表示为 `-1` 而不是全零位，所以"零初始化"和 `memset(…, 0, …)` 并不等价。对浮点类型得到 `+0.0`。
- ¶5.3 非联合类：**填充位**（padding bits）置零，每个非静态数据成员、每个非虚基类子对象，以及（仅当它不是基类子对象时）每个虚基类子对象，递归零初始化。
- ¶5.4 联合：填充位置零，**第一个具名**非静态数据成员零初始化。
- ¶5.5 数组：每个元素零初始化。
- ¶5.6 引用：**不做任何事**。引用没有"零"可言。

为什么虚基类有"若不是基类子对象"的限制？因为虚基类子对象只由**最派生类**负责构造（[[class.base.init]]）；作为基类子对象被零初始化时，它的虚基可能根本不在它"以为"的位置上。

零初始化在哪里发生？三处：静态/线程存储期变量在一切其他初始化之前（[[basic.start.static]]）；值初始化的第一步（¶8.1、¶8.3）；以及列表初始化/聚合初始化中某些成员的兜底。

```cpp run ok
#include <cassert>
struct P { int i; double d; int* p; };
P g;                  // 静态存储期：先零初始化，没有其他初始化
int main() {
  assert(g.i == 0 && g.d == 0.0 && g.p == nullptr);
  static int s;       // 同样零初始化
  assert(s == 0);
}
```

### 默认初始化（¶6）

¶6 **默认初始化**（default-initialize）类型为 `T` 的对象：

- ¶6.1 类类型：以 `()` 为初始化器做构造函数的重载决议（[[over.match.ctor]]），用空实参列表调用选中的构造函数。若没有可用的默认构造函数（被删除、不可访问、有歧义），程序非良构。
- ¶6.2 数组：先检查"默认初始化一个假想元素"的语义约束（这保证 `T a[0]`/空数组也会检查 `T` 是否可默认构造），然后每个元素默认初始化。
- ¶6.3 {{c++26}} `std::meta::info`：零初始化（即空反射）。这是唯一一个默认初始化也会给出确定值的标量类型——设计者不希望 `meta::info` 出现"不确定值"。
- ¶6.4 其他（标量）：**不做任何初始化**。

¶6.4 是 C++ "零开销"原则的体现：`int buf[4096];` 不应该被强迫清零。但这也是 C++ 最大的安全隐患之一——"没有初始化"的对象里装着什么，由 [[basic.indet]] 回答（见后文"未初始化的自动变量"）。

注意默认初始化对类类型调用的是**构造函数**；如果那是隐式定义的默认构造函数，它对标量成员同样什么都不做：

```cpp
struct S { int i; std::string s; };
void f() {
  S x;        // 默认初始化：调用隐式默认构造函数；s 被构造为空串，x.i 未初始化
}
```

### 常量对象与 const-default-constructible（¶7）

¶7 若程序要求默认初始化一个 const 限定类型 `T` 的对象，`T` 必须是 **const 可默认构造**（const-default-constructible）的。满足以下任一即可：

- ¶7.1 `std::meta::info`；¶7.2 `std::nullptr_t`（它只有一个值，"不初始化"也不会出错）；
- ¶7.3 默认初始化会调用 `T` 的**用户提供的**构造函数（不能是从基类继承来的）；
- ¶7.4 类类型且：每个直接非变体非静态数据成员要么有默认成员初始化器、要么本身是 const 可默认构造类型（¶7.4.1）；若是有成员的联合，恰好一个变体成员有默认成员初始化器（¶7.4.2）；若不是联合，每个匿名联合成员的类型是 const 可默认构造的（¶7.4.3）；每个潜在构造的基类都 const 可默认构造（¶7.4.4）；
- ¶7.5 元素类型 const 可默认构造的数组。

动机：`const` 对象之后不能再赋值，如果默认初始化留下了未初始化的成员，这个对象就**永远**是不确定值，几乎一定是 bug。早期标准的规则更粗暴——"必须有用户提供的默认构造函数"——连 `struct Empty {}; const Empty e;` 都被拒绝。¶7.4 是后来放宽的结果：只要"每个成员都有着落"就行。

```cpp
struct A { int i; };
struct B { int i; B() {} };            // 用户提供的构造函数（哪怕它不初始化 i）
struct C { int i = 0; };
struct D { int i; D() = default; };    // 类内 =default 不是"用户提供"
struct F { };
union  U { int a; int b = 0; };

const A ca;      // error: A 不是 const 可默认构造的
const B cb;      // OK: ¶7.3（注意 cb.i 仍未初始化——规则只看"形式"）
const C cc;      // OK: ¶7.4.1
const D cd;      // error: D() = default 不是用户提供的
const F cf;      // OK: 没有成员，¶7.4 空真
const U cu;      // OK: ¶7.4.2
const int ci;    // error: 标量没有任何一条适用
```

`const B cb;` 是这条规则的漏洞：用户写了一个空构造函数，规则就放行了。标准选择信任"用户提供"这个信号。

### 值初始化（¶8）

¶8 **值初始化**（value-initialize）类型为 `T` 的对象：

- ¶8.1 类类型：设 `C` 是默认初始化时会被选中的构造函数。若 `C` **不是用户提供的**，先零初始化整个对象；无论如何，然后再默认初始化。
- ¶8.2 数组：检查假想元素的约束，然后每个元素值初始化。
- ¶8.3 其他：零初始化。

¶8.1 的两步设计非常精妙。考虑：

```cpp run ok
#include <cassert>
#include <string>
struct X {
  X() = default;          // 不是用户提供的
  int i;
  std::string s;          // 有非平凡构造函数
};
int main() {
  X x{};                  // X 不是聚合（有用户声明的构造函数），{} → 值初始化
  assert(x.i == 0);       // 先零初始化，i 变成 0；再调用隐式默认构造函数构造 s
}
```

如果只是"调用默认构造函数"，`x.i` 会是未初始化的；如果只是"零初始化"，`s` 不会被构造。两步组合恰好给出"程序员期望的 `X{}` 语义"：编译器生成的部分全部清零，用户写了构造函数的部分尊重用户。

反过来，只要构造函数是**用户提供的**——哪怕是类外 `= default`——值初始化就**不再清零**：

```cpp
struct Y { Y(); int i; };
Y::Y() = default;         // 首次声明时没有 =default → 用户提供的
Y y{};                    // 值初始化：C 是用户提供的，不清零；y.i 未初始化
```

"用户提供"（user-provided）的精确定义在 [[dcl.fct.def.default]]：用户声明的、且在**首次声明**时没有被显式 `= default` 或 `= delete` 的函数。这就是"类内 `= default`"和"类外 `= default`"的差异来源——一个经常让人困惑的点。

### 引用不能默认初始化或值初始化（¶9）

¶9 要求默认初始化或值初始化一个引用类型实体的程序非良构。例如 `int& r;`（引用缺少初始化器，[[dcl.init.ref]] ¶1 也禁止）、`new (int&)()`（这根本不合文法，但思路如此）、聚合中未被显式初始化的引用成员（[[dcl.init.aggr]] ¶6.3）。

### 静态初始化与"没有初始化器"（¶10–¶11）

¶10（注）每个静态存储期对象都会在程序启动时先进行**静态初始化**（[[basic.start.static]]：零初始化，或常量初始化），之后某些对象还会有动态初始化。

¶11 **没有指定初始化器的对象被默认初始化**。这一句是 `T x;` 语义的来源。结合 ¶10：

| 声明 | 存储期 | 效果 |
|---|---|---|
| `int g;`（命名空间作用域） | 静态 | 静态初始化阶段零初始化 → `0`；默认初始化不再做任何事 |
| `static int s;`（块作用域） | 静态 | 同上 → `0` |
| `int a;`（块作用域） | 自动 | 默认初始化 → 不初始化 → C++26 起是**错误值**（erroneous value） |
| `new int` | 动态 | 默认初始化 → 不初始化 → **不确定值**（indeterminate value） |

## 未初始化的自动变量：从 UB 到错误行为 {{c++26}}

这不是本节的段落，但 ¶6.4"不做任何初始化"的后果是理解初始化的必修课，所以放在这里讲清楚。

C++23 及以前：读取一个未初始化的 `int` 局部变量（除少数 `unsigned char` 的例外）是**未定义行为**。编译器可以假定它不发生，并据此做出任意优化。

C++26（[[P2795R5]]）：[[basic.indet]] ¶1 规定，自动存储期对象的存储在获得时，其字节具有**错误值**（erroneous value）——一个由实现决定、与程序状态无关的值。读取它是**错误行为**（erroneous behavior）{{erroneous}}：

- 程序仍然是"有错的"，实现**被鼓励**诊断（例如在调试构建中报告），也可以终止程序；
- 但如果实现不诊断，读到的就是那个固定的错误值，**不再是 UB**，编译器不能做"假定不会发生"的优化。

```cpp run eb
int f() {
  int x;          // 默认初始化：不初始化；x 的字节具有错误值
  return x;       // C++26: 错误行为（读取错误值）；C++23: UB
}
int main() { return f() & 0; }
```

需要注意的边界：

- **动态存储期**对象（`new int`）的字节仍然是**不确定值**，读取仍是 UB（[[basic.indet]] ¶1.1）。
- 可以用 `[[indeterminate]]` 属性（[[dcl.attr.indet]]）显式要求"不确定值"，恢复旧语义（例如为了性能，不希望编译器为大缓冲区写入模式值）。
- 若错误值对于类型无效（例如 `bool` 的位模式既非 0 也非 1），左值到右值转换仍是 UB（[[basic.indet]] 注 1、[[conv.lval]]）。

!!! impl
    实现上，"错误值"通常就是编译器在栈上预先写入的某个固定模式。Clang 和 GCC 早就提供了 `-ftrivial-auto-var-init=pattern|zero` 选项做类似的事情，C++26 的错误行为为这类做法提供了标准层面的语义。具体某个编译器版本在 `-std=c++26` 下是否默认开启自动初始化，请以其发行说明为准。

## 圆括号中只能有一个表达式（¶12）

¶12 若被初始化的实体**不是类类型也不是数组类型**，圆括号初始化器里的 *expression-list* 必须是单个表达式。

```cpp
int x(1, 2);      // error: 标量的圆括号初始化器只能有一个表达式
int y((1, 2));    // OK: 内层括号构成逗号表达式，y == 2
```

注意 `int x(1, 2)` **不会**被当作逗号表达式——文法上这是 *expression-list*，逗号是分隔符。数组的圆括号初始化（¶15.5）是 C++20 新增的，所以本段特意把数组排除在外。

## 拷贝初始化与直接初始化（¶13–¶14）

这是初始化中最重要的二分法。它不取决于"有没有拷贝"，而**只取决于语法上下文**：

¶13 **拷贝初始化**（copy-initialization）发生在：

| 上下文 | 例子 |
|---|---|
| *brace-or-equal-initializer* 的 `=` 形式 | `T x = e;`、`T x = {a, b};` |
| `=` 形式的 *condition* | `if (T x = e)` |
| 实参传递 | `f(e)` 初始化形参 |
| 函数返回 | `return e;` 初始化返回对象 |
| 抛出异常 | `throw e;` 初始化异常对象（[[except.throw]]） |
| 处理异常 | `catch (T x)` 从异常对象初始化 `x`（[[except.handle]]） |
| 聚合成员初始化（非指派） | `S s{e};`、`S s(e);` 中成员从 `e` 初始化 |

注 5：拷贝初始化可能调用**移动**构造函数（[[class.copy.ctor]]）。名字里的"拷贝"只是历史称谓。

¶14 **直接初始化**（direct-initialization）发生在：

| 编号 | 上下文 | 例子 |
|---|---|---|
| ¶14.1 | 圆括号 *expression-list* 或 *braced-init-list* 形式的 *initializer* | `T x(a, b);`、`T x{a};`、成员初始化器 `: m(a)` |
| ¶14.2 | *new-initializer* | `new T(a)`、`new T{a}` |
| ¶14.3 | `static_cast` | `static_cast<T>(e)` |
| ¶14.4 | 函数式类型转换 | `T(e)`、`T{e}` |
| ¶14.5 | *braced-init-list* 形式的 *condition* | `if (T x{e})` |

一个值得记住的不对称：聚合的**非指派**成员初始化总是拷贝初始化（¶13），而指派初始化器的形式是 *brace-or-equal-initializer*，所以 `.m = e` 是拷贝初始化、`.m{e}` 是直接列表初始化（[[dcl.init.aggr]] ¶5.2.1 注 3）。于是对 `struct P { E e; };`（`E` 只有 explicit 构造函数），`P{.e{1}}` 合法而 `P{1}`、`P{.e = 1}` 都非良构。

### 二者的实际差异

二者语义不同之处主要有三：

1. **`explicit` 构造函数与 `explicit` 转换函数**只在直接初始化中参与（[[over.match.ctor]]、[[over.match.copy]]、[[over.match.conv]]）。
2. **类类型从"不相关类型"的拷贝初始化**走 ¶15.6.3 的"用户定义转换"路径，而不是 ¶15.6.2 的"构造函数重载决议"路径：只考虑转换构造函数和转换函数，并且至多一次用户定义转换。
3. **`nullptr` → `bool`** 只在直接初始化中允许（¶15.8）。

```cpp
struct E { explicit E(int); };
E e1 = 1;                    // error: 拷贝初始化不考虑 explicit 构造函数
E e2(1);                     // OK: 直接初始化
E e3{1};                     // OK: 直接列表初始化
E e4 = {1};                  // error: 拷贝列表初始化选中了 explicit 构造函数
E e5 = static_cast<E>(1);    // OK: static_cast 是直接初始化（结果是 E 的纯右值，再经 ¶15.6.1）
void take(E);
void g() { take(1); }        // error: 实参传递是拷贝初始化
```

注意 `e1` 与 `e4` 的错误机理不同：`E e1 = 1;` 中 `explicit` 构造函数**根本不是候选**；而 `E e4 = {1};` 中 `explicit` 构造函数**是候选、并被选中**，然后才因为"拷贝列表初始化选中了 explicit 构造函数"而非良构（[[over.match.list]]）。这一差异在有多个构造函数时会表现出来，见 [[dcl.init.list]]。

## 初始化器的语义：总决策流程（¶15）

¶15 是整个 [dcl.init] 的核心。先定义两个术语：

- **目标类型**（destination type）：被初始化的对象或引用的类型，去掉顶层 cv 限定。
- **源类型**（source type）：初始化表达式的类型。若初始化器不是单个（可带括号的）表达式——比如 `(a, b)` 这样的多元素列表、或花括号列表——源类型**未定义**。

然后**按顺序**检查以下条件，第一个满足的分支决定一切：

```text
¶15.1  初始化器是 {…} 或 = {…}             → 列表初始化 [dcl.init.list]
¶15.2  目标类型是引用                       → 引用绑定 [dcl.init.ref]
¶15.3  目标是字符数组，初始化器是字符串字面量 → [dcl.init.string]
¶15.4  初始化器是 ()                        → 值初始化
¶15.5  目标是数组（必然是 (x1,…,xk) 形式）   → 逐元素拷贝初始化，其余值初始化     (C++20)
¶15.6  目标是类类型
   .1  初始化器是同类型纯右值               → 直接用它初始化（保证的复制消除）  C++17
   .2  直接初始化，或从同类/派生类拷贝初始化 → 构造函数重载决议
       .2.1 成功                           → 调用构造函数
       .2.2 无可行构造函数 + 聚合 + (…)     → 圆括号聚合初始化               (C++20)
       .2.3 否则                           → 非良构
   .3  其余拷贝初始化                       → 用户定义转换 [over.match.copy]，结果再直接初始化
¶15.7  源类型是类类型（目标非类）            → 转换函数 [over.match.conv]
¶15.8  直接初始化，nullptr_t → bool         → false
¶15.9  其他                                → 标准转换序列
```

（¶15.5 与 ¶15.6.2.2 是 C++20 新增的分支；¶15.6.1 的"保证"语义来自 C++17 的 [[P0135R1]]。）

下表给出每个分支一个最小例子：

| 分支 | 例子 | 结果 |
|---|---|---|
| ¶15.1 | `std::vector<int> v{1, 2};` | 列表初始化 → `initializer_list` 构造函数 |
| ¶15.2 | `const int& r = 1;` | 引用绑定到实质化的临时量 |
| ¶15.3 | `char s[] = "hi";` | `s` 是 `char[3]` |
| ¶15.4 | `new int()`、`T()`、`: m()` | 值初始化 → `0` |
| ¶15.5 | `int a[](1, 2, 3);` | `int[3]`，{{c++20}} |
| ¶15.6.1 | `T x = T(T(T()));` | 只有一个对象，被值初始化 |
| ¶15.6.2 | `std::string s("abc");` | 调用 `string(const char*)` |
| ¶15.6.2.2 | `struct P{int a, b;}; P p(1, 2);` | 圆括号聚合初始化，{{c++20}} |
| ¶15.6.3 | `std::string s = "abc";` | 转换构造函数 → 纯右值 → 初始化 `s` |
| ¶15.7 | `struct Q { operator int(); } q; int n = q;` | 调用 `Q::operator int` |
| ¶15.8 | `bool b(nullptr);` | `b == false` |
| ¶15.9 | `double d = 1;` | 整数到浮点的标准转换 |

下面逐个分支展开。

### ¶15.1–¶15.3：三个"转交"分支

¶15.1 只要初始化器是**非括号包围**的花括号列表（`T x{…}`、`T x = {…}`），一律转交 [[dcl.init.list]]——无论 `T` 是什么类型，包括引用、标量。所以**列表初始化优先于引用、数组、类的一切规则**。注意"非括号包围"：`T x({1, 2})` 是圆括号形式，其中唯一的表达式是一个花括号列表，会走到 ¶15.6.2，用 `{1, 2}` 作为构造函数的实参。

¶15.2 目标是引用：转交 [[dcl.init.ref]]。

¶15.3 目标是 `char`/`char8_t`/`char16_t`/`char32_t`/`wchar_t` 数组，初始化器是字符串字面量：转交 [[dcl.init.string]]。

这三条放在最前面，是因为它们的规则与"对象的类型"无关或优先于一般规则。

### ¶15.4：`()` 是值初始化

¶15.4 初始化器是 `()` 时，对象值初始化。但如注 6 所说，`()` 不是 *initializer* 文法允许的形式——`X a();` **不是**对象声明，而是声明了一个"无参、返回 `X`"的函数。`()` 只出现在其他上下文中：

```cpp run ok
#include <cassert>
struct M { int v; M() : v() {} };   // mem-initializer 中的 ()：值初始化 → v == 0
int main() {
  int* p = new int();               // new-initializer 中的 ()：值初始化 → 0
  int i = int();                    // 函数式转换 T()：值初始化 → 0
  M m;
  assert(*p == 0 && i == 0 && m.v == 0);
  delete p;
}
```

这就是"最令人烦恼的解析"（most vexing parse）的最简形态。更复杂的形态，例如 `T x(U());`（被解析为"参数是返回 `U` 的函数"的函数声明），由 [[dcl.ambig.res]] 的规则"能解析为声明的就是声明"导致。C++11 的花括号初始化 `T x{};` 的一大动机就是绕开这个歧义。

```cpp
struct A {};
void f() {
  A a();          // 函数声明！不是 A 类型的对象
  A b{};          // OK: 值初始化的对象
  int x(int());   // 函数声明：参数类型是 int(*)()
}
```

### ¶15.5：数组的圆括号初始化 {{c++20}}

¶15.5 目标是数组时，初始化器只能是 `( expression-list )`（花括号、字符串字面量、`()` 都已在前面的分支处理掉了；`T a[3] = x;` 这种单表达式等号形式不符合要求，非良构）。设元素为 x₁…x_k：

- 未知边界的数组被定义为有 k 个元素；
- 若 k 大于数组大小 n，非良构；
- 第 i 个元素从 xᵢ **拷贝初始化**，其余元素**值初始化**；
- 各元素的初始化**从左到右严格有序**。

```cpp run ok
int a[](1, 2, 3);          // int[3]
int b[5](1, 2);            // {1, 2, 0, 0, 0}
static_assert(sizeof a == 3 * sizeof(int));
int main() { return b[4]; }
```

这一分支是 [[P0960R3]]（"允许用圆括号初始化聚合"）的一部分，动机是让 `std::make_unique<T>(args...)`、`emplace_back(args...)` 这类内部写 `T(std::forward<Args>(args)...)` 的泛型代码也能用于聚合与数组。

### ¶15.6.1：同类型纯右值——保证的复制消除

¶15.6.1 若初始化表达式是**纯右值**，且其类型（去 cv）与目标类型相同，则**直接用该初始化表达式初始化目标对象**。

这是 C++17 [[P0135R1]]（"通过简化值类别保证复制消除"）的核心：纯右值不再是"临时对象"，而是"初始化某个对象的配方"，它的**结果对象**（result object）由上下文决定（[[basic.lval]]）。所以

```cpp run ok
struct NoMove {
  NoMove(int) {}
  NoMove(const NoMove&) = delete;
  NoMove(NoMove&&) = delete;
};
NoMove make() { return NoMove(1); }   // C++17: OK，return 的纯右值直接初始化返回对象
NoMove a = NoMove(NoMove(NoMove(1))); // C++17: OK，只构造一次
NoMove b = make();                    // C++17: OK
int main() {}
```

在 C++14 中，以上三处都要求可访问的拷贝/移动构造函数（即使实现会消除拷贝），因此非良构。标准的例 2 `T x = T(T(T()));` 是同一道理：只有一个对象，它被值初始化。

!!! lawyer
    ¶15.6.1 只要求"纯右值 + 同类型"，不区分直接/拷贝初始化，也不要求有任何构造函数。这意味着，通过返回纯右值的函数，可以"初始化"一个既不可拷贝也不可移动、甚至构造函数私有的类型的变量——只要函数内部能构造它。`std::optional::emplace`、`std::lock_guard` 的工厂函数都依赖这一点。

### ¶15.6.2：构造函数重载决议

¶15.6.2 若是**直接初始化**，或是**拷贝初始化但源类型（去 cv）与目标类型相同或派生自目标类型**，则考虑构造函数：用 [[over.match.ctor]] 枚举候选（直接初始化时包括 `explicit` 构造函数；拷贝初始化时只有转换构造函数），通过重载决议选最佳。

- ¶15.6.2.1 成功：用初始化表达式（或 *expression-list*）作为实参调用选中的构造函数。
- ¶15.6.2.2 {{c++20}} 没有**可行**的构造函数、目标是**聚合类**、初始化器是**圆括号** *expression-list*：做圆括号聚合初始化（见下）。
- ¶15.6.2.3 否则非良构。

"源类型与目标相同或派生"这个条件是为了让 `Base b = derived;` 这种"切片拷贝"走构造函数路径（调用 `Base` 的拷贝/移动构造函数），而不是去找转换函数。

#### 圆括号聚合初始化（¶15.6.2.2）{{c++20}}

设聚合元素为 e₁…e_n（[[dcl.init.aggr]] ¶2），表达式为 x₁…x_k：k > n 非良构；eᵢ 从 xᵢ **拷贝初始化**；其余元素用默认成员初始化器，没有则值初始化；各元素初始化从左到右严格有序。

注 7 列出了它与花括号（直接列表初始化）的四点区别，标准的例 3 很好地展示了前两点：

```cpp
struct A {
  int a;
  int&& r;
};
int f();
int n = 10;

A a1{1, f()};               // OK: 临时量寿命被延长到 a1 的寿命
A a2(1, f());               // 良构，但 a2.r 悬垂
A a3{1.0, 1};               // error: 窄化转换
A a4(1.0, 1);               // 良构（允许窄化），但 a4.r 悬垂
A a5(1.0, std::move(n));    // OK
```

| | `T{…}` | `T(…)`（聚合） |
|---|---|---|
| 窄化转换 | 禁止 | **允许** |
| 指派初始化器 | 允许 | 不允许 |
| 绑定到引用成员的临时量 | 寿命延长 | **不延长**（[[class.temporary]] ¶6.11） |
| 花括号省略（brace elision） | 有 | **没有** |

为什么故意不同？设计目标是让 `T(args...)` 对聚合的行为**尽可能像"调用一个按成员顺序接受参数的构造函数"**：真实构造函数的参数允许窄化；绑定到构造函数引用参数的临时量在完整表达式结束时销毁；构造函数调用没有花括号省略。这样，把一个聚合改成带构造函数的类（或反之），`T(args...)` 的语义变化最小。

```cpp
struct In { int i, j; };
struct O { In in; int k; };
O o1{1, 2, 3};          // OK: 花括号省略，o1.in = {1, 2}
O o2({1, 2}, 3);        // OK: 第一个元素从 {1, 2} 拷贝初始化
O o3(1, 2, 3);          // error: 圆括号聚合初始化没有花括号省略，int 不能转换为 In
```

注意"没有**可行**的构造函数"这一条件：聚合可以有（隐式的）拷贝/移动构造函数，所以 `P p(other_p);` 仍然调用拷贝构造函数，只有当实参无法匹配任何构造函数时才落到聚合初始化。

### ¶15.6.3：拷贝初始化中的用户定义转换

¶15.6.3 剩下的情形——**拷贝初始化**，且源类型与目标类型**无关**（不相同、不是派生类）——按 [[over.match.copy]] 枚举能把源类型转换为目标类型（或其派生类，当使用转换函数时）的**用户定义转换**：目标类的非 explicit 转换构造函数，以及源类型的非 explicit 转换函数。选出最佳者：

- 若是构造函数，调用结果是目标类型的纯右值，其结果对象由该构造函数初始化；
- 若是转换函数，其返回值（可能是纯右值或左值）被用来**再按上述规则直接初始化**目标对象。

```cpp
#include <string>
std::string s1 = "abc";       // ¶15.6.3：string(const char*) 产生纯右值，随即按 ¶15.6.1 直接成为 s1
struct Base {}; struct Der : Base {};
struct From { operator Der() const; };
Base b = From();              // ¶15.6.3：转换函数返回 Der（Base 的派生类），
                              // 再直接初始化 b → ¶15.6.2：Base 的移动构造函数（切片）
```

与 ¶15.6.2 的区别：这里**只允许一次用户定义转换**，而且是在"转换到目标类型"层面选最佳，而不是在"目标类型的构造函数"层面。经典的差异例子：

```cpp
struct A { A(int); };
struct B { B(A); };
B b1(1);     // OK: 直接初始化，构造函数 B(A)，实参 1 经 A(int) 转换——一次用户定义转换
B b2 = 1;    // error: 需要 int→A→B 两次用户定义转换
```

C++17 之前，¶15.6.3 的结果是一个临时对象，再用它**拷贝/移动构造**目标——即使会被消除，也要求拷贝/移动构造函数可访问。C++17 起，转换构造函数的纯右值直接初始化目标对象。

### ¶15.7：从类类型到非类类型

¶15.7 目标不是类类型（也不是引用、数组）但源类型是类类型：按 [[over.match.conv]] 枚举转换函数并做重载决议。直接初始化时 `explicit` 转换函数也是候选：

```cpp
struct Q { explicit operator int() const; };
Q q;
int a(q);        // OK: 直接初始化考虑 explicit 转换函数
int b = q;       // error: 拷贝初始化不考虑
int c = int(q);  // OK: 函数式转换是直接初始化
bool d = q;      // error（即使能 int→bool：explicit operator int 不是候选）
```

`explicit operator bool` 之所以能在 `if (q)` 中用，是因为条件是**按语境转换为 bool**（contextually converted to bool），定义为直接初始化 `bool t(e);`（[[conv]]）。

### ¶15.8：`nullptr` 直接初始化 `bool`

¶15.8 直接初始化、源类型 `std::nullptr_t`、目标 `bool`：结果为 `false`。拷贝初始化 `bool b = nullptr;` 非良构——[[conv.bool]] 的布尔转换只覆盖算术、无作用域枚举、指针、成员指针类型，`std::nullptr_t` 不在其中，所以 ¶15.9 找不到标准转换；`nullptr` 到 `bool` 的唯一途径就是 ¶15.8 这条直接初始化特例。设计意图是：对 `nullptr` 字面量做隐式的"判空"没有意义，不应该悄悄发生；但为了让泛型代码中的 `bool(x)` 对任何类似指针的类型都可用，直接初始化仍然允许。

```cpp
bool b1(nullptr);    // OK: false
bool b2{nullptr};    // OK: 列表初始化 → [dcl.init.list] ¶3.9 → 直接初始化 → false
bool b3 = nullptr;   // error
```

### ¶15.9：标准转换

¶15.9 其余情形（目标与源都不是类类型）：用**标准转换序列**（[[conv]]）把初始化表达式转换为目标类型的纯右值，**不考虑用户定义转换**；无法转换则非良构。

两个细节：

- 用无法表示的值初始化**位域**，结果是**实现定义**的 {{impl}}（而不是 UB）。C++20 起整数转换本身是取模定义的（[[conv.integral]]），所以对普通整数来说早已不是问题，但位域的宽度不属于类型，所以单列。
- 注 8：cv 限定不影响初始化——`const int b = a; int c = b;` 都没问题。这是因为左值到右值转换会去掉 cv（[[conv.lval]]）。

## 立即调用、包展开、子表达式（¶16–¶18）

¶16 {{c++20}} 默认实参和默认成员初始化器中的**立即调用**（`consteval` 函数调用，[[expr.const]]）在其出现的位置并不求值；它们在初始化器**被使用**的地方——函数调用、构造函数定义、聚合初始化——才求值并检查是否为常量表达式。这允许默认实参里写 `std::source_location::current()` 这样依赖调用点的立即函数。

¶17 后跟省略号的 *initializer-clause* 是**包展开**（[[temp.variadic]]）：`int arr[]{args...};`。

¶18 "初始化"包括对初始化器中**所有子表达式**的求值（包括嵌套在花括号里的），以及为函数实参或返回值**创建临时对象**。这句话界定了"初始化"这一事件的范围——例如 [[stmt.dcl]] 说"初始化以抛出异常结束则下次重试"，抛出点可以是初始化器中任何子表达式。

## 求值顺序：圆括号 vs 花括号（¶19）

¶19 若目标类型**不是聚合**且初始化器是圆括号 *expression-list*，各表达式按**函数调用实参**的顺序求值——即**不确定顺序**（indeterminately sequenced，[[expr.call]]）。

对比：花括号列表中的子句**严格从左到右**（[[dcl.init.list]] ¶4），聚合的圆括号初始化也从左到右（¶15.6.2.2）。

```cpp run unspecified
#include <cstdio>
struct I { I(int x) { std::printf("%d", x); } };
struct S { S(I, I) {} };
int main() {
  S(I(1), I(2)); std::puts("");   // 打印 12 或 21：未指定
  S{I(1), I(2)}; std::puts("");   // 一定打印 12
}
```

## 指派符不重复（¶20）

¶20 同一个 *designated-initializer-list* 中，同一标识符不能出现在多个指派符中：`A a{.x = 1, .x = 2};` 非良构。C 允许"后者覆盖前者"，C++ 不允许，因为覆盖意味着前一个初始化器的副作用发生了但值被丢弃，与"每个成员恰好初始化一次"的模型冲突。

!!! impl
    截至写作时，Clang 在 C++ 模式下对重复指派只给出警告（`-Winitializer-overrides`，沿袭 C 的行为），加 `-pedantic-errors` 才报错。这是编译器的宽松之处，标准规定它非良构。

## 视为构造与销毁（¶21）

¶21 定义**视为构造**（deemed construction）：对象的初始化完成时，即视为它被构造；若初始化是一个完整表达式，则在该完整表达式求值完成时视为构造（这是为 [[basic.start.term]] 服务的）。**即使对象不是类类型、或者没有调用任何构造函数**，对象也被视为"已构造"。

为什么需要这个概念？[[basic.start.term]] 规定静态存储期对象按**构造完成的逆序**销毁，且"只有被构造过的对象才会被销毁"（[[stmt.dcl]] ¶4）。对于 `int`、聚合、值初始化的对象，"构造"这个词以前没有精确定义；¶21 把它统一为"初始化完成"。

¶21 后半：销毁类对象调用析构函数；销毁标量除结束生命周期外没有任何效果；销毁数组按下标**逆序**销毁每个元素。

## 初始化声明（¶22）

¶22 指定了变量初始化（通过显式初始化器，或通过默认初始化）的那个声明称为该变量的**初始化声明**（initializing declaration）。

注 10：通常就是定义性声明；但对于非 inline 的静态数据成员，初始化声明可以是**类内**的声明，而定义在类外：

```cpp
struct S {
  static const int n = 42;   // 初始化声明（但不是定义）
};
const int S::n;              // 定义（无初始化器）
```

这一术语在 [[expr.const]]（常量初始化、"在初始化声明之后可用于常量表达式"）等处使用。

## 静态局部变量的初始化

块作用域的 `static` 变量的初始化时机在 [[stmt.dcl]] ¶3，而不是本节，但它与初始化密不可分：

1. 先做静态初始化（零初始化或常量初始化，[[basic.start.static]]）——这发生在程序启动时，与控制流无关。
2. 若还需要**动态初始化**，在控制流**第一次经过声明时**执行。
3. 若初始化抛出异常，视为未完成，下次经过时**重试**。
4. 若多个线程并发到达，其余线程**等待**初始化完成（C++11 起的"魔法静态"）。
5. 初始化过程中**递归**重入该声明：{{ub}}。

```cpp
int foo(int i) {
  static int s = foo(2 * i);   // UB: 递归重入正在初始化的静态局部变量
  return i + 1;
}
```

!!! impl
    Itanium C++ ABI 用一个 guard 变量加 `__cxa_guard_acquire` / `__cxa_guard_release` / `__cxa_guard_abort` 三个运行时函数实现第 2–4 条：快速路径只检查 guard 的第一个字节（已初始化则直接跳过），慢速路径加锁。GCC/Clang 的 `-fno-threadsafe-statics` 可以关掉加锁。若初始化是常量初始化（例如 `static const int k = 42;` 或 `constinit`），则没有 guard，也没有任何运行时开销——这是推荐用 `constinit`（[[dcl.constinit]]）标注的原因之一。

## 实现视角

!!! impl
    - **零初始化与 `.bss`**：只需零初始化的静态存储期对象被放在 `.bss` 段，加载时由操作系统清零，不占可执行文件体积。需要常量初始化的放在 `.data`/`.rodata`。只有需要动态初始化的才生成初始化函数（在 ELF 上登记到 `.init_array`）。
    - **零初始化不一定是全零位**：Itanium ABI 中空的数据成员指针是 `-1`；所以含成员指针的结构体零初始化时编译器会生成非零写入，也不能放进 `.bss`。
    - **值初始化的代码生成**：`X x{};`（`X() = default`）常被编译为一次 `memset` 或若干清零存储，再调用（往往是平凡的）构造函数；而 `Y y{};`（用户提供的构造函数）只有构造函数调用。
    - **诊断**：Clang 对 `T x();` 默认给出 `-Wvexing-parse` 警告（"empty parentheses interpreted as a function declaration"），GCC 也有类似警告。

## 历史与演进

!!! history
    - **C++98**：只有零初始化和默认初始化。当时"默认初始化"对非 POD 类调用默认构造函数、对 POD 类型则是**零初始化**；而"没有初始化器"的 POD 对象根本不初始化。所以 `T()` 对 POD 清零，但对"带有非平凡成员的非 POD 类"不会清零其标量成员。
    - **C++03**：引入**值初始化**，`T()` 对没有用户声明构造函数的类一律先清零，修正了上述问题。
    - **C++11**：统一初始化（花括号）、`std::initializer_list`、列表初始化（[[dcl.init.list]]）；静态局部变量的线程安全初始化；"用户提供"的概念与 `= default`，值初始化的规则据此改写。
    - **C++17**：[[P0135R1]] 保证复制消除，¶15.6.1 出现；¶15.6.3 中转换结果直接初始化目标，不再要求可访问的拷贝/移动构造函数。const 对象默认初始化的规则（原先要求"用户提供的默认构造函数"）通过解决一个长期悬而未决的核心问题放宽为 const-default-constructible。
    - **C++20**：[[P0960R3]] 圆括号聚合初始化（¶15.5、¶15.6.2.2）；指派初始化器。
    - **C++26**：[[P2795R5]] 错误行为——未初始化自动变量从 UB 变为错误行为；[[P2996R13]] 静态反射，`std::meta::info` 的零/默认初始化规则。

## 陷阱

!!! pitfall "`T x();` 不是对象"
    `std::mutex m();` 声明了一个函数。之后 `std::lock_guard g(m);` 会在一个意想不到的地方报错。用 `T x;` 或 `T x{};`。

!!! pitfall "类外 `= default` 会关掉值初始化的清零"
    `struct Y { Y(); int i; }; Y::Y() = default;` 让 `Y{}` 不再把 `i` 清零。把 `= default` 写在类内，或者给成员加默认成员初始化器（`int i = 0;`），后者最稳健。

!!! pitfall "`explicit` 在 `= {…}` 中的报错方式"
    `E e = {1};` 不是"找不到构造函数"，而是"选中了 explicit 构造函数所以非良构"。如果同时存在一个非 explicit 但匹配较差的构造函数，它**不会**被退而求其次地选中（见 [[dcl.init.list]] 与 [[over.match.list]]）。

!!! pitfall "圆括号聚合初始化的悬垂引用"
    `A a(1, f());` 中 `A::r` 是引用成员时，临时量**不会**延寿。花括号版本 `A a{1, f()};` 才会。泛型代码 `std::make_unique<A>(1, f())` 走的是圆括号版本。

## 思考题

!!! question "1. 下面每个变量的值是什么？"
    ```cpp
    struct A { int i; A() = default; };
    struct B { int i; B(); }; B::B() = default;
    struct C { A a; int j; C() {} };
    A a1{}; B b1{}; C c1{};      // 都在函数体内（自动存储期）
    ```

<details markdown="1">
<summary>答案</summary>

- `A` 有用户声明的构造函数，不是聚合（C++20 起）。`A a1{}` → [[dcl.init.list]] ¶3.5 值初始化 → 默认构造函数不是用户提供的 → 先零初始化 → `a1.i == 0`。
- `B b1{}` → 值初始化 → `B::B()` 是用户提供的 → 不清零 → `b1.i` 未初始化（C++26 中为错误值）。
- `C c1{}` → 值初始化 → `C()` 是用户提供的 → 不清零 → 调用 `C()`。`C()` 的成员初始化列表没有提到 `a` 和 `j`，于是它们被**默认初始化**（[[class.base.init]]）：`a` 调用 `A` 的隐式默认构造函数，`a.i` 未初始化；`j` 未初始化。外层的值初始化并不会"渗透"进用户构造函数。
</details>

!!! question "2. 为什么 `bool b = nullptr;` 非良构，而 `bool b{nullptr};` 良构？"

<details markdown="1">
<summary>答案</summary>

`bool b = nullptr;` 是拷贝初始化，走到 ¶15.9（¶15.8 只适用于直接初始化），需要从 `std::nullptr_t` 到 `bool` 的标准转换；而 [[conv.bool]] 不包括 `nullptr_t`，所以失败。

`bool b{nullptr};` 是直接列表初始化：¶15.1 → [[dcl.init.list]] ¶3.9（单元素）→ "以直接初始化方式从该元素初始化" → 回到 ¶15，此时初始化器是单个表达式、直接初始化 → ¶15.8 → `false`。至于窄化：[[dcl.init.list]] ¶7.5 只把"指针或成员指针到 `bool`"列为窄化，`nullptr_t` 不在其中。
</details>

!!! question "3. 对于 `struct NoMove { NoMove(int); NoMove(NoMove&&) = delete; };`，`NoMove x = 1;` 在 C++14 和 C++17 中分别如何？"

<details markdown="1">
<summary>答案</summary>

两者都走 ¶15.6.3：拷贝初始化，源类型 `int` 与目标无关，选中转换构造函数 `NoMove(int)`。

- C++14：转换的结果是一个**临时对象**，再用它直接初始化 `x`——需要移动构造函数，而它被删除，所以非良构（即使实际实现会消除这次移动）。
- C++17：构造函数调用是一个纯右值，其结果对象就是 `x`（¶15.6.3 的措辞"result object is initialized by the constructor"），不需要移动构造函数，良构。
</details>

## 小结

!!! summary
    - 初始化只有两大类上下文：**拷贝初始化**（`=`、传参、返回、throw/catch、非指派的聚合成员）与**直接初始化**（`()`、`{}`、`new`、`static_cast`、`T(…)`）。差异主要在 `explicit` 与用户定义转换的次数。
    - 三个原子动作：**零初始化**（转换 0，不是 memset）、**默认初始化**（类调构造函数，标量不管）、**值初始化**（非用户提供的构造函数先清零）。
    - ¶15 的顺序：花括号 → 引用 → 字符串 → `()` → 数组 → 类（同类纯右值 / 构造函数 / 圆括号聚合 / 用户定义转换） → 类到非类 → `nullptr`→`bool` → 标准转换。
    - `T x;` 对自动存储期的标量：C++26 起是错误值（错误行为），C++23 及以前读取是 UB；`new T` 仍然是不确定值。
    - 进一步阅读：[[dcl.init.list]]（花括号的全部故事）、[[dcl.init.ref]]、[[dcl.init.aggr]]、专题 [[topics/initialization]]。
