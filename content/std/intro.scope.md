!!! tldr
    - C++ 标准规定的是对**实现**（implementation）的要求。实现指编译器、标准库和运行环境的整体。
    - 第一条要求是实现要实现这门语言，所以标准顺带定义了 C++。
    - 条文里"程序不得……"的说法，最终都读成对实现的要求。未定义行为的本意是标准对实现没有要求。

## 标准规定的是什么（¶1）

¶1 本文档规定对 C++ 实现的要求，C++ 是一门通用编程语言。第一条要求是实现要实现这门语言，因此本文档也定义了 C++。其他要求，以及对第一条要求的放宽，散布在文档各处。

!!! std
    This document specifies requirements for implementations of C++, which is a general-purpose programming language.

标准约束的对象是实现，而不是程序员。这决定了读条文的方式。比如问"有符号整数溢出合法吗"，标准的回答不是"不准溢出"，而是"溢出时本文档对实现不施加任何要求"，也就是未定义行为（[[defns.undefined]]）。编译器可以假设它不发生，sanitizer 可以在发生时报错，两者都符合标准。

条文里也常把要求写成对程序的要求，例如"程序应当只有一个 `main`"，因为这样更好懂。[[intro.compliance]] ¶2 规定了怎样把这类说法翻译回对实现的要求：必须诊断、不要求诊断，还是行为未定义。

原文最后一句提到的放宽，主要有这几项，都集中在 [[intro.compliance]]：

- 实现限制：程序太大、嵌套太深时，实现可以拒绝它；
- 有条件支持的构造：实现可以不支持，但要在文档中说明；
- 独立实现（freestanding）：只需提供部分标准库；
- as-if 规则：实现不必按抽象机的步骤执行，只需产生相同的可观察行为。

    C++98 到 C++14 的第 1 章叫 General，范围只是其中的 1.1 [intro.scope]。C++17 按 ISO 文件的统一结构重排，第 1 章只剩范围，规范性引用、术语定义、总则分别成为第 2、3、4 章。早期版本的范围条款还写明 C++ 以 C 语言为基础并引用了当时的 C 标准，当前草案中已经没有这句话。与 C 的关系改由 [[intro.refs]] 和 Annex C [[diff]] 交代。
