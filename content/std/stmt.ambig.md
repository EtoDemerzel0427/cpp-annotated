!!! tldr
    - `T(x);` 既可以是把 `x` 转换为 `T` 的表达式语句，也可以是声明 `T x;`。只要整条语句能读成声明，它就是声明。
    - 判断能否读成声明有时要看完整条语句：`T(a)->m = 7;` 是表达式，`T(*d)(int);` 是声明。
    - 判断只依据语法，以及每个名字是不是类型名。读成声明后即使声明本身有错，也不会退回去当表达式。
    - `std::unique_lock<std::mutex>(m);` 声明了一个名为 `m` 的锁，而没有锁住全局的 `m`。RAII 守卫对象要有名字。
    - 能读成带尾置返回类型的声明时，只有以 `auto` 开头才算声明（C++23 的 `auto(x)` 引出的补充规则）。

## 一行代码，两种读法

```cpp
#include <mutex>
std::mutex m;
int counter;
void inc() {
    std::unique_lock<std::mutex>(m);   // 声明了一个名为 m 的局部锁，没有锁住全局 m
    ++counter;                         // 没有加锁
}
```

这段代码能编译，却完全没有加锁。C 的声明语法允许给声明符加括号，`int (x);` 和 `int x;` 相同；C++ 又有函数式类型转换 `T(x)`（[[expr.type.conv]]）。于是 `T(x);` 有两种读法：

- 表达式语句：把 `x` 转换为 `T`，然后丢弃结果；
- 声明：声明一个类型为 `T`、名为 `x` 的变量，括号是多余的。

¶1 标准规定，以函数式类型转换为最左子表达式的表达式语句，如果与第一个声明符以 `(` 开头的声明无法区分，就**把它当作声明**（¶4 有一个例外）。上面那一行因此是 `std::unique_lock<std::mutex> m;`：一个遮蔽了全局 `m`、默认构造、不关联任何互斥量的锁。

选择声明，一是因为 C 里 `int (x);` 一直是声明；二是带括号的声明符本来就不可缺少，例如函数指针 `T (*p)(int);`。[[dcl.ambig.res]] 处理声明内部的歧义（函数还是对象），[[stmt.pre#7]] 处理条件中的歧义，方向都一样：能当作声明的就是声明。

本机 Clang 23 对这一行给出 `-Wvexing-parse` 警告，说括号被当成了变量 `m` 声明周围的多余括号。如果换成没有默认构造函数的 `std::lock_guard`，就会因为找不到匹配的构造函数而编译失败，这反倒更好。

正确的写法是给守卫起名字：

| 写法 | 效果 |
|---|---|
| `std::unique_lock<std::mutex> lk(m);` | 正确 |
| `std::unique_lock lk{m};` | 正确，用 CTAD 推导模板实参 |
| `std::unique_lock<std::mutex>{m};` | 表达式语句：临时锁在语句结束时就释放了 |
| `(std::unique_lock<std::mutex>(m));` | 同上 |

后两行不再是声明，但临时对象在完整表达式结束时销毁，锁立即释放，同样起不到作用。

## 要看完整条语句（¶2）

¶2（注）如果语句在语法上不可能是声明，就没有歧义，规则也不适用。判断能否是声明，有时要检查整条语句，而不只是开头几个记号。标准例 1 假设 `T` 是一个简单类型说明符：

| 语句 | 结果 | 原因 |
|---|---|---|
| `T(a)->m = 7;` | 表达式 | 声明符里不能出现 `->m` |
| `T(a)++;` | 表达式 | 声明符后面不能跟 `++` |
| `T(a,5)<<c;` | 表达式 | `(a,5)` 不是声明符 |
| `T(*d)(int);` | 声明 | `d` 是指向函数 `T(int)` 的指针 |
| `T(e)[5];` | 声明 | `e` 的类型是 `T[5]` |
| `T(f) = { 1, 2 };` | 声明 | 带初始化器的 `f` |
| `T(*g)(double(3));` | 声明 | `g` 是 `T*`，初始化器是 `double(3)` |

最后一行作为声明是非良构的，`double` 不能初始化 `T*`。但语法分析不管语义，只要能解析为声明，它就是声明。

标准例 2 列出的其余情形也都是声明（`T` 是一个有相应构造函数的类）：

```cpp ok
class T {
public:
    T();
    T(int);
    T(int, int);
};
extern int h;
void f() {
    T(a);             // T a;
    T(*b)();          // b 是指向函数 T() 的指针
    T(c) = 7;         // T c = 7;
    T(d), e, f = 3;   // 三个 T 类型的变量 d、e、f
    T(g)(h, 2);       // T g(h, 2);
}
```

`T(d), e, f = 3;` 当作表达式是一个逗号表达式，但它也能读成声明三个变量，所以是声明。

## 只看语法，不回头（¶3）

¶3 消解是纯语法的：除了一个名字是不是 *type-name* 以外，名字的含义既不参与消解，也不因消解而改变。为了判断一个限定名是不是类型名，必要时会实例化类模板。

消解先于解析。被消解为声明的语句完全可能是一个非良构的声明，编译器不会因为当作声明会出错，就回头把它当作表达式。标准例 3：

```cpp error
struct T1 {
    T1 operator()(int x) { return T1(x); }
    int operator=(int x) { return x; }
    T1(int) { }
};
struct T2 { T2(int) { } };
int a, (*(*b)(T2))(int), c, d;

void f() {
    T1(a) = 3,
    T2(4),                    // 这里把 T2 声明成一个 T1 类型的变量
    (*(*b)(T2(c)))(int(d));   // error: T2 不再是类型名，这一部分无法解析
}
```

当作表达式，这条语句是一串赋值和函数调用组成的逗号表达式，完全合法。但它的开头也能读成声明：`T1(a) = 3` 是带初始化器的声明符，`T2(4)` 像是名为 `T2`、初始化器为 `4` 的声明符。于是消解选择了声明。`T2` 一旦被声明为变量，后面 `T2(c)` 里的 `T2` 就不再是类型名，最后一部分解析失败，而此时已经不能回头。本机 Clang 23 报的错误正是 `T2` 被一个非类型声明隐藏了。

¶3 的最后一句：如果解析过程中，查找发现模板实参里的某个名字绑定到了正在解析的这个声明（或其一部分），程序非良构但不要求诊断（[[g:ifndr|IFNDR]]）：编译器可以不报错，标准对这样的程序没有任何要求。

!!! impl "编译器怎样实现"
    编译器一般用试探性解析（tentative parsing）：从语句开头试着按声明解析，遇到不可能出现在声明里的记号（如 `->m`、`++`）就判定为表达式。试探阶段只做语法判断和是不是类型名的查找，正好对应 ¶3 的纯语法。例 3 中，试探时 `T2` 还没有被重新声明，判定为声明；真正解析时 `T2` 已经是变量，于是失败。Clang 中对应的逻辑在 `Parser::isCXXDeclarationStatement` 一族函数里。

## 以 auto 开头的尾置返回类型（¶4）

C++23 引入了 `auto(x)` 和 `auto{x}`（衰变复制，[[expr.type.conv]]），`auto(s)` 因此也可以是一个函数式类型转换。而 `auto f() -> R;` 是带尾置返回类型的函数声明，加括号写成 `auto(f)() -> R;` 同样合法。于是 `auto(s)()->M;` 有两种读法：

- 表达式：复制 `s`，调用它的 `operator()`，访问结果的成员 `M`；
- 声明：声明一个无参函数 `s`，返回类型是 `M`。

¶4 一条有歧义的语句，如果能读成最外层声明符带尾置返回类型的声明，那么**只有以 `auto` 开头时**才当作声明。

带尾置返回类型的函数声明，说明符必须是 `auto`（[[dcl.fct]]）。所以以其他类型开头的这种声明必定非良构，没有理由选它，而开头是不是 `auto` 只看记号就能判断，不违反 ¶3 的纯语法要求。标准例 4：

```cpp ok
struct M;
struct S {
    S* operator()();
    int N;
    int M;
    void mem(S s) {
        auto(s)()->M;      // 表达式：这里 M 指成员 S::M，不是类型名
    }
};
void f(S s) {
    {
        auto(s)()->N;      // 表达式：N 不是类型名
        auto(s)()->M;      // 声明：函数 s，返回类型 ::M
    }
    {
        S(s)()->N;         // 表达式
        S(s)()->M;         // 表达式：不以 auto 开头
    }
}
```

本机 Clang 23 的表现与标准一致：四条表达式语句都得到结果未使用的警告，唯独 `f` 里的 `auto(s)()->M;` 被当成了声明。

## 常见误解

!!! pitfall "`T(x);` 会创建一个临时对象"
    它声明了一个名为 `x` 的变量。同一作用域里 `x` 已经声明过时，这是重复声明的错误；在内层块中，它会遮蔽外层的 `x`。

!!! pitfall "编译器会按语义选择更合理的读法"
    消解只看名字是不是类型名。即使当作声明会导致语义错误，比如类型没有默认构造函数，编译器也不会改为当作表达式。

## 思考题

!!! question "思考题 1"
    `T` 是类类型，下面每条语句是声明还是表达式？
    ```cpp
    T(x);           // (a)
    T(x).f();       // (b)
    T(x) + 1;       // (c)
    T(*x);          // (d)
    T(x)(1);        // (e)
    ```

<details markdown="1">
<summary>答案</summary>

- (a) 声明 `T x;`。
- (b) 表达式：声明符后面不能出现 `.f()`。
- (c) 表达式：声明符后面不能出现 `+ 1`。
- (d) 声明 `T* x;`。
- (e) 声明 `T x(1);`，用 `1` 直接初始化名为 `x` 的 `T`。
</details>

!!! question "思考题 2"
    ¶4 为什么只检查语句是否以 `auto` 开头，而不检查这个声明在语义上是否合法？

<details markdown="1">
<summary>答案</summary>

消解必须在语法层面完成（¶3）。如果让语义检查参与，就会出现先当声明、发现语义错误、再改当表达式的回溯，这正是 ¶3 所排除的。带尾置返回类型的函数声明，说明符必须是 `auto`（[[dcl.fct]]），这是只看记号就能判断的条件，恰好能在语法层面排除那些必定非良构的声明。
</details>
