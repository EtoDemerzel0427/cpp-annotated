!!! tldr
    - 形参、返回值、异常对象的初始化和变量的初始化走同一套规则；`T x = e`、传参、`return` 都是拷贝初始化，`T x(e)`、`T x{e}`、`static_cast` 是直接初始化。两者的主要区别是拷贝初始化不考虑 `explicit`。
    - 零初始化把对象设为 0 转换得到的值；默认初始化对类调用默认构造函数，对标量什么也不做；值初始化在构造函数不是用户提供的时候先清零，再默认初始化。
    - 一个初始化器做什么，由第 15 段的流程按顺序决定：花括号、引用、字符串字面量、`()`、数组、类、类到非类、`nullptr` 到 `bool`、标准转换。
    - C++17 起，用同类型的纯右值初始化对象时不再有临时量，也不需要拷贝或移动构造函数。
    - C++26 起，读取未初始化的自动变量是错误行为，不再是 UB；`new int` 得到的仍是不确定值。

## 同一个类型，不同的写法

```cpp run ok
#include <cassert>
struct P { int i; P() = default; };
int main() {
  int a = 1;        // 拷贝初始化
  int b(1);         // 直接初始化
  int c{1};         // 直接列表初始化
  int d = {1};      // 拷贝列表初始化
  P p1{};           // 值初始化：p1.i == 0
  P p2;             // 默认初始化：p2.i 没有初始化
  int f();          // 这不是变量，而是函数声明
  assert(a + b + c + d == 4 && p1.i == 0);
  (void)p2;
}
```

这些写法看起来只是风格不同，结果却可能是不初始化、清零、调用某个构造函数，甚至根本不是变量。它们都由这一节决定：第 5–8 段定义几种基本的初始化动作，第 13–14 段区分两类语法上下文，第 15 段给出一个按顺序判断的流程。花括号、引用、字符数组、聚合这几个分支各有一个子条款展开：[[dcl.init.list]]、[[dcl.init.ref]]、[[dcl.init.string]]、[[dcl.init.aggr]]。

变量什么时候初始化（静态初始化、动态初始化、块作用域的静态变量）不在这一节，见 [[basic.start.static]]、[[basic.start.dynamic]] 和 [[stmt.dcl]]。

### 初始化发生在哪里（¶1）

¶1 这一节的规则适用于所有初始化，不论出现在什么语法位置。用实参初始化形参（[[expr.call]]）、`return` 初始化返回值（[[stmt.return]]）、`throw` 初始化异常对象，和变量声明里的初始化器一样都是初始化。

所以 `f(x)` 中形参的初始化和 `T p = x;` 是同一回事，都是拷贝初始化（见后文）。`explicit` 构造函数不能用于隐式传参，原因和它不能用于 `T p = x;` 完全一样。

初始化器的文法可以归纳成下面几种形式：

| 写法 | 文法 |
|---|---|
| `T x = e;` | `= initializer-clause` |
| `T x = { … };` | `= braced-init-list` |
| `T x( … );` | `( expression-list )` |
| `T x{ … };` | *braced-init-list* |
| `T x{ .m = … };` | *designated-initializer-list* {{c++20}} |

*braced-init-list* 允许尾随逗号 `{1, 2, 3,}`，也可以是空的 `{}`。子句后面可以跟 `...` 表示包展开（¶17）。`()` 不是合法的 *initializer*，所以 `T x();` 声明的是函数（见后文第 15 段第 4 项）。

注 1 补充，即使某个上下文的文法只允许 `=` 和花括号两种形式，比如类内的默认成员初始化器不能写圆括号，这一节的规则照样适用。

指派初始化器列表的文法是先写若干普通子句，再写若干指派子句。前面的普通子句只能用来初始化基类子对象（[[dcl.init.aggr#4]]），这是 C++23 之后的新措辞；C++20/23 中一个列表只能全是指派子句。

## 三种基本动作（¶5–¶11）

第 15 段的流程最终落到下面三个动作上。它们名字相近，效果差别很大：

| 动作 | 什么时候发生 | 对 `int` | 对构造函数是用户提供的类 | 对构造函数不是用户提供的类 |
|---|---|---|---|---|
| 零初始化 | 静态存储期变量最先做的事 | `0` | 成员清零，不调用构造函数 | 同左 |
| 默认初始化 | 没有写初始化器 | 不初始化 | 调用默认构造函数 | 调用隐式的默认构造函数，标量成员不初始化 |
| 值初始化 | 写了空的 `()` 或 `{}` | `0` | 调用默认构造函数 | 先清零，再调用默认构造函数 |

**用户提供**（[[g:user-provided|user-provided]]）的函数是用户声明、并且在首次声明时没有写 `= default` 或 `= delete` 的函数（[[dcl.fct.def.default]]）。类内写 `= default` 的构造函数不是用户提供的，类外写的是。

### 零初始化（¶5）

```cpp run ok
#include <cassert>
struct P { int i; double d; int* p; };
P g;                // 静态存储期：零初始化，之后没有别的初始化
int main() {
  assert(g.i == 0 && g.d == 0.0 && g.p == nullptr);
  static int s;     // 同样是零初始化
  assert(s == 0);
}
```

¶5 **零初始化**（[[g:zero-initialization|zero-initialize]]）一个 `T` 类型的对象或引用：

- ¶5.1 {{c++26}} `T` 是 `std::meta::info`（静态反射的值类型，[[P2996R13]]）时，初始化为空反射值。它是标量类型，但整数 0 转换不到它，所以单独列出。
- ¶5.2 其他标量类型，初始化为整数字面量 `0` 转换为 `T` 得到的值。
- ¶5.3 非联合的类，填充位置零，每个非静态数据成员、每个非虚基类子对象递归地零初始化；虚基类子对象只在这个对象本身不是基类子对象时才零初始化，因为虚基类只由最终派生类负责。
- ¶5.4 联合，填充位置零，第一个具名的非静态数据成员零初始化。
- ¶5.5 数组，每个元素零初始化。
- ¶5.6 引用，什么也不做。

¶5.2 说的是 0 转换得到的值，不是所有位为零。指针得到空指针值，浮点数得到 `+0.0`。在 Itanium C++ ABI 上，空的数据成员指针表示为 `-1`，所以对含成员指针的结构体，零初始化和 `memset(…, 0, …)` 并不等价。

零初始化主要出现在两处：静态和线程存储期变量在其他一切初始化之前（¶10 的注，[[basic.start.static]]）；以及值初始化之中，对类是第一步，对标量就是全部（见下文 ¶8）。

### 默认初始化（¶6、¶11）

¶11 没有写初始化器的对象被默认初始化。`T x;` 的含义就来自这一句。

¶6 **默认初始化**（[[g:default-initialization|default-initialize]]）一个 `T` 类型的对象：

- ¶6.1 类类型，以空实参列表做构造函数的重载决议（[[over.match.ctor]]），调用选中的构造函数。没有可用的默认构造函数（被删除、不可访问、有歧义）时非良构。
- ¶6.2 数组，先检查默认初始化一个假想元素的语义约束，再逐个默认初始化元素。有了假想元素，元素个数为零时也会检查元素类型能否默认构造。
- ¶6.3 {{c++26}} `std::meta::info`，零初始化。所以这种变量即使不写初始化器，值也是确定的空反射。
- ¶6.4 其他情况，不做任何初始化。

¶6.4 是零开销的选择：`int buf[4096];` 不应该被强制清零。对类，默认初始化调用的是构造函数；隐式定义的默认构造函数对标量成员同样什么都不做：

```cpp
struct S { int i; std::string s; };
void f() {
  S x;   // s 构造为空串，x.i 没有初始化
}
```

把 ¶11、¶6 和静态初始化放在一起：

| 声明 | 存储期 | 结果 |
|---|---|---|
| 命名空间作用域的 `int g;` | 静态 | 启动时零初始化，值为 0 |
| 块作用域的 `static int s;` | 静态 | 同上 |
| 块作用域的 `int a;` | 自动 | 不初始化；C++26 起是错误值 |
| `new int` | 动态 | 不初始化；不确定值 |

### 未初始化的自动变量 {{c++26}}

```cpp run eb
int f() {
  int x;      // 不初始化：x 的字节是错误值
  return x;   // C++26：错误行为；C++23 及以前：UB
}
int main() { return f() & 0; }
```

在 C++23 及以前，读取一个没有初始化的 `int` 局部变量是未定义行为，优化器可以假设它不会发生。C++26 的 [[P2795R5]] 改变了这一点。[[basic.indet#1]] 规定，自动存储期对象的存储一获得，它的字节就具有**错误值**（[[g:erroneous-value|erroneous value]]）：一个由实现决定、与程序状态无关的值。读取它是**错误行为**（[[g:erroneous-behavior|erroneous behavior]]）。

错误行为仍然是程序的错误，实现可以诊断，也可以终止程序。但如果实现既不诊断也不终止，读到的就是那个错误值，编译器不能再假设这种读取不会发生。本机 Clang 23 对上面的代码给出 `-Wuninitialized` 警告。

这条规则有三个边界。动态存储期对象（`new int`）的字节仍是不确定值，读取仍是 UB（[[basic.indet#1]] 第 1 项）。用 `[[indeterminate]]` 属性（[[dcl.attr.indet]]）标记的变量也恢复为不确定值，适合不想让编译器为大缓冲区写入填充值的场合。错误值对类型无效时，比如 `bool` 的位模式既不是 0 也不是 1，读取它仍是 UB（[[basic.indet#1]] 注 1）。

### 值初始化（¶8）

¶8 **值初始化**（[[g:value-initialization|value-initialize]]）一个 `T` 类型的对象：

- ¶8.1 类类型，设 `C` 是默认初始化时会选中的构造函数。如果 `C` 不是用户提供的，先零初始化整个对象；然后在任何情况下都再默认初始化。
- ¶8.2 数组，检查假想元素的约束，再逐个值初始化元素。
- ¶8.3 其他情况，零初始化。

¶8.1 的两步正好给出人们对 `X{}` 期望的结果：

```cpp run ok
#include <cassert>
#include <string>
struct X {
  X() = default;     // 不是用户提供的
  int i;
  std::string s;     // 需要构造函数
};
int main() {
  X x{};             // X 不是聚合，{} 导致值初始化
  assert(x.i == 0);  // 先清零，i 为 0；再调用隐式默认构造函数构造 s
}
```

只调用默认构造函数，`x.i` 不会初始化；只清零，`s` 不会构造。两步合起来，编译器生成的部分全部清零，用户写的构造函数照常调用。

反过来，只要构造函数是用户提供的，哪怕是类外 `= default`，值初始化就不再清零：

<div class="compare" markdown="1">

```cpp ok
struct Y { Y() = default; int i; };
int f() {
  Y y{};       // 先清零
  return y.i;  // 0
}
```

```cpp eb
struct Y { Y(); int i; };
Y::Y() = default;  // 用户提供
int f() {
  Y y{};       // 不清零
  return y.i;  // 读取错误值
}
```

</div>

### const 对象必须有初始值（¶7）

```cpp
struct A { int i; };
struct B { int i; B() {} };            // 用户提供的构造函数
struct C { int i = 0; };
struct D { int i; D() = default; };    // 类内 = default：不是用户提供的
struct F { };
union  U { int a; int b = 0; };

const A ca;      // error: A 不是 const 可默认构造的
const B cb;      // OK: ¶7.3，尽管 cb.i 仍然没有初始化
const C cc;      // OK: ¶7.4.1
const D cd;      // error
const F cf;      // OK: 没有成员，¶7.4 的条件都成立
const U cu;      // OK: ¶7.4.2
const int ci;    // error
```

const 对象之后不能再赋值。如果默认初始化留下了没有初始化的成员，它们就永远没有确定的值，这几乎一定是 bug。所以 ¶7 规定，默认初始化 const 限定类型 `T` 的对象时，`T` 必须是 **const 可默认构造**（const-default-constructible）的，即满足下列之一：

- ¶7.1 `T` 是 `std::meta::info`；¶7.2 `T` 是 `std::nullptr_t`；
- ¶7.3 默认初始化 `T` 会调用 `T` 的用户提供的构造函数，而且不是从基类继承来的；
- ¶7.4 `T` 是类，并且每个直接的非变体非静态数据成员都有默认成员初始化器或者本身是 const 可默认构造的（¶7.4.1）；有成员的联合恰好有一个变体成员带默认成员初始化器（¶7.4.2）；不是联合时，每个匿名联合成员是 const 可默认构造的（¶7.4.3）；每个可能被构造的基类也是 const 可默认构造的（¶7.4.4）；
- ¶7.5 `T` 是元素类型 const 可默认构造的数组。

¶7.3 只看形式：`B` 有一个什么也不做的用户提供构造函数，`const B cb;` 就能通过。¶7.4 是 [[CWG253]] 的解决结果，在此之前的规则只认用户提供的默认构造函数，连 `struct F {}; const F cf;` 都会被拒绝。

### 引用不能默认初始化或值初始化（¶9）

¶9 要求默认初始化或值初始化一个引用的程序是非良构的。例如聚合中没有写到、也没有默认成员初始化器的引用成员（[[dcl.init.aggr#6]]）。`int& r;` 这样没有初始化器的引用声明另由 [[dcl.init.ref#1]] 禁止。

## 拷贝初始化与直接初始化（¶13–¶14）

```cpp
struct E { explicit E(int); };
E e1 = 1;                   // error: 拷贝初始化不考虑 explicit 构造函数
E e2(1);                    // OK: 直接初始化
E e3{1};                    // OK: 直接列表初始化
E e4 = {1};                 // error: 拷贝列表初始化选中了 explicit 构造函数
E e5 = static_cast<E>(1);   // OK: static_cast 是直接初始化
void take(E);
void g() { take(1); }       // error: 传参是拷贝初始化
```

初始化分成两类，区分它们的只是语法上下文，与实际有没有发生拷贝无关。

¶13 下列场合的初始化是**拷贝初始化**（[[g:copy-initialization|copy-initialization]]）：

| 场合 | 例子 |
|---|---|
| `=` 形式的初始化器 | `T x = e;`、`T x = {a, b};` |
| `=` 形式的条件 | `if (T x = e)` |
| 传参 | `f(e)` 初始化形参 |
| 返回 | `return e;` 初始化返回对象 |
| 抛出异常 | `throw e;` 初始化异常对象（[[except.throw]]） |
| 捕获异常 | `catch (T x)` 从异常对象初始化 `x`（[[except.handle]]） |
| 聚合成员，非指派 | `S s{e};`、`S s(e);` 中成员从 `e` 初始化 |

注 5 提醒，拷贝初始化可能调用移动构造函数（[[class.copy.ctor]]），名字里的拷贝是沿用下来的叫法。

¶14 下列场合的初始化是**直接初始化**（[[g:direct-initialization|direct-initialization]]）：

- ¶14.1 圆括号或花括号形式的初始化器：`T x(a, b);`、`T x{a};`、成员初始化器 `: m(a)`；
- ¶14.2 *new-initializer*：`new T(a)`、`new T{a}`；
- ¶14.3 `static_cast<T>(e)`；
- ¶14.4 函数式类型转换：`T(e)`、`T{e}`；
- ¶14.5 花括号形式的条件：`if (T x{e})`。

两者的实际差别有三点：

1. `explicit` 构造函数和 `explicit` 转换函数只在直接初始化中作为候选（[[over.match.ctor]]、[[over.match.copy]]、[[over.match.conv]]）。
2. 从无关类型拷贝初始化一个类对象时，走第 15 段第 6.3 项的用户定义转换，而不是第 6.2 项的构造函数重载决议，两者的候选集不同（见后文）。
3. `nullptr` 到 `bool` 只在直接初始化中允许（第 15 段第 8 项）。

`e1` 和 `e4` 出错的原因不同。`E e1 = 1;` 中，explicit 构造函数根本不是候选，于是找不到转换。`E e4 = {1};` 中，它是候选，而且被选中了，程序因为拷贝列表初始化选中 explicit 构造函数而非良构（[[over.match.list]]）。即使还有一个非 explicit 但匹配较差的构造函数，编译器也不会退而选它。

指派初始化器的形式决定了它属于哪一类：`.m = e` 是拷贝初始化，`.m{e}` 是直接列表初始化（[[dcl.init.aggr#5]] 注 3）。

## 总流程（¶15）

¶15 先定义两个术语。**目标类型**（destination type）是被初始化的对象或引用的类型，去掉顶层 cv 限定。**源类型**（source type）是初始化表达式的类型；初始化器不是单个（可以带括号的）表达式时，比如 `(a, b)` 或花括号列表，源类型没有定义。

然后按顺序检查，第一个成立的分支决定结果：

```text
15.1  初始化器是 {…} 或 = {…}              → 列表初始化 [dcl.init.list]
15.2  目标类型是引用                        → 引用绑定 [dcl.init.ref]
15.3  目标是字符数组，初始化器是字符串字面量  → [dcl.init.string]
15.4  初始化器是 ()                         → 值初始化
15.5  目标是数组，初始化器是 (x1, …, xk)     → 逐元素拷贝初始化，其余值初始化   C++20
15.6  目标是类类型
  .1  初始化器是同类型的纯右值               → 直接用它初始化目标              C++17
  .2  直接初始化，或从同类/派生类拷贝初始化   → 构造函数重载决议
      .2.1 成功                            → 调用构造函数
      .2.2 无可行构造函数、聚合、(…) 形式    → 圆括号聚合初始化                C++20
      .2.3 否则                            → 非良构
  .3  其余的拷贝初始化                       → 用户定义转换 [over.match.copy]
15.7  源类型是类类型（目标不是类）            → 转换函数 [over.match.conv]
15.8  直接初始化，nullptr_t → bool          → false
15.9  其他                                 → 标准转换序列
```

每个分支一个最小例子：

| 分支 | 例子 | 结果 |
|---|---|---|
| 15.1 | `std::vector<int> v{1, 2};` | 列表初始化，调用 `initializer_list` 构造函数 |
| 15.2 | `const int& r = 1;` | 引用绑定到实质化的临时量 |
| 15.3 | `char s[] = "hi";` | `s` 是 `char[3]` |
| 15.4 | `new int()`、`T()`、`: m()` | 值初始化 |
| 15.5 | `int a[](1, 2, 3);` | `int[3]` |
| 15.6.1 | `T x = T(T(T()));` | 只有一个对象，它被值初始化 |
| 15.6.2 | `std::string s("abc");` | 调用 `string(const char*)` |
| 15.6.2.2 | `struct P { int a, b; }; P p(1, 2);` | 圆括号聚合初始化 |
| 15.6.3 | `std::string s = "abc";` | 转换构造函数产生纯右值，再初始化 `s` |
| 15.7 | `struct Q { operator int(); } q; int n = q;` | 调用 `Q::operator int` |
| 15.8 | `bool b(nullptr);` | `b == false` |
| 15.9 | `double d = 1;` | 整数到浮点的标准转换 |

### 第 1–3 项：转交给子条款

第 1 项：初始化器是不带外层圆括号的花括号列表，即 `T x{…}` 或 `T x = {…}` 时，不论 `T` 是引用、标量还是类，一律转交 [[dcl.init.list]]。所以列表初始化优先于后面所有关于引用、数组和类的规则。`T x({1, 2})` 是圆括号形式，唯一的表达式恰好是花括号列表，它不走这一项，而是走到第 6.2 项，把 `{1, 2}` 作为构造函数的实参。

第 2 项：目标是引用，转交 [[dcl.init.ref]]。第 3 项：目标是 `char`、`char8_t`、`char16_t`、`char32_t` 或 `wchar_t` 数组，初始化器是字符串字面量，转交 [[dcl.init.string]]。

### 第 4 项：`()` 表示值初始化

```cpp run ok
#include <cassert>
struct M { int v; M() : v() {} };   // 成员初始化器里的 ()：v == 0
int main() {
  int* p = new int();               // new 里的 ()：*p == 0
  int i = int();                    // 函数式转换 T()：i == 0
  M m;
  assert(*p == 0 && i == 0 && m.v == 0);
  delete p;
}
```

初始化器是 `()` 时，对象被值初始化。但注 6 指出 *initializer* 的文法不允许 `()`，所以 `X a();` 不是对象声明，而是声明了一个无参、返回 `X` 的函数。`()` 只出现在 `new`、函数式转换和成员初始化器里。

这是**最令人烦恼的解析**（[[g:most-vexing-parse|most vexing parse]]）最简单的形式。更复杂的形式如 `T x(U());` 也会被解析成函数声明，形参是返回 `U` 的函数；原因是 [[dcl.ambig.res]] 规定能解析为声明的就是声明。C++11 的 `T x{};` 可以绕开这种歧义。本机 Clang 23 对 `T x();` 给出 `-Wvexing-parse` 警告（empty parentheses interpreted as a function declaration）。

### 第 5 项：数组的圆括号初始化 {{c++20}}

```cpp run ok
int a[](1, 2, 3);   // int[3]
int b[5](1, 2);     // {1, 2, 0, 0, 0}
static_assert(sizeof a == 3 * sizeof(int));
int main() { return b[4]; }
```

目标是数组时，花括号、字符串字面量和 `()` 都已在前面处理掉，剩下的初始化器必须是 `(x1, …, xk)` 形式；`T a[3] = x;` 这样的单个表达式是非良构的。

未知边界的数组定义为 k 个元素。k 大于数组长度时非良构。第 i 个元素从 xi 拷贝初始化，其余元素值初始化。各元素的初始化严格从左到右进行。

这一项和第 6.2.2 项都来自 [[P0960R3]]，动机是让 `std::make_unique<T>(args...)`、`emplace_back(args...)` 这类内部写 `T(std::forward<Args>(args)...)` 的泛型代码也能用于聚合和数组。

### 第 6.1 项：同类型的纯右值

```cpp run ok
struct NoMove {
  NoMove(int) {}
  NoMove(const NoMove&) = delete;
  NoMove(NoMove&&) = delete;
};
NoMove make() { return NoMove(1); }    // OK：纯右值直接初始化返回对象
NoMove a = NoMove(NoMove(NoMove(1)));  // OK：只构造一次
NoMove b = make();                     // OK
int main() {}
```

初始化表达式是纯右值，并且去掉 cv 后类型与目标类型相同时，直接用这个表达式初始化目标对象。

这是 C++17 [[P0135R1]]（保证的复制消除）的核心：纯右值不再代表一个临时对象，而是初始化某个对象的方法，被初始化的那个对象叫它的**结果对象**（result object），由上下文决定（[[basic.lval]]）。在 C++14 中，上面三处都要求可访问的拷贝或移动构造函数，即使实现会把拷贝省掉，所以都是非良构的。

这一项不区分直接初始化和拷贝初始化，也根本不看构造函数。所以 C++17 起可以写 `auto g = std::lock_guard<std::mutex>(m);`，也可以让函数按值返回 `std::lock_guard` 这种既不能拷贝也不能移动的类型。

### 第 6.2 项：构造函数重载决议

如果是直接初始化，或者是拷贝初始化但源类型（去掉 cv）与目标类型相同或派生自目标类型，就考虑构造函数：按 [[over.match.ctor]] 列出候选，直接初始化时包括 explicit 构造函数，然后做重载决议。

- 第 6.2.1 项：决议成功，用初始化表达式或表达式列表作为实参调用选中的构造函数。
- 第 6.2.2 项 {{c++20}}：没有可行的构造函数、目标是聚合类、初始化器是圆括号表达式列表时，做圆括号聚合初始化。
- 第 6.2.3 项：否则非良构。

源类型派生自目标类型这个条件，让 `Base b = derived;` 这样的切片拷贝走构造函数，调用 `Base` 的拷贝或移动构造函数。

聚合也有隐式的拷贝和移动构造函数，所以 `P p(other_p);` 仍然调用拷贝构造函数；只有实参匹配不上任何构造函数时，才轮到圆括号聚合初始化。

### 圆括号聚合初始化（第 6.2.2 项）{{c++20}}

设聚合的元素是 e1…en（[[dcl.init.aggr#2]]），表达式是 x1…xk。k 大于 n 时非良构。ei 从 xi 拷贝初始化，其余元素用默认成员初始化器初始化，没有的话值初始化。各元素严格从左到右初始化。

注 7 列出了它与花括号形式的四点不同，下面是标准的例 3：

```cpp
struct A {
  int a;
  int&& r;
};
int f();
int n = 10;

A a1{1, f()};               // OK: 临时量的生命期被延长
A a2(1, f());               // 良构，但 a2.r 悬垂
A a3{1.0, 1};               // error: 窄化
A a4(1.0, 1);               // 良构（允许窄化），但 a4.r 悬垂
A a5(1.0, std::move(n));    // OK
```

| | `T{…}` | `T(…)` 用于聚合 |
|---|---|---|
| 窄化转换 | 禁止 | 允许 |
| 指派初始化器 | 允许 | 不允许 |
| 绑定到引用成员的临时量 | 延长生命期 | 不延长（[[class.temporary#6]]） |
| 花括号省略 | 有 | 没有 |

这些差异是有意的：`T(args...)` 用于聚合时，表现得像调用一个按成员顺序接受参数的构造函数。构造函数的形参允许窄化；绑定到构造函数引用形参的临时量在完整表达式结束时销毁；构造函数调用也没有花括号省略。这样，把一个聚合改成带构造函数的类，或者反过来，`T(args...)` 的含义变化最小。

```cpp
struct In { int i, j; };
struct O { In in; int k; };
O o1{1, 2, 3};      // OK: 花括号省略，o1.in = {1, 2}
O o2({1, 2}, 3);    // OK: 第一个元素从 {1, 2} 拷贝初始化
O o3(1, 2, 3);      // error: 没有花括号省略，int 不能转换为 In
```

### 第 6.3 项：拷贝初始化中的用户定义转换

剩下的是拷贝初始化，并且源类型与目标类型无关。这时按 [[over.match.copy]] 列出能把源类型转换为目标类型的用户定义转换：目标类的非 explicit 转换构造函数，以及源类型的非 explicit 转换函数（它可以返回目标类型的派生类），然后从中选出最佳的一个。

选中的是构造函数时，调用的结果是目标类型的纯右值，它的结果对象就是被初始化的对象。选中的是转换函数时，用它的返回值按上面的规则再直接初始化目标对象。

```cpp
#include <string>
std::string s1 = "abc";   // string(const char*) 的纯右值直接成为 s1
struct Base {}; struct Der : Base {};
struct From { operator Der() const; };
Base b = From();          // 转换函数返回 Der，再直接初始化 b：
                          // 第 6.2 项，调用 Base 的移动构造函数（切片）
```

与第 6.2 项相比，这里只允许一次用户定义转换，并且是在所有能到达目标类型的转换中选，而不只是在目标类型的构造函数中选：

<div class="compare" markdown="1">

```cpp ok
struct A { A(int); };
struct B { B(A); };
B b1(1);
// 直接初始化：调用 B(A)，
// 实参 1 经 A(int) 转换
```

```cpp error
struct A { A(int); };
struct B { B(A); };
B b2 = 1;
// 需要 int→A→B
// 两次用户定义转换
```

</div>

C++17 之前，这一项的结果是一个临时对象，再用它拷贝或移动构造目标，即使这次拷贝会被省掉，也要求拷贝或移动构造函数可访问。

### 第 7 项：从类类型到非类类型

```cpp
struct Q { explicit operator int() const; };
Q q;
int a(q);        // OK: 直接初始化考虑 explicit 转换函数
int b = q;       // error: 拷贝初始化不考虑
int c = int(q);  // OK: 函数式转换是直接初始化
bool d = q;      // error: explicit operator int 不是候选
```

目标不是类类型，源类型是类类型时，按 [[over.match.conv]] 列出转换函数并做重载决议。直接初始化时 explicit 转换函数也是候选。

`explicit operator bool` 能用在 `if (q)` 中，是因为条件表达式要按语境转换为 `bool`，这种转换的定义就是直接初始化 `bool t(e);`（[[conv]]）。

### 第 8 项：用 `nullptr` 直接初始化 `bool`

```cpp
bool b1(nullptr);    // OK: false
bool b2{nullptr};    // OK: 直接列表初始化，最终也走到第 8 项
bool b3 = nullptr;   // error
```

直接初始化、源类型是 `std::nullptr_t`、目标是 `bool` 时，结果是 `false`。拷贝初始化走不到这一项，只能落到第 9 项，而 [[conv.bool]] 的布尔转换只覆盖算术、无作用域枚举、指针和成员指针类型，不包括 `std::nullptr_t`，所以 `b3` 非良构。

这样设计，`bool(x)` 在泛型代码中对任何类似指针的类型都能用，而对 `nullptr` 字面量的隐式判空不会悄悄发生。本机 Clang 23 对 `b1`、`b2` 给出 `-Wnull-conversion` 警告。

### 第 9 项：标准转换

其他情况下，源和目标都不是类类型。用标准转换序列（[[conv]]）把初始化表达式转换为目标类型的纯右值，不考虑用户定义转换；转换不了就非良构。

用位域表示不了的值初始化位域，结果由实现定义 {{impl}}。普通整数的转换 C++20 起按取模定义（[[conv.integral]]），位域的宽度不属于类型，所以单独规定。注 8 提醒，cv 限定不影响初始化：`const int b = a; int c = b;` 都没问题。

## 圆括号里的表达式（¶12、¶19）

¶12 被初始化的实体既不是类也不是数组时，圆括号里只能有一个表达式：

```cpp
int x(1, 2);     // error: 标量的圆括号初始化器只能有一个表达式
int y((1, 2));   // OK: 内层括号是逗号表达式，y == 2
```

`int x(1, 2)` 里的逗号是表达式列表的分隔符，不是逗号运算符。数组被排除在外，是因为 C++20 起数组可以用圆括号初始化（第 15 段第 5 项）。

¶19 目标类型不是聚合、初始化器是圆括号表达式列表时，各表达式按函数实参的方式求值，彼此**顺序不确定**（[[g:indeterminately-sequenced|indeterminately sequenced]]，[[expr.call]]）。花括号列表中的子句则严格从左到右求值（[[dcl.init.list#4]]），聚合的圆括号初始化也是从左到右。

```cpp run unspecified
#include <cstdio>
struct I { I(int x) { std::printf("%d", x); } };
struct S { S(I, I) {} };
int main() {
  S(I(1), I(2)); std::puts("");   // 打印 12 或 21，未指定
  S{I(1), I(2)}; std::puts("");   // 一定打印 12
}
```

## 其他规则（¶2、¶16–¶18、¶20–¶22）

¶2 除 `constexpr` 变量外（它要求常量表达式，见 [[dcl.constexpr]]），变量的初始化器可以是任意表达式，与存储期无关。C 要求静态存储期对象的初始化器是常量表达式，C++ 允许命名空间作用域的 `int b = f(a);`。代价是动态初始化和随之而来的初始化顺序问题（[[g:static-initialization-order-fiasco|static initialization order fiasco]]），见 [[basic.start.dynamic]]。

¶16 {{c++20}} 默认实参和默认成员初始化器里的**立即调用**（对 `consteval` 函数的调用，[[expr.const.imm]]）不在它出现的位置求值，而是在使用这个初始化器的函数调用、构造函数定义或聚合初始化处求值，并在那里检查它是否是常量表达式。

¶17 后面跟 `...` 的子句是包展开（[[temp.variadic]]），如 `int arr[]{args...};`。

¶18 初始化包括初始化器中所有子表达式的求值（包括嵌套在花括号里的），以及为函数实参或返回值创建临时对象。这句话界定了初始化这件事的范围，例如 [[stmt.dcl]] 规定静态局部变量的初始化以异常结束时下次会重试，异常可以来自初始化器中的任何子表达式。

¶20 同一个指派初始化器列表中，同一个名字不能出现两次：`A a{.x = 1, .x = 2};` 非良构。C 允许后者覆盖前者，C++ 不允许，因为每个成员只初始化一次。本机 Clang 23 在 C++ 模式下对此只给出 `-Winitializer-overrides` 警告，加 `-pedantic-errors` 才报错；按标准它是非良构的。

¶21 定义了**视为构造**（deemed construction）：对象的初始化完成时，就视为它已经构造好了，即使它不是类类型，或者初始化时没有调用任何构造函数。为了 [[basic.start.term]]，如果初始化是一个完整表达式，就在这个完整表达式求值完成时视为构造。静态存储期对象按构造完成的逆序销毁，只有构造过的对象才销毁（[[stmt.dcl#4]]），这需要对 `int`、聚合这类对象也说清楚什么时候算构造完成。¶21 的后半段规定：销毁类对象调用析构函数；销毁标量除结束生命期外没有其他效果；销毁数组按下标逆序销毁各元素。

¶22 指定了变量如何初始化的那个声明（通过初始化器，或者通过默认初始化）叫做变量的**初始化声明**（[[g:initializing-declaration|initializing declaration]]）。注 10 指出，它通常就是定义；但非 inline 静态数据成员的初始化声明可以是类内的声明，而定义在类外：

```cpp
struct S {
  static const int n = 42;   // 初始化声明，不是定义
};
const int S::n;              // 定义，没有初始化器
```

[[expr.const]] 用这个术语规定变量从哪里开始可以用在常量表达式中。

¶3 的注：默认实参受更多限制，见 [[dcl.fct.default]]。

¶4 的注：静态存储期变量的初始化顺序见 [[basic.start]] 和 [[stmt.dcl]]。

¶10 的注：每个静态存储期对象在程序启动时，先于任何其他初始化进行静态初始化（[[basic.start.static]]），某些对象之后还有动态初始化。

## 实现视角

!!! impl
    - 只需零初始化的静态存储期对象放在 `.bss` 段，由加载器清零，不占可执行文件的体积；常量初始化的对象放在 `.data` 或 `.rodata`；只有需要动态初始化的对象才生成初始化代码（ELF 上登记在 `.init_array`）。
    - 零初始化不一定是全零位。Itanium ABI 中空的数据成员指针是 `-1`，含成员指针的结构体零初始化时编译器要写入非零值，这样的对象也不能放进 `.bss`。
    - `X x{};`（`X() = default`）通常编译成一次清零再加上（往往为空的）构造函数调用；`Y y{};`（用户提供的构造函数）只有构造函数调用。

## 历史

!!! history
    - C++98 只有零初始化和默认初始化。当时默认初始化对非 POD 类调用默认构造函数，对 POD 类型是零初始化；没有初始化器的 POD 对象则不初始化。于是 `T()` 会把 POD 清零，却不会清零一个带非平凡成员的类的标量成员。
    - C++03 引入值初始化：`T()` 对没有用户声明构造函数的类先清零，修正了上面的问题。
    - C++11 加入列表初始化（[[dcl.init.list]]），引入用户提供的概念和 `= default`，值初始化据此改写。
    - C++17 的 [[P0135R1]] 保证了复制消除，有了第 15 段第 6.1 项，第 6.3 项的转换结果也直接初始化目标；[[CWG253]] 的解决把 const 对象的规则放宽为 const 可默认构造。
    - C++20 的 [[P0960R3]] 加入数组和聚合的圆括号初始化，还加入了指派初始化器。
    - C++26 的 [[P2795R5]] 把读取未初始化的自动变量从 UB 改为错误行为；[[P2996R13]] 加入 `std::meta::info` 的零初始化和默认初始化规则。

## 常见误解

!!! pitfall "`T x();` 声明了一个对象"
    它声明的是函数。`std::mutex m();` 之后写 `std::lock_guard g(m);`，报错的位置会离真正的原因很远。应该写 `T x;` 或 `T x{};`。

!!! pitfall "`= default` 写在类内还是类外都一样"
    `struct Y { Y(); int i; }; Y::Y() = default;` 让构造函数成为用户提供的，`Y{}` 不再把 `i` 清零。把 `= default` 写在类内，或者给成员写默认成员初始化器 `int i = 0;`，后者最稳妥。

!!! pitfall "`std::make_unique<A>(1, f())` 和 `A{1, f()}` 一样"
    `make_unique` 内部用圆括号初始化。如果 `A` 是有引用成员的聚合，圆括号形式不延长临时量的生命期，引用成员立即悬垂。

## 思考题

!!! question "思考题 1"
    下面三个自动变量的成员各是什么值？
    ```cpp
    struct A { int i; A() = default; };
    struct B { int i; B(); }; B::B() = default;
    struct C { A a; int j; C() {} };
    A a1{}; B b1{}; C c1{};
    ```

<details markdown="1">
<summary>答案</summary>

`A` 有用户声明的构造函数，C++20 起不是聚合。`A a1{}` 按 [[dcl.init.list#3]] 第 5 项值初始化；默认构造函数不是用户提供的，所以先清零，`a1.i == 0`。

`B::B()` 是用户提供的，`B b1{}` 值初始化时不清零，`b1.i` 没有初始化，C++26 中是错误值。

`C()` 是用户提供的，`C c1{}` 不清零，直接调用 `C()`。它的成员初始化列表没有提到 `a` 和 `j`，二者都默认初始化（[[class.base.init]]）：`a` 调用 `A` 的隐式默认构造函数，`a.i` 没有初始化，`j` 也没有。外层的值初始化不会延伸进用户写的构造函数。
</details>

!!! question "思考题 2"
    为什么 `bool b = nullptr;` 非良构，而 `bool b{nullptr};` 良构？

<details markdown="1">
<summary>答案</summary>

`bool b = nullptr;` 是拷贝初始化，走不到第 15 段第 8 项，落到第 9 项，需要从 `std::nullptr_t` 到 `bool` 的标准转换，而 [[conv.bool]] 不包括 `nullptr_t`。

`bool b{nullptr};` 是直接列表初始化：第 1 项转到 [[dcl.init.list#3]] 第 9 项（单元素列表），以直接初始化的方式从这个元素初始化，回到第 15 段时满足第 8 项，结果为 `false`。它也不是窄化：[[dcl.init.list#7]] 第 5 项只把指针和成员指针到 `bool` 的转换列为窄化。
</details>

!!! question "思考题 3"
    对 `struct NoMove { NoMove(int); NoMove(NoMove&&) = delete; };`，`NoMove x = 1;` 在 C++14 和 C++17 中分别如何？

<details markdown="1">
<summary>答案</summary>

两者都走第 15 段第 6.3 项：拷贝初始化，源类型 `int` 与目标无关，选中转换构造函数 `NoMove(int)`。

C++14 中，转换的结果是一个临时对象，再用它直接初始化 `x`，这需要移动构造函数，而它被删除了，所以非良构。C++17 中，构造函数调用是一个纯右值，它的结果对象就是 `x`，不需要移动构造函数，因此良构。
</details>
