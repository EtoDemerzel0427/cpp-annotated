第 1 章是 ISO 文件必备的范围（Scope）条款，只有一段话，但这段话决定了整本标准的视角，值得仔细读。

## 标准规定的是什么（¶1）

¶1 本文档规定对 C++ 实现的要求。C++ 是一门通用编程语言。第一条要求是实现要实现这门语言，因此本文档也定义了 C++。其他要求以及对第一条要求的放宽散布在文档各处。

!!! std
    This document specifies requirements for implementations of C++, which is a general-purpose programming language.

这段话有三个要点。

**1. 标准的读者是实现者，不是程序员。** 标准对实现（编译器、标准库和运行环境的组合）提要求；对程序的要求只是一种方便的说法，[[intro.compliance]] ¶2 规定了如何把它翻译回对实现的要求。所以当标准说"程序 shall not ……"时，严格的含义是：如果程序这样做了，实现必须给出诊断（在 IFNDR 或 UB 的情况下，则是实现不受约束）。从这个视角看，未定义行为的含义就很自然了：它的意思不是程序做了坏事会受到惩罚，而是标准对实现没有要求。

**2. 语言的定义是要求的副产品。** 标准并不先定义一个抽象的 C++ 语言、再要求实现遵守它，而是说实现必须实现这门语言，至于这门语言是什么，由接下来的全部条文描述。因此 C++ 的语义最终落在抽象机（[[intro.abstract]]）上，抽象机描述的正是实现必须表现得像什么。

**3. 放宽同样是标准的一部分。** 原文所说的"其他要求以及对第一条要求的放宽"，指的是实现限制（实现可以拒绝过大的程序）、有条件支持的构造（实现可以不支持）、独立实现（只需提供部分库）、as-if 规则（实现无需真的按抽象机的步骤执行）等。它们都在 [[intro.compliance]] 中集中规定。

## 历史

!!! history
    在 C++98 到 C++14 中，第 1 章叫 General，范围只是其中的 1.1 [intro.scope]。C++17 按 ISO 文件的统一结构重排，第 1 章只剩范围，规范性引用、术语定义、总则分别成为第 2、3、4 章。stable name `[intro.scope]` 始终未变。

    早期版本的范围条款还专门说明 C++ 基于 C 编程语言，并引用当时的 C 标准；当前草案中这句话已经不在了。与 C 的关系改由 [[intro.refs]]（C 标准作为规范性引用）和 Annex C [[diff]]（兼容性差异）交代。
