当一个名字对应多个函数模板时，模板实参推导可能为**不止一个**模板找到可行的特化：

```cpp
template<class T> void f(T);         // #1
template<class T> void f(T*);        // #2
int* p;
f(p);                                // #1 推导出 f<int*>(int*)，#2 推导出 f<int>(int*)
```

两个特化的参数类型完全相同（都是 `int*`、精确匹配），重载决议的转换序列比较分不出高下。这时就要问：**哪个模板更"特化"**——更窄、对实参要求更多？直觉上 `#2` 只接受指针，而 `#1` 接受任何东西，所以 `#2` 更特化，应当被选中。[[g:partial-ordering|**偏序**]]（partial ordering）就是把这个直觉形式化的算法。

之所以叫"偏"序，是因为它不是全序：两个模板可能**互不更特化**（例如 `f(T, int)` 与 `f(int, T)`），此时偏序不给出答案，调用歧义。

这一节（13.7.7.3 [temp.func.order]）规定算法的框架：何时使用、怎样变换模板、成员函数怎么处理、约束怎么作为平局裁决；具体的推导步骤在 [[temp.deduct.partial]]。本页把两者合起来讲，并附多个完整的推演表格。

## 何时使用偏序（¶1）

¶1 函数模板同名时，名字的使用可能有歧义，因为模板实参推导（[[temp.deduct]]）可能为多个函数模板识别出特化。偏序在以下语境中用于选择函数模板特化所对应的那个函数模板：

- ¶1.1 对函数模板特化的**调用**进行重载决议时（[[over.match.best]]）；
- ¶1.2 **取**函数模板特化的**地址**时（[[over.over]]）；
- ¶1.3 为 placement 分配函数选择匹配的 placement **释放函数**，且后者是函数模板特化时（[[basic.stc.dynamic.deallocation]]、[[expr.new]]）；
- ¶1.4 **友元函数声明、显式实例化、显式特化**指向函数模板特化时。

注意在重载决议中，偏序是**靠后的**平局裁决：先比较隐式转换序列，再比较"非模板优于模板"，然后才是偏序（[[over.match.best]]）。偏序只在转换序列不分高下时介入。

¶1.4 是常被忽略的一点：没有显式模板实参的显式特化，要靠推导 + 偏序来决定它特化的是哪个模板：

```cpp run ok
template<class T> void f(T) { }      // #1
template<class T> void f(T*) { }     // #2
template<> void f(int*) { }          // 显式特化：#1(T=int*) 与 #2(T=int) 都匹配，偏序选 #2 → 这是 #2 的 f<int>
int main() { int x; f(&x); }         // 调用 #2 的显式特化
```

## 算法总览（¶2）

¶2 偏序通过**依次变换**每个模板（见 ¶3），并**用函数类型做模板实参推导**，来判断两个函数模板中哪个更特化。推导过程决定是否一个比另一个更特化；若是，偏序选择更特化的那个。若**双向推导都成功**，偏序选择**更受约束**的模板（若存在，见 ¶8）。

整体流程：

1. 对模板 F，把它的每个模板形参替换为**合成的唯一**类型/值/模板，得到"变换后的 F"（¶3–4）。
2. 用变换后的 F 的参数类型作**实参**（A），对模板 G 的原始参数类型（P）做推导（[[temp.deduct.partial]]）。若成功，说"F 至少和 G 一样特化"。
3. 反过来，用变换后的 G 对 F 推导。
4. 若 F 至少和 G 一样特化，而 G 不是至少和 F 一样特化，则 **F 比 G 更特化**。
5. 若双向都成功（互相至少一样特化），进入约束比较（¶8）；若双向都失败或约束也分不出，则互不更特化。

直觉：**变换后的 F 代表"F 能接受的最一般的实参"**。若 G 能接受这样的实参（推导成功），说明 G 的接受范围 ⊇ F 的；若反之不成立，F 的范围严格更小，F 更特化。

## 变换：合成唯一的类型、值与模板（¶3–4）

¶3 为生成变换后的模板，对每个类型、常量、类型模板、变量模板或概念模板形参（包括其形参包），分别**合成**一个唯一的类型、值、类模板、变量模板或概念，并替换模板函数类型中该形参的每一次出现。为常量模板形参合成的值，若其类型含占位符，占位符被替换为一个唯一的合成类型。

¶4 合成的模板与对应的模板模板形参有**相同的** *template-head*。

"唯一"的意思是：合成的类型**不等于任何其他类型**，不满足任何"恰好是某某类型"的匹配。因此 `T` 变换后成为 `U₁`，推导 `P = int` 对 `A = U₁` 就会失败（`U₁` 不是 `int`）。

!!! note "合成类型满足约束吗？"
    偏序的推导阶段**不检查约束**——合成类型 `U₁` 是否满足 `std::integral` 在推导中不被问到。约束只在 ¶8 中作为平局裁决单独比较（用的是约束的**包含关系**，[[temp.constr.order]]，而不是"`U₁` 满不满足"）。

## 成员函数：插入对象参数（¶5）

¶5 成员函数模板 M 被看作在其函数参数列表最前面插入了一个**新的第一参数**，类型为 X(M)。对 `cv` 限定的、类 A 的成员函数模板 M：

- ¶5.1 若 M 的 *ref-qualifier* 是 `&&`，或者 M **没有** *ref-qualifier* 而另一个变换后模板中位置对应的参数是**右值引用**类型，则 X(M) 是"对 cv A 的右值引用"（若这一判断递归地依赖于 X(M) 本身是否是右值引用，则不认为它是右值引用）；
- ¶5.2 否则，X(M) 是"对 cv A 的左值引用"。

注 1：这使得成员函数可以与非成员函数一起排序，结果与两个等价的非成员函数的排序一致。

此外：若**恰好一个**模板是经由**参数顺序反转**的重写候选（[[over.match.oper]]，如 C++20 中 `a == b` 被重写为 `b == a`）被考虑的，那么它的变换后模板中函数参数的顺序也要**反转**。

```cpp run ok
struct A { };
template<class T> struct B {
    template<class R> int operator*(R&) { return 1; }              // #1
};
template<class T, class R> int operator*(T&, R&) { return 2; }     // #2

// 偏序时 #1 被看作：template<class R> int operator*(B<A>&, R&);   // #1a

int main() {
    A a;
    B<A> b;
    return b * a - 1;   // 调用 #1：#1a 的第一参数是具体的 B<A>&，比 #2 的 T& 更特化
}
```

推演：#1a = `(B<A>&, R&)`，#2 = `(T&, R&)`。

| 方向 | 变换后（A） | 对另一个的原始 P 推导 | 结果 |
|---|---|---|---|
| #1a → #2 | `(B<A>&, U&)` | `T& ← B<A>&`：`T = B<A>`；`R& ← U&`：`R = U` | 成功 |
| #2 → #1a | `(U₁&, U₂&)` | `B<A>& ← U₁&`：`U₁` 不是 `B<A>` | 失败 |

#1 更特化。注意 `B<A>` 中的 `A` 不是模板形参（`B<A>` 是已实例化的类），所以它不被替换为合成类型。

!!! note "显式对象参数（C++23）"
    带显式对象参数的成员函数（`this auto&& self`，[[P0847R7]]）本来就把对象参数写在参数列表里，不需要 ¶5 的插入。¶5 只适用于具有**隐式**对象参数的成员函数。

## 推导细节（[temp.deduct.partial]）

¶6 用变换后函数模板的函数类型，按 [[temp.deduct.partial]] 对另一个模板做类型推导。由于 ¶6 把具体步骤委托过去，这里完整复述那一节的要点（段落号指 [temp.deduct.partial]）：

**用哪些类型**（¶3）：

- 函数**调用**语境：只用**调用中有对应实参**的那些函数参数的类型（脚注：默认实参在此不算实参）；
- 调用**转换函数**的语境：用转换函数模板的**返回类型**；
- 其他语境（取地址、显式特化等）：用整个**函数类型**。

**预处理**（¶5–7）：

1. 若 P 是引用类型，替换为所引用的类型；A 同理；
2. 若 P 和 A **原本都是**引用类型，记下哪一个**更 cv 限定**（供 ¶9 使用）；
3. 去掉 P 与 A 的顶层 cv 限定。

**推导**（¶8）：若 A 来自函数形参包而 P 不是包，推导失败。否则按 [[temp.deduct.type]] 推导。若 P 是函数形参包，则参数模板中剩余的每个参数类型 A 都与包的声明符类型比较。若对某个类型推导成功，A 所在的类型"至少与 P 所在的类型一样特化"。

**引用的平局规则**（¶9）：若某一对类型在上述变换后**相同**，并且 P、A 原本**都是引用**：

- ¶9.1 若来自实参模板的是**左值引用**而来自形参模板的不是，则形参模板的类型**不**被认为至少与实参模板的一样特化；否则
- ¶9.2 若来自实参模板的类型**更 cv 限定**，则形参模板的类型不被认为至少一样特化。

**汇总**（¶10）：F 对每一对类型都至少一样特化，则 F 至少与 G 一样特化；F 至少与 G 一样特化而 G 不至少与 F 一样特化，则 F 更特化。

**尾随包的平局**（¶11）：若 F 与 G 互相至少一样特化，G 有一个尾随函数形参包而 F 在该位置没有对应参数，且 F 自身没有尾随函数形参包，则 F 更特化。

**未使用的模板形参**（¶12）：偏序时，模板形参可以没有推导出值，只要它没有在用于偏序的类型中被使用（非推导语境中的使用也算"使用"）。

## 推演实例

### 实例 1：T、T*、const T*

¶6 的例 2：

```cpp run ok
template<class T> int f(T)        { return 1; }
template<class T> int f(T*)       { return 2; }
template<class T> int f(const T*) { return 3; }
int main() {
    const int* p = nullptr;
    return f(p) - 3;   // 调用 f(const T*)
}
```

三个候选推导：`f(T)`：`T = const int*`；`f(T*)`：`T = const int`；`f(const T*)`：`T = int`。参数类型都是 `const int*`，精确匹配，进入偏序。两两比较：

| F → G（F 变换后作 A，G 原始作 P） | A | P | 推导 | F 至少与 G 一样特化？ |
|---|---|---|---|---|
| `T*` → `T` | `U*` | `T` | `T = U*` | 是 |
| `T` → `T*` | `U` | `T*` | `U` 不是指针 | 否 |
| `const T*` → `T*` | `const U*` | `T*` | `T = const U` | 是 |
| `T*` → `const T*` | `U*` | `const T*` | `U*` 的指向类型 `U` 没有 const（推导不加 cv） | 否 |
| `const T*` → `T` | `const U*` | `T` | 成功 | 是 |

所以 `f(T*)` 比 `f(T)` 更特化，`f(const T*)` 比两者都更特化。注意第四行：在偏序中 P/A 推导**不允许**普通调用推导中的那些宽松（[[temp.deduct.call]] 允许 A 比 P 少 cv 再做限定转换，偏序用的是 [[temp.deduct.type]] 的精确匹配）。

### 实例 2：T 与 T&（为什么歧义）

```cpp error
template<class T> void g(T);
template<class T> void g(T&);
void m() {
    float x;
    g(x);          // error: 歧义
}
```

| 方向 | A（变换后） | P（原始） | 预处理后 | 结果 |
|---|---|---|---|---|
| `g(T&)` → `g(T)` | `U&` | `T` | A 去引用：`U`；P = `T` | 成功 |
| `g(T)` → `g(T&)` | `U` | `T&` | P 去引用：`T`；A = `U` | 成功 |

双向成功；¶9 的引用平局规则要求 P 和 A **都**原本是引用，这里只有一边是，不适用。没有约束。互不更特化 → 歧义。这就是"按值与按引用重载函数模板"总是歧义的原因。

### 实例 3：T& 与 const T&、T& 与 T&&

```cpp run ok
template<class T> int a(T&)       { return 1; }
template<class T> int a(const T&) { return 2; }
template<class T> int b(T&)       { return 1; }
template<class T> int b(T&&)      { return 2; }
int main() {
    const int ci = 0;
    int i = 0;
    return (a(ci) - 2) + (b(i) - 1);   // a(ci) 调用 #2，b(i) 调用 #1
}
```

`a(ci)`：`a(T&)` 推导 `T = const int`，`a(const T&)` 推导 `T = int`，两者都绑定 `const int&`，转换序列相同。偏序：

| 方向 | A | P | 去引用、去顶层 cv 后 | ¶9 |
|---|---|---|---|---|
| `const T&` → `T&` | `const U&` | `T&` | `U` vs `T`：成功 | 两边原本都是引用、类型相同；A 更 cv 限定 → P（`T&`）**不**至少一样特化——即这一方向"不算数" |
| `T&` → `const T&` | `U&` | `const T&` | `U` vs `T`：成功 | P 更 cv 限定，A 不更 → 算数 |

结果：`const T&` 至少与 `T&` 一样特化，反之不成立——`a(const T&)` 更特化。直觉：`T&` 中的 `T` 可以吸收 `const`（`T = const U`），所以 `T&` 能匹配的形状包含 `const T&` 能匹配的形状；`const T&` 把 const 固定在模式里，模式更具体。

`b(i)`：`b(T&)` 推导 `T = int`，`b(T&&)` 推导 `T = int&`（转发引用），参数类型都是 `int&`。偏序中 ¶9.1：来自实参模板（变换后的 `T&` 版本）的是左值引用、来自形参模板（`T&&`）的不是，于是 `T&&` 不被认为至少一样特化；反向 `T&&`→`T&` 时，A 是右值引用，P 是左值引用，¶9.1 不阻止，成功。所以 `b(T&)` 更特化。这条规则就是为转发引用与左值引用重载共存设计的。

### 实例 4：只考虑有实参的参数（¶7）

¶7 是一个注：在调用语境中，推导只考虑有显式调用实参的参数，所以有些参数被忽略——**函数形参包、带默认实参的参数、省略号参数**。

```cpp run ok
template<class T> int f(T)            { return 1; }   // #1
template<class T> int f(T*, int = 1)  { return 2; }   // #2
template<class T> int g(T)            { return 3; }   // #3
template<class T> int g(T*, ...)      { return 4; }   // #4

int main() {
    int* ip = nullptr;
    return (f(ip) - 2) + (g(ip) - 4);   // 调用 #2 与 #4
}
```

`f(ip)` 只有一个实参，偏序只比较第一个参数：`T*` vs `T`，#2 更特化；第二个参数（带默认实参）被忽略。`g` 同理，省略号不参与。

但"忽略"也会导致歧义：

```cpp error
template<class T, class U> struct A { };

template<class T, class U> void f(U, A<U, T>* p = 0);   // #1
template<         class U> void f(U, A<U, U>* p = 0);   // #2
template<class T         > void g(T, T = T());          // #3
template<class T, class... U> void g(T, U...);          // #4

void h() {
    f<int>(42, (A<int, int>*)0);   // OK: 调用 #2
    f<int>(42);                    // error: 歧义
    g(42);                         // error: 歧义
}
```

- `f<int>(42, (A<int,int>*)0)`：两个实参，两个参数都参与偏序。#2 的变换 `(U, A<U,U>*)` 对 #1 推导：`U = U`，`A<U, T> ← A<U, U>` 得 `T = U`，成功；#1 的变换 `(U₂, A<U₂, U₁>*)` 对 #2：`U = U₂` 与 `A<U, U> ← A<U₂, U₁>` 要求 `U = U₁`，冲突，失败。#2 更特化。
- `f<int>(42)`：只有一个实参，偏序只比较第一个参数——两者都是 `U`（显式模板实参在偏序中不起作用，比较的是模板本身）。双向推导都成功（#1 的 `T` 只出现在没有实参的第二参数中，未在被比较的类型中使用，[temp.deduct.partial] ¶12 允许它没有值）。进入 ¶8：两者模板形参列表长度不同（2 vs 1），¶8.1 判定互不更特化 → 歧义。
- `g(42)`：#3 只看第一个参数 `T`（第二个有默认实参，忽略）；#4 只看 `T`（包 `U...` 推导为空，没有对应实参，忽略）。双向成功。¶11 的尾随包平局：要求 F 在 G 的尾随包处"没有对应参数"且 F 自己没有尾随包——#3 在该位置**有**参数（带默认实参的 `T`），不满足，歧义。

再看包的情况（例 5）：

```cpp run ok
template<class T, class... U> int f(T, U...) { return 1; }   // #1
template<class T>             int f(T)       { return 2; }   // #2
template<class T, class... U> int g(T*, U...) { return 3; }  // #3
template<class T>             int g(T)        { return 4; }  // #4

int main() {
    int i;
    return (f(&i) - 2) + (g(&i) - 3);   // 调用 #2 与 #3
}
```

- `f(&i)`：只比较第一个参数，`T` vs `T`，双向成功。¶11：#1 有尾随包，#2 在该处没有参数，且 #2 没有尾随包 → #2 更特化。
- `g(&i)`：`T*` vs `T`，#3 在推导上就更特化（实例 1 的结论），包的存在不影响。

### 实例 5：变参模板之间

[temp.deduct.partial] ¶8 的例子：

```cpp run ok
template<class... Args>           int f(Args...)        { return 1; }   // #1
template<class T1, class... Args> int f(T1, Args...)    { return 2; }   // #2
template<class T1, class T2>      int f(T1, T2)         { return 3; }   // #3

int main() {
    return (f() - 1) + (f(1, 2, 3) - 2) + (f(1, 2) - 3);
}
```

- `f()`：只有 #1 可行。
- `f(1, 2, 3)`：#1、#2 可行。#2 变换为 `(U₁, Us...)`，对 #1 的 `Args...`：P 是包，A 的每个剩余参数逐一与 `Args` 比较，成功。#1 变换为 `(Us...)`，对 #2 的 `(T1, Args...)`：A 来自函数形参包而 P（`T1`）不是包，失败（¶8 第一句）。#2 更特化。
- `f(1, 2)`：三个都可行；#3 变换 `(U₁, U₂)` 对 #2 成功、对 #1 成功；反向 #1、#2 的变换中含包，对 #3 的非包参数失败。#3 最特化。

一般结论：**非变参的比变参的更特化；带固定前缀参数的变参比纯变参更特化。** [temp.deduct.partial] ¶13 的注还指出：含包模板的偏序与包实际推导出的元素个数**无关**。

### 实例 6：未使用的模板形参（[temp.deduct.partial] ¶12）

```cpp run ok
template<class T> T c(int) { return 1; }            // #1
template<class T, class U> T c(U) { return 2; }     // #2
int main() { return c<int>(1) - 1; }                // 调用 #1
```

偏序只看函数参数类型（调用语境）：#1 的 `int` vs #2 的 `U`。#1 的变换中 `T` 被替换为合成类型，但 `T` 只出现在返回类型中，不参与比较；推导 #1 → #2：`U = int`，成功（#2 的 `T` 没有得到值，但它没有在比较的类型中被使用，¶12 允许）。反向 #2 → #1：`int ← U₂` 失败。#1 更特化。

## 约束作为平局裁决（¶8）

¶8 若对另一个模板的推导**双向都成功**，约束可以按以下方式考虑：

- ¶8.1 若两者的 *template-parameter-list*（包括为简写函数模板发明的模板形参）或函数参数列表**长度不同**，则互不更特化。
- ¶8.2 否则：
    - ¶8.2.1 若**恰好一个**模板是经由参数顺序反转的重写候选被考虑的：
        - ¶8.2.1.1 若任一模板的某些模板形参不能从其函数参数推导，则互不更特化；
        - ¶8.2.1.2 若对其模板形参列表**不存在或存在多于一种重排**，使得对应的模板形参等价且位置对应的函数参数类型相同，则互不更特化。
    - ¶8.2.2 否则（没有反转），若对应的模板形参**不等价**（[[temp.over.link]]），或位置对应的函数参数**类型不同**，则互不更特化。
- ¶8.3 否则，若偏序的语境是对**转换函数**的调用，而两模板的返回类型不同，则互不更特化。
- ¶8.4 否则，若一个模板比另一个**更受约束**（[[temp.constr.order]]），更受约束者更特化。
- ¶8.5 否则，互不更特化。

核心思想：**只有当两个模板"除约束外完全一样"时，才用约束来裁决**。为什么要求得这么严？因为约束的比较（包含关系）只有在两边的模板形参"指的是同一个东西"时才有意义。若 `template<std::integral T> void f(T)` 与 `template<class U> void f(U*)` 比较约束，`T` 和 `U` 根本不对应，说"前者更受约束"是没有意义的。

```cpp run ok
#include <concepts>
template<class T>         int d(T) { return 1; }
template<std::integral T> int d(T) { return 2; }   // 模板形参等价（忽略约束）、参数类型相同 → 比较约束

int main() { return (d(1) - 2) + (d(1.0) - 1); }    // d(1) 选更受约束的 #2；d(1.0) 只有 #1 可行
```

¶8.1 的反例——形参列表长度不同：

```cpp error
#include <concepts>
template<std::integral T> void r(T);
template<class T, class U = void> void r(T);   // 多了一个模板形参
void t() { r(1); }                             // error: 歧义——长度不同，不比较约束
```

双向推导都成功（`U` 未在比较的类型中使用），但两个模板的模板形参列表长度不同，¶8.1 直接判定互不更特化，即使第一个"看起来"更受约束。

### 简写函数模板与重排（¶8 的例 6）

```cpp run ok
template<typename> constexpr bool True = true;
template<typename T> concept C = True<T>;

void f(C auto&, auto&) = delete;               // #1：template<C T1, class T2> void f(T1&, T2&)
template<C Q> void f(Q&, C auto&);             // #2：template<C Q, C T2> void f(Q&, T2&)

void g(struct A* ap, struct B* bp) {
    f(*ap, *bp);   // OK: 选 #2
}
int main() { }
```

两个模板都是两个模板形参、两个函数参数，类型位置对应（`T1& ↔ Q&`，`T2& ↔ T2'&`），模板形参（忽略约束）等价。所以进入约束比较：#2 的约束 `C<Q> ∧ C<T2'>` 包含 #1 的 `C<T1>`，#2 更受约束，调用 #2（而不是被删除的 #1）。例中注释"can use different methods to produce template parameters"指的就是：一个用简写语法、一个用 *template-head*，并不妨碍它们对应。

### 反转候选的重排（¶8.2.1）

C++20 的 `==` 重写会把 `x == y` 也考虑为 `y == x`（反转候选，[[over.match.oper]]）。若参与偏序的两个模板中恰好一个是反转候选，它的参数顺序被反转（¶5），然后要找一个模板形参的**重排**使两边对应：

```cpp
template<typename> constexpr bool True = true;
template<typename T> concept C = True<T>;
template<typename T, typename U> struct X { };

template<typename T, C U, typename V> bool operator==(X<T, U>, V) = delete;   // #1
template<C T, C U, C V>               bool operator==(T, X<U, V>);            // #2

void h() {
    X<void*, int>{} == 0;   // 标准：OK——#2 作为反转候选被考虑，重排 [T, U, V] ↔ [U, V, T] 使两者对应，#2 更受约束
}
```

推演：`X<void*, int>{} == 0` 中，#1 正常匹配（`T = void*, U = int, V = int`）；#2 只能以反转形式 `0 == X<...>` 匹配（`T = int, U = void*, V = int`）。反转后 #2 的参数为 `(X<U, V>, T)`，与 #1 的 `(X<T, U>, V)` 的位置对应要求 #1 的 `[T, U, V]` 与 #2 的 `[U, V, T]` 一一对应——恰好一种重排，模板形参（忽略约束）等价。于是比较约束：#2 约束 `C<T> ∧ C<U> ∧ C<V>`（对应到 #1 是全部三个），#1 只约束 `C<U>`，#2 更受约束，选 #2。

!!! warning "编译器现状"
    截至写作时，本机 Clang 23 对上例报告"重载决议选中了被删除的 `operator==`"——即它没有实现 ¶8.2.1 的重排对应规则，选了 #1。按标准应选 #2。

### 转换函数的特殊情况（¶8.3）

对转换函数调用做偏序时，[temp.deduct.partial] ¶3.2 用的是**返回类型**；¶8.3 进一步要求：若两个转换函数模板的返回类型不同，不用约束裁决。原因：转换函数的"签名"本质上就是它的目标类型，返回类型不同就意味着它们不是"同一个东西的不同约束版本"。

## 部分特化如何复用本节

类模板/变量模板的部分特化偏序（[[temp.spec.partial.order]]）把每个部分特化改写成"单参数函数模板"，然后完全复用本节的算法（语境为"其他"，用整个函数类型）。所以本页的推演方法直接适用于部分特化。

## 实现视角

!!! impl "实现视角"
    - 编译器实现偏序时并不真的"生成"变换后的模板，而是用一组特殊的**不透明类型**（opaque/unique types）替换模板形参，然后复用推导引擎；"不满足任何具体匹配"正是不透明类型的性质。
    - 偏序的代价是候选数的平方：重载集中有 n 个可行的模板特化时，最坏需要 O(n²) 次双向推导。大型重载集（如某些格式化库、序列化库中按类型重载的几十个模板）会让这部分成为可测量的编译开销；用约束 + `if constexpr` 收敛到少数模板可以缓解。
    - Clang 的歧义诊断会列出每个候选及其推导结果（"candidate function [with T = …]"），但**不会**解释为什么偏序失败——这需要你自己按本页的表格推演。

## 历史与演进

!!! history "历史与演进"
    - **C++98**：偏序规则基本成型（变换、双向推导、引用与 cv 的处理）。
    - **C++11**：变参模板带来函数形参包的规则（[temp.deduct.partial] ¶8、¶11）；右值引用带来 ¶9.1 的左值引用平局规则；成员函数的 X(M) 考虑 *ref-qualifier*。
    - **C++20**：约束作为平局裁决（¶2、¶8），并要求模板"除约束外对应"；C++20 定稿前的修订细化了 ¶8 的对应性要求（模板形参等价、参数类型相同），使简写函数模板与普通写法的模板可以对应；`operator==` 的反转候选引入 ¶5 的参数反转与 ¶8.2.1 的重排规则。
    - **C++23**：显式对象参数（[[P0847R7]]）——它们不需要 ¶5 的隐式对象参数插入。
    - **C++26**：模板形参种类扩展（变量模板模板形参、概念模板形参），¶3 相应地为它们合成唯一的变量模板与概念。

## 陷阱

!!! pitfall "常见误解"
    - "偏序比较的是哪个特化'更匹配'实参"——不是。偏序比较的是**模板本身**（变换后的形参），与实际实参无关（除了"哪些参数有实参"这一点）。
    - "`f(T)` 与 `f(T&)` 能用偏序区分"——不能，按值和按引用的模板重载永远歧义。
    - "`f(T&&)` 比 `f(T&)` 更特化，因为它是'右值引用'"——相反：对左值实参，`f(T&)` 更特化（¶9.1）。
    - "带约束的版本总是胜出"——只有在两模板除约束外**完全对应**时才比较约束；形参列表长度不同、参数类型不同都会让约束失效（¶8.1、¶8.2.2）。
    - "默认实参会让模板更特化"——在调用语境中，没有对应实参的参数（含默认实参的参数）根本不参与偏序。

## 思考题

!!! question "思考题 1"
    下面的调用选哪个？

    ```cpp
    template<class T> void p(T, int);    // #1
    template<class T> void p(int, T);    // #2
    p(1, 1);
    ```

<details markdown="1">
<summary>答案</summary>

歧义。两个模板都可行（`T = int`），参数类型都是 `(int, int)`。偏序：#1 变换 `(U, int)` 对 #2 的 `(int, T)`：第一位 `int ← U` 失败。#2 变换 `(int, U)` 对 #1 的 `(T, int)`：第二位 `int ← U` 失败。双向失败，互不更特化。这是"偏"序的标准例子：每个模板在一个位置上比另一个更具体，没有一个全面胜出。
</details>

!!! question "思考题 2"
    为什么 `template<class T> void f(T*)` 与 `template<class T> void f(const T*)` 在 `int* p; f(p);` 时选前者，而在 `const int* q; f(q);` 时选后者？

<details markdown="1">
<summary>答案</summary>

`f(p)`：`f(const T*)` 推导 `T = int`，参数 `const int*`，需要从 `int*` 做限定转换；`f(T*)` 推导 `T = int`，参数 `int*`，恒等。两者都是精确匹配等级，但 [[over.ics.rank]] 中"一个是另一个的真子序列/限定转换更少"的规则使 `f(T*)` 的转换序列更好——偏序根本没有介入。

`f(q)`：`f(T*)` 推导 `T = const int`，`f(const T*)` 推导 `T = int`，参数类型都是 `const int*`，转换序列相同，进入偏序：`f(const T*)` 更特化（实例 1 第三、四行）。

教训：偏序是**最后的**平局裁决，许多看似"偏序"的选择其实在转换序列比较中就决定了。
</details>

!!! question "思考题 3"
    `template<class T> int f(T, T*)` 与 `template<class T, class U> int f(T, U*)` 对 `int i; f(i, &i)` 选哪个？若再加上约束 `template<class T, class U> requires std::same_as<T, U> int f(T, U*)` 替换第二个呢？

<details markdown="1">
<summary>答案</summary>

第一种情况：选第一个。第一个变换 `(V, V*)` 对第二个 `(T, U*)`：`T = V, U = V`，成功。第二个变换 `(V₁, V₂*)` 对第一个 `(T, T*)`：`T = V₁` 与 `T = V₂` 冲突，失败。第一个更特化。

第二种情况：推导部分完全不变（约束不参与推导），所以仍然选第一个——约束只在双向推导**都成功**时才被考虑。而且即使双向成功，两者模板形参列表长度不同（1 vs 2），¶8.1 也会让约束失效。约束不能把一个"结构上更一般"的模板变成"更特化"的。
</details>

!!! summary "小结"
    - 偏序：为每个模板合成唯一类型/值/模板得到变换后的模板，双向做 P/A 推导；单向成功者更特化。
    - 调用语境只比较有实参的参数（形参包、默认实参参数、省略号被忽略）；转换函数比较返回类型；其他语境比较整个函数类型。
    - 预处理：去引用、去顶层 cv；两边都是引用且类型相同时，左值引用胜过右值引用，cv 更多者更特化。
    - 包：A 来自包而 P 不是 → 失败；互相一样特化时，没有尾随包的胜过有尾随包的。
    - 成员函数插入对象参数 X(M)；反转候选的参数顺序反转。
    - 双向都成功时，仅当两模板除约束外完全对应（形参列表长度相同、形参等价、参数类型相同，反转时存在唯一重排）才比较约束，更受约束者更特化。
