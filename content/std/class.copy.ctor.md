复制构造函数和移动构造函数决定了"用一个同类型对象初始化另一个对象"时发生什么——按值传参、按值返回（复制消除不适用时）、`T b = a;`、`T b(std::move(a));`、容器扩容……它们是 C++ 值语义的核心。本节的结构与 [[class.copy.assign]] 几乎完全平行：

1. 什么样的构造函数**是**复制/移动构造函数（¶1–¶5）；
2. 何时**隐式声明**、形式是什么（¶6–¶9、¶11）；
3. 何时**定义为弃置**（¶10）；
4. 何时**平凡**（¶12）；
5. **隐式定义**做什么（¶13–¶16）。

总表与"合格"等概念见 [[special]]。

## 复制构造函数的识别（¶1）

¶1：类 `X` 的一个**非模板**构造函数是**复制构造函数**，若它的第一个形参类型是 `X&`、`const X&`、`volatile X&` 或 `const volatile X&`，并且没有其他形参，或其他形参都有默认实参。

标准例 1：`X::X(const X&)` 和 `X::X(X&, int = 1)` 都是复制构造函数。

```cpp run title="copy-ctor-forms.cpp" ok
struct X {
    X(int) { }
    X(const X&, int = 1) { }   // 复制构造函数（第二个形参有默认实参）
};

int main() {
    X a(1);        // 调用 X(int)
    X b(a, 0);     // 调用 X(const X&, int)
    X c = b;       // 调用 X(const X&, int)——作为复制构造函数
    (void)c;
}
```

**"非模板"是关键**：构造函数模板**永远不是**复制构造函数，即使它的某个特化的签名恰好是 `X(const X&)`。后果有二：

1. 构造函数模板**不会抑制**隐式复制构造函数的声明；
2. 但在重载决议中，模板特化**可以**比隐式复制构造函数更匹配，从而被选中（见下文"完美转发构造函数劫持复制"）。

## 移动构造函数的识别（¶2–¶3）

¶2：类 `X` 的一个非模板构造函数是**移动构造函数**，若它的第一个形参类型是 `X&&`、`const X&&`、`volatile X&&` 或 `const volatile X&&`，且没有其他形参或其他形参都有默认实参。

```cpp run title="move-ctor.cpp" ok
#include <cstdio>

struct Y {
    Y() { }
    Y(const Y&) { std::puts("copy"); }
    Y(Y&&)      { std::puts("move"); }
};

Y f(int) { return Y(); }

int main() {
    Y d(f(1));     // C++17 起：prvalue 直接初始化 d，两者都不调用（复制消除）
    Y e = d;       // copy：d 是左值
    Y g = static_cast<Y&&>(e);   // move：xvalue
    (void)g;
}
```

（标准例 2 对这一行的注释是"calls Y(Y&&)"，反映的是 C++17 之前的语义；C++17 起 `Y d(f(1));` 中 prvalue 直接初始化 `d`，既不调用复制也不调用移动，见 [[dcl.init]]。）

¶3 注 1：所有形式的复制/移动构造函数可以同时声明。`X(const X&&)` 合法但通常没有意义——不能从 `const` 对象"偷走"资源。它有一个罕见用途：`= delete` 掉它以禁止从 const 右值构造（`std::ref` 用 `void ref(const T&&) = delete;` 防止绑定临时量，原理相同）。

## 只有 `X&` 复制构造函数的类（¶4）

¶4 注 2：如果类 `X` **只有**形参为 `X&` 的复制构造函数，那么 `const X` 或 `volatile X` 类型的初始化器无法初始化 `cv X` 对象——`X&` 不能绑定到 `const` 左值。

这种类型在历史上真实存在：C++98 的 `std::auto_ptr` 的"复制"构造函数是 `auto_ptr(auto_ptr&)`，因为它要修改源对象（转移所有权）。这正是 C++11 引入移动语义要解决的问题。

## 不能有 `X(X)` 形式的构造函数（¶5）

¶5：若类 `X` 的构造函数声明的第一个形参是 `cv X`（**按值**），且没有其他形参或其他形参都有默认实参，则该声明**非良构**。理由：按值传参本身就需要复制构造——`X(X)` 要调用自己才能接收实参，无限递归。

并且，**成员函数模板永远不会被实例化来产生这样的构造函数签名**。标准例 5：

```cpp run title="no-X-of-X.cpp" ok
struct S {
    template<typename T> S(T) { }
    S() { }
};

S g;

int main() {
    S a(g);     // 不会实例化 S::S<S>(S)；使用隐式声明的复制构造函数
    (void)a;
}
```

如果没有这条规则，`S a(g);` 中模板推导出 `T = S`，得到 `S(S)` 签名——按值接收 `S` 又需要复制 `g`，又会选中这个模板……

```cpp title="X-of-X.cpp" error
struct Bad {
    Bad(Bad);   // error: 复制构造函数必须按引用接收第一个形参
};
```

## 隐式声明的复制构造函数（¶6–¶7）

¶6：若类没有用户声明的复制构造函数，且不是匿名联合体，则**隐式声明**一个非 explicit 的复制构造函数。

- 若类定义声明了**移动构造函数或移动赋值运算符**，隐式声明的复制构造函数被**定义为弃置**；
- 否则它是**预置的**（[[dcl.fct.def]]）。若类有用户声明的**复制赋值运算符**或**析构函数**，这种预置是**弃用的**（[[depr.impldec]]）。

¶7：隐式声明的复制构造函数的形式是 `X::X(const X&)`，前提是每个类类型（或其数组）的潜在构造子对象 `M` 都有一个第一形参为 `const M&` 或 `const volatile M&` 的复制构造函数；否则形式是 `X::X(X&)`。脚注 82：这意味着隐式复制构造函数的引用形参**不能绑定到 `volatile` 左值**（[[diff.class]]）。

```cpp title="implicit-copy-form.cpp" error
struct M { M() { } M(M&) { } };   // 只有非 const 形参的复制构造函数
struct X { M m; };                // 隐式复制构造函数形如 X(X&)

X x1;
const X cx{};
X x2 = x1;      // OK
X x3 = cx;      // error: X(X&) 不能接收 const X
```

为什么要"降级"为 `X(X&)` 而不是直接删除？因为逐成员复制 `m` 需要调用 `M(M&)`，这要求源对象非 const——降级是"能做到的最好的事"，保留了从非 const 左值复制的能力。

!!! lawyer "volatile 对象不能被隐式复制"
    `volatile X vx; X y = vx;` 非良构：隐式复制构造函数的形参是 `const X&`，不能绑定 `volatile` 左值。如果确实需要，自己声明 `X(const volatile X&)`。C 中结构体可以从 `volatile` 对象复制，这是 [[diff.class]] 列出的 C/C++ 不兼容之一。

## 隐式声明的移动构造函数（¶8–¶9）

¶8：若类 `X` 没有用户声明的移动构造函数，则**当且仅当**以下全部成立时，隐式声明一个非 explicit 的、预置的移动构造函数：

- ¶8.1 `X` 不是匿名联合体；
- ¶8.2 没有用户声明的复制构造函数；
- ¶8.3 没有用户声明的复制赋值运算符；
- ¶8.4 没有用户声明的移动赋值运算符；
- ¶8.5 没有用户声明的析构函数。

注 3：移动构造函数没有被隐式声明也没有显式提供时，原本会调用移动构造函数的表达式可能改为调用复制构造函数（`const X&` 能绑定右值）。

¶9：隐式声明的移动构造函数的形式是 `X::X(X&&)`。

为什么条件这么严？用户声明了复制、赋值或析构中的任何一个，说明这个类有**非平凡的资源语义**——编译器生成的逐成员移动很可能是错的（例如析构函数会 `delete` 一个原始指针成员，逐成员"移动"指针后源和目标会重复释放）。所以 C++11 选择"保守"：只有在用户什么都没自定义时才生成移动操作；否则退回复制，**慢但正确**。

## 访问性与弃置条件（¶10–¶11）

¶10 第一句：隐式声明的复制/移动构造函数是类的 **inline public** 成员。

类 `X` 的**预置**复制/移动构造函数在 `X` 有以下情况时被**定义为弃置**（[[dcl.fct.def.delete]]）：

- ¶10.1 某个潜在构造子对象是类型 `M`（或其多维数组），为找到 `M` 的对应构造函数所做的重载决议**没有得到可用候选**——或者对于**变体成员**，选中了一个**非平凡**函数；
- ¶10.2 某个类类型 `M`（或其多维数组）的潜在构造子对象，其析构函数被删除或从预置构造函数中不可访问；
- ¶10.3 对于复制构造函数：有**右值引用类型**的非静态数据成员。

逐条解释：

- ¶10.1 的主体很直观：成员不能复制/移动，整体就不能。"对于变体成员，选中非平凡函数"是联合体规则：联合体不知道哪个成员活跃，只能按字节复制（¶16），所以若某个变体成员的复制构造函数非平凡（如 `std::string`），联合体的复制构造函数就被删除。
- ¶10.2 与默认构造函数的 ¶2.4 理由相同：构造中途异常需要析构已构造的子对象。
- ¶10.3：复制构造函数接收 `const X&`，从中读出的右值引用成员 `x.r` 是**左值**，不能用来初始化新对象的右值引用成员——除非显式 `static_cast`，而那等于"复制"出了一个对同一对象的第二个右值引用，违背右值引用"唯一所有"的意图。移动构造函数则通过 ¶15.2 的 `static_cast<T&&>(x.m)` 处理。

```cpp title="copy-ctor-deleted.cpp" error
#include <string>
#include <utility>

union U {
    std::string s;
    int i;
    U() : i(0) { }
    ~U() { }
};
U u1;
U u2 = u1;               // error: 变体成员 s 的复制构造函数非平凡 ⇒ U 的复制构造函数被删除（¶10.1）

struct RR { int&& r; };
int g = 1;
RR r1{std::move(g)};
RR r2 = r1;              // error: 有右值引用成员 ⇒ 复制构造函数被删除（¶10.3）
RR r3 = std::move(r1);   // OK: 移动构造函数用 static_cast<int&&>(r1.r) 初始化 r
```

注 4：**被定义为弃置的预置移动构造函数会被重载决议忽略**（[[over.match]]、[[over.over]]）。否则它会干扰"本可以用复制构造函数完成"的右值初始化。示例见 [[special]] 的 `deleted-move-ignored.cpp`。

¶11 注 5：派生类 `C` 中指名基类构造函数的 *using-declaration*（继承构造函数）**永远不会抑制** `C` 的复制/移动构造函数的隐式声明——即使基类的那个构造函数如果声明为 `C` 的成员会是复制/移动构造函数。而且，从基类继承来的、形参为基类引用的构造函数**不会**被用来复制派生类对象（[[over.match.funcs]] 会排除这种候选）。

## 平凡的复制/移动构造函数（¶12）

¶12：类 `X` 的复制/移动构造函数是**平凡的**，若它**不是用户提供的**，并且：

- ¶12.1 `X` 没有虚函数和虚基类；
- ¶12.2 为复制/移动每个**直接基类**子对象而选中的构造函数，是**该基类的直接成员**并且是平凡的；
- ¶12.3 对 `X` 的每个类类型（或其数组）非静态数据成员，为复制/移动它而选中的构造函数是平凡的。

否则是**非平凡的**。

¶12.2 中"是该基类的直接成员"排除了一种怪异情况：为复制基类子对象而选中的构造函数是基类从**它自己的**基类继承来的构造函数（经由 *using-declaration*）——那不是基类真正的复制构造函数，不能据此认定平凡。

注意"**选中的**"：判断平凡性时看的是复制/移动该子对象时重载决议**实际选中**的那个构造函数，而不是"成员类型有没有某个平凡的复制构造函数"。例如成员类型 `M` 同时有平凡的 `M(const M&)`（隐式或首次声明预置）和用户提供的 `M(M&&)`，那么 `X` 的复制构造函数（复制 `m` 时选中 `M(const M&)`）可以是平凡的，而 `X` 的移动构造函数（移动 `m` 时选中 `M(M&&)`）是非平凡的。配合 C++20 的约束，同一个成员类型甚至可以让外层类在不同模板实参下平凡或不平凡。

```cpp run title="trivial-copy.cpp" ok
#include <type_traits>
#include <string>

struct A { int x; std::string* p; };               // 平凡
struct B { std::string s; };                       // 非平凡：成员 s 的复制构造函数非平凡
struct C { virtual void f() { } };                 // 非平凡：有虚函数（需要设置 vptr）
struct D { D(const D&) = default; int x; };        // 平凡：首次声明预置
struct E { E(const E&); int x; };
E::E(const E&) = default;                          // 非平凡：类外预置 ⇒ 用户提供

static_assert( std::is_trivially_copy_constructible_v<A>);
static_assert(!std::is_trivially_copy_constructible_v<B>);
static_assert(!std::is_trivially_copy_constructible_v<C>);
static_assert( std::is_trivially_copy_constructible_v<D>);
static_assert(!std::is_trivially_copy_constructible_v<E>);
int main() { }
```

为什么虚函数使复制非平凡？考虑 `Derived d; Base b = d;`（切片）：如果 `Base` 的复制构造函数按字节复制，`b` 的 vptr 会指向 `Derived` 的虚表——`b` 的动态类型就错了。所以复制构造函数必须**把 vptr 设置为 `Base` 的虚表**，而不是从源复制。

## 隐式定义（¶13–¶16）

### 何时定义、constexpr（¶13–¶14）

¶13 注 6：即使实现**消除**了对复制/移动构造函数的 odr-use（复制消除，[[class.copy.elision]]），它**仍然被隐式定义**。所以若隐式定义会非良构，复制消除救不了你。

¶13 第二句：**隐式定义的复制/移动构造函数是 `constexpr` 的**。

¶14：在预置的复制/移动构造函数被隐式定义之前，其潜在构造子对象的所有非用户提供的复制/移动构造函数先被隐式定义。注 7：隐式声明的复制/移动构造函数有隐含的异常说明（[[except.spec]]）：若它调用的所有构造函数都不抛出，它就是 `noexcept` 的。

!!! tip "为什么 `noexcept` 的移动构造函数如此重要"
    `std::vector` 扩容时，只有当元素的移动构造函数是 `noexcept` 的（或者元素不可复制）才会移动元素；否则为了强异常安全保证，它会**复制**。隐式定义的移动构造函数自动推导 `noexcept`；自己写移动构造函数时，务必标上 `noexcept`。

### 非联合体：逐成员复制/移动（¶15）

¶15：非联合体类 `X` 的隐式定义的复制/移动构造函数执行其基类与成员的**逐成员复制/移动**。注 8：**非静态数据成员的默认成员初始化器被忽略**。初始化顺序与用户定义构造函数中基类和成员的初始化顺序相同（[[class.base.init]]：先虚基类，再直接基类按声明顺序，再成员按声明顺序）。

设 `x` 是构造函数的形参，或（对移动构造函数）指代该形参的 xvalue。每个基类或非静态数据成员按适合其类型的方式复制/移动：

- ¶15.1 若成员是**数组**，每个元素用 `x` 中对应的子对象**直接初始化**；
- ¶15.2 若成员 `m` 是**右值引用类型** `T&&`，用 `static_cast<T&&>(x.m)` 直接初始化；
- ¶15.3 否则，基类或成员用 `x` 中对应的基类或成员**直接初始化**。

虚基类子对象只被隐式定义的复制/移动构造函数初始化一次（[[class.base.init]]）。

换句话说，隐式移动构造函数**大致等价于**：

```cpp
X(X&& x) : Base(static_cast<Base&&>(x)), m1(static_cast<X&&>(x).m1), m2(static_cast<X&&>(x).m2) { }
```

注意几点：

1. **数组成员被逐元素复制**——这是复制数组的唯一"隐式"方式（数组本身不能赋值或复制初始化），所以 `struct { int a[10]; }` 可以整体复制；
2. **引用成员**被"复制"意味着新对象的引用绑定到同一个对象（¶15.3 中用 `x.r` 直接初始化 `r`）；
3. "**默认成员初始化器被忽略**"——复制出来的对象的成员值来自源对象，而不是初始化器。

```cpp run title="memberwise.cpp" ok
#include <string>
#include <utility>
#include <cassert>

struct X {
    int arr[3];
    std::string s;
    int& ref;
    int counter = 100;   // 复制时被忽略
};

int main() {
    int target = 7;
    X a{{1, 2, 3}, "hello", target, 5};
    X b = a;                       // 逐成员复制：数组逐元素、string 复制、引用绑定同一对象
    assert(b.arr[2] == 3 && b.s == "hello" && &b.ref == &target && b.counter == 5);

    X c = std::move(a);            // 逐成员移动：s 被移走
    assert(c.s == "hello");
    return 0;
}
```

### 联合体：复制对象表示（¶16）

¶16：联合体 `X` 的隐式定义的复制/移动构造函数**复制 `X` 的对象表示**（[[basic.types.general]]，即按字节复制）。并且：对于源对象中嵌套的（[[intro.object]]）每个对象，在目标中识别（若是子对象）或**创建**（否则）一个对应的嵌套对象 *o*，*o* 的生命周期在复制之前开始。

这是 C++20 起对象模型精确化的一部分：联合体按字节复制时，**活跃成员也随之"复制"过去**——目标联合体中对应的成员对象开始生命周期，成为活跃成员。否则按字节复制之后，目标联合体中"没有任何活跃成员"，读任何成员都是 UB。

```cpp run title="union-copy.cpp" ok
union U { int i; float f; };

int main() {
    U a;
    a.f = 1.5f;          // f 是活跃成员
    U b = a;             // 按字节复制；b.f 成为 b 的活跃成员（¶16）
    return b.f == 1.5f ? 0 : 1;   // OK
}
```

（只有当所有变体成员的复制构造函数都平凡时，联合体才有可用的隐式复制构造函数——见 ¶10.1。）

## 完美转发构造函数劫持复制

这是 ¶1"模板永远不是复制构造函数"最著名的后果。考虑一个带转发引用构造函数模板的类：

```cpp run title="forwarding-hijack.cpp" ok
#include <cstdio>
#include <string>
#include <utility>

struct P {
    std::string s;
    P(const char* p) : s(p) { }
    template<class T>
    P(T&&) { std::puts("template"); }           // 转发引用构造函数
    P(const P& o) : s(o.s) { std::puts("copy"); }
};

int main() {
    P a("x");
    P b = a;          // 打印 "template"！T = P&，P(P&) 比 P(const P&) 匹配更好（无需加 const）
    const P c("y");
    P d = c;          // 打印 "copy"：对 const 左值，两者同样好，非模板优先
    (void)b; (void)d;
}
```

对非 const 左值 `a`，模板推导出 `P(P&)`，它比 `P(const P&)` 少一次限定转换，重载决议选中模板。如果模板体里写的是 `s(std::forward<T>(t))`，就会尝试用 `P&` 初始化 `std::string`——编译错误；更糟的情况下它能编译但语义错误。修复方法是**约束**模板：

```cpp
template<class T>
    requires (!std::is_same_v<std::remove_cvref_t<T>, P>)
P(T&& t);
```

（C++20 之前用 `std::enable_if_t<!std::is_same_v<std::decay_t<T>, P>, int> = 0`。）

## 实现视角

!!! impl "平凡复制 = memcpy；非平凡复制与 ABI"
    平凡的复制/移动构造函数被编译为 `memcpy`（或寄存器移动），`std::vector<Trivial>` 的复制、扩容直接调用 `memmove`。Itanium ABI 规定：若类有**非平凡**的复制构造函数、移动构造函数或析构函数（或复制、移动构造函数全部被删除），则按值传递时**不能放在寄存器中**，调用方要在栈上构造临时对象并传递其地址。所以给一个小类加上用户提供的复制构造函数，会改变它的调用约定——这是 ABI 破坏性变更。

!!! impl "Clang 的 `[[clang::trivial_abi]]`"
    Clang 提供 `[[clang::trivial_abi]]` 属性，允许有非平凡复制/析构的类（如 `unique_ptr` 风格的智能指针）仍按寄存器传递。代价是析构的时机变化（在被调用方析构），不影响标准语义上的"平凡性"。

## 历史与演进

!!! history "历史与演进"
    - **C++98**：只有复制构造函数；隐式声明规则只看"是否有用户声明的复制构造函数"；`X(X&)` 降级规则已存在（为 `auto_ptr` 一类类型）。
    - **C++11**：**移动构造函数**；隐式移动的严格条件；声明移动操作使隐式复制被删除；有用户声明的复制赋值或析构时隐式复制被弃用；被删除的预置移动构造函数被重载决议忽略（这条在 C++11 发布后不久通过核心语言 issue 加入）。
    - **C++17**：保证复制消除——prvalue 初始化同类型对象不再需要可用的复制/移动构造函数。
    - **C++20**：联合体隐式复制时创建活跃成员对象（隐式对象创建，[[P0593R6]]）；平凡性用"选中的"函数判断，配合条件平凡的特殊成员函数。
    - **C++23**：隐式定义的复制/移动构造函数无条件 `constexpr`。

## 陷阱

!!! pitfall "只写了析构函数，移动悄悄变成复制"
    见 [[special]]。所有"自定义了析构函数"的类都应检查是否需要显式 `= default` 移动操作。

!!! pitfall "移动构造函数忘了 `noexcept`"
    `std::vector` 扩容会退回复制（若可复制），性能骤降且很难察觉。

!!! pitfall "转发引用构造函数劫持复制"
    见上节。所有形如 `template<class T> X(T&&)` 的构造函数都应排除 `X` 自身（及其派生类）。

!!! pitfall "移动后的源对象状态"
    隐式移动构造函数对标量成员是**复制**（`int`、原始指针移动后源对象中的值不变）。若类用原始指针表示所有权，隐式移动会导致两个对象指向同一资源——这正是为什么这类类必须自己写移动操作（并把源指针置空），或者改用 `std::unique_ptr` 成员（Rule of zero）。

## 思考题

!!! question "思考题 1"
    ```cpp
    struct A {
        A() = default;
        A(A&) = default;
    };
    struct B { A a; };
    const B cb{};
    B b2 = cb;   // ?
    ```
    最后一行合法吗？`B` 的隐式复制构造函数是什么形式？

<details markdown="1">
<summary>答案</summary>

`A` 只有一个复制构造函数 `A(A&)`（用户声明，首次声明处预置——[[dcl.fct.def.default#2]]¶2.4 允许把 `const A&` 改成 `A&`）。按 ¶7，`B` 的成员 `a` 没有形参为 `const A&` 的复制构造函数，所以 `B` 的隐式复制构造函数是 `B(B&)`。`B b2 = cb;` 中 `cb` 是 `const B`，`B&` 不能绑定——**非良构**。另外 `A` 声明了复制构造函数，所以 `A` 没有隐式移动构造函数，也没有隐式默认构造函数——这里显式预置了默认构造函数，所以 `B` 能默认构造。
</details>

!!! question "思考题 2"
    为什么 ¶13 要规定"即使复制被消除，复制构造函数也会被隐式定义"？

<details markdown="1">
<summary>答案</summary>

为了让**程序的良构性不依赖于实现是否进行可选的复制消除**。C++17 之前，几乎所有复制消除都是可选的（NRVO 至今仍是可选的）。如果"消除了就不定义"，那么一个隐式定义会非良构的复制构造函数（比如成员的复制构造函数不可访问——在 C++11 前这会让隐式定义非良构）在一个编译器上能通过、在另一个上报错。规定"无论如何都隐式定义"，诊断就与优化无关了。
</details>

!!! question "思考题 3"
    `struct S { template<class T> S(const T&); };` 中 `S s2 = s1;` 调用哪个构造函数？

<details markdown="1">
<summary>答案</summary>

调用**隐式声明的复制构造函数** `S(const S&)`。模板不是复制构造函数，不抑制隐式声明；重载决议中，模板特化 `S(const S&)`（`T = S`）与隐式复制构造函数签名完全相同，此时非模板优先（[[over.match.best]]）。若是 `template<class T> S(T&)` 而 `s1` 是非 const 左值，推导出 `S(S&)`，比 `S(const S&)` 更匹配，模板会被选中。
</details>

## 小结

| 主题 | 复制构造函数 | 移动构造函数 |
|---|---|---|
| 识别 | 非模板；首形参 `cv X&`；其余有默认实参 | 非模板；首形参 `cv X&&`；其余有默认实参 |
| 隐式声明 | 没有用户声明的复制构造时 | 没有用户声明的复制构造、复制赋值、移动赋值、析构时 |
| 形式 | `X(const X&)`，若某子对象只能 `M(M&)` 则 `X(X&)` | `X(X&&)` |
| 弃置 | 声明了移动操作；子对象不可复制；子对象析构不可用；有右值引用成员；变体成员复制非平凡 | 子对象不可移动；子对象析构不可用；变体成员非平凡（弃置后被重载决议忽略） |
| 平凡 | 非用户提供 + 无虚 + 基类与成员选中的构造函数平凡 | 同左 |
| 隐式定义 | 逐成员直接初始化（数组逐元素）；忽略默认成员初始化器；`constexpr` | 同左，源为 xvalue；右值引用成员用 `static_cast` |
| 联合体 | 复制对象表示，并在目标中创建对应的活跃成员对象 | 同左 |
