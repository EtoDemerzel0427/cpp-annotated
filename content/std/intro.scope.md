!!! tldr
    - C++ 标准直接约束的对象是**实现**（implementation，即编译器、标准库与运行环境的统称），而非编写代码的程序员。
    - 为了界定一套实现怎样才算支持了 C++，标准必须先把这门语言的语法、语义和标准库完整定义出来。
    - 正文中针对代码的各项规则，最终都会换算为对实现的要求；所谓未定义行为，本质上就是标准对这样的程序不再向实现提出任何要求。

## 标准规定的是什么（¶1）

¶1 C++ 是一门通用编程语言，但本标准直接约束的对象并不是程序员，而是 C++ 的**实现**（implementation，即编译器、标准库与运行环境的统称）。作为一份面向实现者的技术规范，它对实现提出的首要要求就是完整支持 C++ 语言；为了界定怎样才算支持这门语言，本标准才随之在正文中给出了 C++ 的完整定义。至于对实现的其他要求（如输出诊断信息、提供说明文档），以及对上述首要要求的豁免与放宽，则散见于后续各章节。

!!! std
    This document specifies requirements for implementations of C++, which is a general-purpose programming language. The first such requirement is that an implementation implements the language, so this document also defines C++.

理解标准只约束实现而不直接约束程序员，是读懂后续条文的前提。以有符号整数溢出为例，标准并不会禁止程序员写出溢出的代码，而是规定一旦发生溢出，本标准不再对实现施加任何要求，这正是**未定义行为**（undefined behavior，[[defns.undefined]]）的本意。既然标准放弃了约束，优化器就可以直接假设溢出不会发生并据此消去分支，而 sanitizer 也可以在运行时拦截报错；两种做法都符合标准。

当然，为了行文直观，正文里仍常从代码的角度表述规则，比如要求程序只能有一个 `main` 函数。[[intro.compliance]] ¶2 专门规定了如何把这类针对程序的条款换算为实现的义务：不违反任何规则的程序，实现必须接受并正确执行（超出实现限制时除外）；违反了可诊断规则的程序，实现必须发出诊断信息；违反了注明“不要求诊断”的规则时，标准对这个程序不再提出任何要求。未定义行为则由各条款分别规定。

至于条文末尾提到的放宽条件，指的是实现在哪些情况下不必字面兑现完整支持整门语言的要求，具体规则集中在 [[intro.compliance]]：

- **实现限制**（implementation limits）：物理机器的资源有限，当程序规模过大或语法结构嵌套过深时，实现可以拒绝编译；
- **有条件支持**（conditionally-supported）：部分特性允许实现不予支持，只需在文档中注明即可；
- **独立实现**（freestanding implementation）：面向无操作系统环境（如内核与嵌入式设备）的实现，只需提供标准库的一个子集；
- **as-if 规则**：实现不必机械照搬标准抽象机的每一步操作，只要最终产生的可观察行为一致，就可以自由变换和优化代码。
