**聚合**（aggregate）是 C++ 从 C 继承来的"没有构造函数的数据包"：数组，以及没有用户构造函数、成员全公开、没有虚函数的类。它最大的特点是**不经过构造函数**——聚合初始化直接把花括号里的初始化器一个一个地分配给各个元素：

```cpp
struct Point { int x, y; };
Point p = {1, 2};            // 不调用任何构造函数，p.x = 1, p.y = 2
int a[3] = {1, 2};           // a[2] 从 {} 初始化，即 0
```

这看似简单，但本节要回答一系列细节问题：哪些类算聚合（这个定义在 C++11、14、17、20 **每个版本都改过**）？什么是元素？初始化器少了怎么办？嵌套的子聚合可不可以省略花括号？指派初始化器 `.x = 1` 有哪些限制？联合、匿名联合、未知边界数组、引用成员各自怎么处理？

聚合初始化的**入口**有两个：花括号（经由 [[dcl.init.list]] ¶3.4）和圆括号（[[dcl.init]] ¶15.6.2.2，C++20）。本节主要描述花括号形式；圆括号形式的差异见 [[dcl.init#15]]。

## 聚合的定义（¶1）

¶1 **聚合**是数组，或满足以下条件的类：

- ¶1.1 没有**用户声明的**或**继承的**构造函数（[[class.ctor]]）；
- ¶1.2 没有 private 或 protected 的**直接**非静态数据成员；
- ¶1.3 没有 private 或 protected 的直接基类；
- ¶1.4 没有虚函数，没有虚基类。

为什么是这四条？聚合初始化的模型是"从外部逐个初始化每个元素"，所以：

- 有构造函数（¶1.1）说明类的作者希望**控制**初始化过程，绕过构造函数会破坏不变式；
- 私有成员/基类（¶1.2–¶1.3）在外部无法访问，无法"从外部逐个初始化"；
- 虚函数/虚基类（¶1.4）需要构造函数设置 vptr / 虚基偏移，这是只有构造过程才能完成的工作。

注意几个**允许**的东西：聚合可以有基类（公开、非虚，C++17 起）、默认成员初始化器（C++14 起）、成员函数、静态成员、私有的**静态**数据成员、私有成员函数、用户声明的析构函数和赋值运算符；元素类型本身可以是有构造函数的类（`struct S { std::string s; int n; };` 是聚合）。

注 1：聚合初始化**不能**访问基类的 protected/private 成员，包括构造函数：

```cpp
struct B { protected: B() = default; int x; };
struct D : B { };       // 聚合：公开基类，无构造函数
D d1;                   // OK: 默认初始化，调用 D 的隐式默认构造函数，后者可以访问 B 的 protected 构造函数
D d2{};                 // error: 聚合初始化，在 d2 的声明处（类外）从 {} 初始化 B 元素，B() 不可访问
```

这是 C++17 允许聚合有基类之后出现的一个反直觉现象：`D d;` 合法而 `D d{};` 非良构。

### 聚合定义的演变

| 标准 | 构造函数 | 默认成员初始化器 | 基类 | 其他 |
|---|---|---|---|---|
| C++98/03 | 不能有**用户声明的**构造函数 | （不存在该特性） | 不允许 | 无私有/保护非静态数据成员，无虚函数 |
| C++11 | 不能有**用户提供的**构造函数（`= default`/`= delete` 不算） | **不允许**（有则非聚合） | 不允许 | 同上 |
| C++14 | 同 C++11 | **允许**（[[N3653]]） | 不允许 | 同上 |
| C++17 | 不能有用户提供的、`explicit` 的或继承的构造函数 | 允许 | **公开非虚基类**（[[P0017R1]]） | 同上 |
| C++20 | 不能有**用户声明的**或继承的构造函数（[[P1008R1]]） | 允许 | 公开非虚基类 | 同上 |

C++11 把条件从"用户声明"放宽为"用户提供"，本意是让 `= default` 的类仍是聚合。但这导致了一个著名的漏洞：

```cpp
struct NoDefault { NoDefault() = delete; int x; };
NoDefault a{};          // C++11–17: OK！聚合初始化绕过了被删除的构造函数
                        // C++20: error: NoDefault 不再是聚合，{} → 值初始化 → 调用被删除的构造函数

struct Priv { private: Priv() = default; };
Priv b{};               // C++11–17: OK（私有构造函数被绕过）；C++20: error
```

C++20 的 [[P1008R1]] 把条件改回"用户声明"，堵上了漏洞，代价是一个破坏性变化：C++17 中 `struct S { S() = default; int i; }; S s{1};` 合法，C++20 中非良构（`S` 不再是聚合，没有接受 `int` 的构造函数）。

```cpp run ok std=c++20
#include <type_traits>
struct A { int x; int y = 2; };                // C++14 起是聚合
struct Base { int b; };
struct D : Base { int d; };                    // C++17 起是聚合
struct Del { Del() = delete; int x; };         // C++20 起不是聚合
static_assert(std::is_aggregate_v<A>);
static_assert(std::is_aggregate_v<D>);
static_assert(!std::is_aggregate_v<Del>);
D d{{1}, 2};                                   // d.b == 1, d.d == 2
int main() {}
```

## 元素与关联元素（¶2–¶3）

¶2 聚合的**元素**（elements）：

- ¶2.1 数组：各数组元素，下标递增顺序；
- ¶2.2 类：先是**直接基类**（声明顺序），然后是不属于匿名联合成员的**直接非静态数据成员**（声明顺序）。

¶12（注）进一步说明：静态数据成员、匿名联合成员的非静态数据成员、**无名位域**都不是元素。匿名联合本身（作为一个整体的匿名联合成员）则是一个元素。

```cpp
struct A {
  int i;
  static int s;     // 不是元素
  int j;
  int : 17;         // 无名位域，不是元素
  int k;
} a = { 1, 2, 3 };  // i = 1, j = 2, k = 3
```

¶3 成员 M 在聚合 T 中的**关联元素**（associated element）：若 M 本身是 T 的元素，就是 M；否则是 T 中**包含** M 的那个元素。例如 `struct B : A { int b1; union { double b2; }; };` 中，`A::a1` 的关联元素是基类子对象 `A`，`B::b2` 的关联元素是包含它的匿名联合。这一概念服务于指派初始化器：`.a1 = 1` 实际上是在初始化元素 `A`。

## 显式初始化的元素（¶4）

¶4 聚合被初始化器列表初始化时，列表中的元素作为聚合元素的初始化器。首先确定哪些元素是**显式初始化的元素**（explicitly initialized elements）：

**¶4.1 指派初始化器列表。** 聚合必须是**类**（数组不能用指派初始化器，这与 C 不同）。对每个指派符 `.id`，在 C 中查找 `id`（[[class.member.lookup]]），查找集必须恰好是：

- ¶4.1.1 一个非静态数据成员的声明，且
- ¶4.1.2 只有一个子对象，其类型是 C 的**聚合基**（aggregate base）：C 本身，或聚合基的直接基类（递归）。

该成员即被"指派"。列表开头的普通（非指派）子句只能对应**直接基类子对象**。显式初始化的元素就是各被指派成员的关联元素。

{{c++26}} 允许通过指派符初始化**基类的成员**（`.a1` 找到基类 `A` 的成员）以及"普通子句初始化基类 + 指派子句初始化成员"的混合写法，是当前草案相对 C++20/23 的扩展。在 C++23 及以前，指派符只能命名聚合**自身的直接**非静态数据成员，基类只能通过非指派形式初始化，而且同一列表中不能混用两种形式。

```cpp
struct A { int a1, a2; };
struct B : A { int b; };
struct C : A { int a1; };

A v0 = A{1, .a2 = 2};             // error: 普通子句只能对应基类，而 A 没有基类
B v1 = B{.a1 = 1, .b = 2};        // 当前草案：显式初始化的元素是 [A, B::b]
B v3 = B{A{1, 2}, .b = 3};        // 当前草案：同上
B v4 = B{A{}, .a2 = 1, .b = 3};   // error: A 被以两种方式初始化
C v5 = C{.a1 = 4};                // C::a1 隐藏了 A::a1；显式初始化的元素是 [C::a1]
```

!!! impl
    截至写作时，Clang 尚未实现基类成员的指派初始化：`B{.a1 = 1, .b = 2}` 会报"field designator 'a1' does not refer to any field"。上例中 `v1`、`v3` 在 C++23 规则下也是非良构的。另外，Clang 把 `A{1, .a2 = 2}` 这类混用当作 C99 扩展接受（仅 `-Wc99-designator` 警告），加 `-pedantic-errors` 才报错。

**¶4.2 普通初始化器列表。** 列表中某个子句**归属**（appertain，见 ¶15）于某元素或其子对象，则该元素被显式初始化。

**¶4.3** 其他元素都不是显式初始化的。注 2：`{}` 不显式初始化任何元素。

若某元素同时经由普通列表和指派列表被显式初始化，非良构。

## 显式初始化的元素如何初始化（¶5）

¶5 对每个显式初始化的元素：

- ¶5.1 **匿名联合**成员、经由指派列表初始化：用 `{ D }` 初始化它，D 是关联元素为该匿名联合的那个指派子句；这样的子句只能有一个。

  ```cpp
  struct C {
    union { int a; const char* p; };
    int x;
  } c = { .a = 1, .x = 3 };     // c.a == 1, c.x == 3
  ```

- ¶5.2 经由指派列表初始化：
    - ¶5.2.1 元素是**直接非静态数据成员**：用对应子句的 *brace-or-equal-initializer* 初始化。若是 `= expr` 形式且需要**窄化转换**，非良构（注意：`= expr` 本身是拷贝初始化，普通的拷贝初始化允许窄化，这里特意禁止）。注 3：形式决定是拷贝初始化（`.m = e`）还是直接初始化（`.m{e}`）。
    - ¶5.2.2 元素是**基类子对象** B：用所有关联元素为 B 的指派子句（按顺序）组成的花括号指派列表**拷贝初始化** B——递归地处理多层基类。
- ¶5.3 经由普通列表初始化：若某子句直接归属于该元素，用该子句**拷贝初始化**元素；否则（花括号省略的情形）用所有归属于该元素子对象的子句组成的花括号列表拷贝初始化它。注 4：若子句本身是花括号列表，元素被列表初始化，对子聚合即递归应用本节。

!!! lawyer "普通子句的窄化检查在哪里？"
    C++23 中有一句明文：元素的初始化器是表达式且需要窄化转换时，程序非良构。当前草案按"归属"模型重写 ¶4–¶5 之后，这句话只在 ¶5.2.1（指派初始化器）中保留，¶5.3 中没有对应文字。但 `int a[] = {1, 2.0};` 非良构仍是标准例子（[[dcl.init.list]] 例 3）和所有实现的共识。

```cpp run ok
#include <cassert>
struct base1 { int b1, b2 = 42; };
struct base2 { base2() { b3 = 42; } int b3; };
struct derived : base1, base2 { int d; };

int main() {
  derived d1{{1, 2}, {}, 4};   // b1=1, b2=2, b3=42, d=4
  derived d2{{}, {}, 4};       // b1=0, b2=42（默认成员初始化器）, b3=42, d=4
  assert(d1.b1 == 1 && d1.b2 == 2 && d1.b3 == 42 && d1.d == 4);
  assert(d2.b1 == 0 && d2.b2 == 42 && d2.b3 == 42 && d2.d == 4);
}
```

注意 `base2` 不是聚合（有用户构造函数），所以它的元素 `{}` 走的是 [[dcl.init.list]] ¶3.5 的值初始化——调用 `base2()`。聚合初始化只是"分配初始化器"，每个元素**自己**怎么被初始化，仍由元素的类型决定。

¶5.2.1 中的"拷贝初始化"有实际后果：

```cpp
struct E { explicit E(int); };
struct P { E e; };
P p1{.e{1}};      // OK: 直接列表初始化
P p2{.e = 1};     // error: 拷贝初始化不能用 explicit 构造函数
P p3{1};          // error: 普通子句也是拷贝初始化
P p4{E{1}};       // OK
```

## 未显式初始化的元素（¶6–¶7）

¶6 对**非联合**聚合，每个非显式初始化的元素：

- ¶6.1 有默认成员初始化器：用它初始化；
- ¶6.2 否则，若不是引用：从**空初始化器列表**拷贝初始化（即 `T e = {};`）；
- ¶6.3 否则（没有默认成员初始化器的引用）：非良构。

对**联合**且初始化器列表为空：

- ¶6.4 若某变体成员有默认成员初始化器，用它初始化该成员；
- ¶6.5 否则第一个成员（若有）从空列表拷贝初始化。

¶6.2 的"从 `{}` 拷贝初始化"是一个精心的选择。早期标准写的是"值初始化"，改成"拷贝列表初始化"之后，元素若是带 `explicit` 默认构造函数的类，**不能**被隐式初始化：

```cpp
struct E { explicit E() = default; };
struct A { int i; E e; };
A a1{1, E{}};     // OK
A a2{1};          // error: e 从 {} 拷贝列表初始化，选中了 explicit 构造函数
```

对标量元素，`int x = {};` 即值初始化为 0，所以 `int arr[5] = {1};` 的其余元素为 0、`Point p = {1};` 的 `y` 为 0。这是 C 程序员熟悉的 `= {0}` 惯用法在 C++ 中的依据（C++ 中写 `= {}` 即可）。

¶7（例）展示了默认成员初始化器可以引用**前面**的元素：

```cpp run ok
#include <cassert>
struct S { int a; const char* b; int c; int d = b[a]; };
int main() {
  S ss = { 1, "asdf" };      // a=1, b="asdf", c=int{}=0, d=b[a]='s'
  assert(ss.c == 0 && ss.d == 's');
}
```

```cpp
struct A { std::string a; int b = 42; int c = -1; };
A x{.c = 21};    // a 从 {} 初始化；b 用 = 42；c 用 = 21
```

## 求值顺序与析构函数（¶8–¶10）

¶8 各元素的初始化**按元素顺序**严格有序：前一个元素的所有值计算和副作用先于后一个。这对任意花括号列表都成立（[[dcl.init.list]] ¶4），对圆括号聚合初始化也成立（[[dcl.init]] ¶15.6.2.2）。

¶9 类聚合也可以用**单个不带花括号的表达式**初始化，见 [[dcl.init]]——即 `S s = other_s;` 走普通的拷贝构造。

¶10 每个类类型元素（匿名联合成员除外）的**析构函数在聚合初始化的上下文中被潜在调用**（[[class.dtor]]）。原因（注 5）：若初始化第 k 个元素时抛出异常，前 k−1 个已构造的元素必须被销毁（[[except.ctor]]）。后果是：析构函数被删除或不可访问的元素会使聚合初始化非良构，即使根本不会抛异常：

```cpp
struct PD { ~PD() = delete; };
struct W { PD p; };
W* w = new W{};     // error: W 的聚合初始化潜在调用了 PD::~PD，而它被删除
```

## 未知边界数组（¶11）

¶11 用花括号列表初始化**未知边界数组**时，元素个数等于显式初始化的元素个数：

```cpp
int x[] = { 1, 3, 5 };                   // int[3]
struct X { int i, j, k; };
X a[] = { 1, 2, 3, 4, 5, 6 };            // X[2]：花括号省略
X b[2] = { { 1, 2, 3 }, { 4, 5, 6 } };   // 与 a 同值
```

未知边界数组**不能**用空列表 `{}` 初始化（脚注：C++ 没有零长度数组）。

注 6：默认成员初始化器**不能**决定成员数组的边界——因为若构造函数的 *mem-initializer* 初始化了该成员，默认成员初始化器会被忽略，此时边界就无从谈起：

```cpp
int z[] = {};                  // error: 零长度数组
struct S { int y[] = { 0 }; }; // error: 非静态数据成员的类型不完整
```

!!! impl
    Clang 和 GCC 把零长度数组作为扩展接受（`int z[] = {};` 只在 `-pedantic` 下警告），加 `-pedantic-errors` 才报错。

## 默认成员初始化器的自引用（¶13）

¶13 若成员的默认成员初始化器中有一个潜在求值的子表达式是**会使用该默认成员初始化器的聚合初始化**，程序非良构——否则会无限递归：

```cpp
struct A;
extern A a;
struct A {
  const A& a1 { A{a, a} };   // OK: 显式给出了两个元素，不使用默认成员初始化器
  const A& a2 { A{} };       // error: A{} 会使用 a1、a2 的默认成员初始化器，a2 的又包含 A{}
};
A a{a, a};                   // OK

struct B {
  int n = B{}.n;             // error
};
```

## 多维数组（¶14）

¶14 初始化多维数组时，**最右边的下标变化最快**（行主序，[[dcl.array]]）：

```cpp
int x[2][2] = { 3, 1, 4, 2 };            // x[0][0]=3, x[0][1]=1, x[1][0]=4, x[1][1]=2
float y[4][3] = { { 1 }, { 2 }, { 3 }, { 4 } };   // 只初始化"第一列"，其余为 0
```

## 花括号省略与"归属"（¶15–¶18）

¶15 是本节技术含量最高的一段：它定义了列表中每个子句**归属**（[[g:appertain|appertain]]）于哪个元素，由此实现**花括号省略**（[[g:brace-elision|brace elision]]）。

算法：维护一个"当前聚合元素序列"，初始为被初始化聚合的元素序列。对每个子句与当前元素，若满足以下任一条件，子句归属于该元素：

- ¶15.1 元素不是聚合；
- ¶15.2 子句以左花括号开头；
- ¶15.3 子句是表达式，且能形成把它转换为元素类型的隐式转换序列；
- ¶15.4 元素是没有元素的聚合（空聚合）。

否则——元素是聚合、子句不以 `{` 开头、也不能直接转换为元素类型——就把这个子聚合在序列中**替换为它自己的元素**，从第一个子元素开始、用同一个子句继续分析。如此直到子句耗尽；若还有子句无处归属，非良构。

```cpp
struct S1 { int a, b; };
struct S2 { S1 s, t; };
S2 x[2] = { 1, 2, 3, 4, 5, 6, 7, 8 };        // 完全省略花括号
S2 y[2] = { { { 1, 2 }, { 3, 4 } },
            { { 5, 6 }, { 7, 8 } } };        // 完全加花括号；x 与 y 同值
char cv[4] = { 'a', 's', 'd', 'f', 0 };      // error: 初始化器过多
```

¶15.3 是 C++11 以来的一个重要细节：若子句**可以直接转换**为子聚合的类型，它就归属于子聚合本身，而**不**进入子聚合内部。¶18 的例子：

```cpp
struct A { int i; operator int(); };
struct B { A a1, a2; int z; };
A a;
B b = { 4, a, a };   // 4 不能转换为 A，于是进入 a1 内部：b.a1.i = 4（花括号省略）
                     // a 可以转换为 A：b.a2 = a（拷贝），而不是进入 a2 内部
                     // 第三个 a：b.z = a.operator int()
```

¶16（例）`float y[4][3] = { 1, 3, 5, 2, 4, 6, 3, 5, 7 };` 与完全加花括号的 `{ {1,3,5}, {2,4,6}, {3,5,7} }` 等价：外层以 `{` 开头，但 `y[0]` 的初始化器不是，所以连续取 3 个。

¶17（注）**空的子聚合**也需要初始化器，如果后面的元素有初始化器的话：

```cpp
struct S { } s;
struct A { S s1; int i1; S s2; int i2; S s3; int i3; } a = {
  { },   // 必需：s1 是空聚合，¶15.4 使下一个子句归属于它
  0,
  s,     // 必需
  0
};       // s3、i3 不需要
```

¶15.4 让空聚合"吃掉"一个子句。这有一个反直觉的后果：

```cpp
struct Empty {};
struct D : Empty { int x; };
D d1{{}, 1};    // OK
D d2{1};        // error: 1 归属于空基类 Empty（¶15.4），而 Empty 不能从 1 初始化
```

### `std::array` 与双层花括号

`std::array<T, N>` 是一个包含 `T[N]` 成员的聚合，所以 `std::array<int, 3> a{{1, 2, 3}};` 是"完整花括号"写法，`a{1, 2, 3}` 依靠花括号省略。但元素本身也是聚合时，花括号省略会出人意料：

```cpp
#include <array>
struct Pt { int x, y; };
std::array<Pt, 2> ok{{ {1, 2}, {3, 4} }};   // OK: 外层 {} 对应 array，第二层对应内部数组
std::array<Pt, 2> bad{ {1, 2}, {3, 4} };    // error: 初始化器过多
```

`bad` 的分析：array 只有一个元素（内部数组 `Pt[2]`）。`{1, 2}` 以 `{` 开头，归属于**内部数组本身**；内部数组从 `{1, 2}` 初始化时，`1` 不能转换为 `Pt`，于是花括号省略进入 `Pt[0]`：`1 → [0].x`、`2 → [0].y`，`[1]` 从 `{}` 初始化。接着 `{3, 4}` 已无元素可归属，非良构。

C++11 时代 `std::array<int, 3> a = {1, 2, 3};` 能编译、`a{1, 2, 3}` 不能——那是因为当时花括号省略只允许在 `= {…}` 形式中发生。这一限制在 C++14 中被核心问题的解决移除。

## 注：带构造函数的元素与静态聚合（¶19–¶20）

¶19（注）聚合的元素可以是带用户声明构造函数的类，这类元素按 [[class.expl.init]] 初始化。¶20（注）静态存储期聚合的初始化是静态还是动态的，见 [[basic.start.static]]、[[basic.start.dynamic]]、[[stmt.dcl]]：全部元素都是常量初始化时，整个聚合是常量初始化的，放在 `.data`/`.rodata` 中，没有运行时代码。

## 联合（¶21–¶22）

¶21 用初始化器列表初始化联合时，**至多一个**显式初始化的元素：

```cpp
union u { int a; const char* b; };
u a = { 1 };                     // OK: 初始化第一个成员
u b = a;                         // OK: 拷贝
u c = 1;                         // error: 联合不能从单个非联合表达式初始化
u d = { 0, "asdf" };             // error: 两个显式初始化的元素
u e = { "asdf" };                // error: 普通列表只能初始化第一个成员，const char* 不能转为 int
u f = { .b = "asdf" };           // OK: 指派初始化器可以选择活跃成员
u g = { .a = 1, .b = "asdf" };   // error
```

在指派初始化器之前，只能用列表初始化联合的**第一个**成员——这是 C++20 指派初始化器最实用的场景之一。

¶22（注）联合是另一个聚合的成员时，其初始化子句的花括号同样可以省略。

## 指派初始化器：C++20 与 C99 的差异

C++20 的指派初始化器（[[P0329R4]]）是 C99 特性的一个**严格子集**。各项限制的理由都是"成员按声明顺序初始化、每个恰好一次"的模型：

| 写法 | C99 | C++20 | 理由 |
|---|---|---|---|
| `{.x = 1, .y = 2}` | ✓ | ✓ | |
| `{.y = 2, .x = 1}`（乱序） | ✓ | ✗（[[dcl.init.list]] ¶3.1） | C++ 的初始化有副作用和析构顺序，必须与声明顺序一致 |
| `{.x = 1, 2}`（指派与普通混用） | ✓ | ✗ | 位置语义与指派语义混合难以推理 |
| `{.in.i = 1}`（嵌套指派符） | ✓ | ✗（文法只有 `. identifier`） | 可以写成 `{.in = {.i = 1}}` |
| `{[3] = 1}`（数组指派符） | ✓ | ✗ | 与 lambda 语法冲突 |
| `{.x = 1, .x = 2}`（重复） | ✓（后者覆盖） | ✗（[[dcl.init#20]]） | 每个成员恰好初始化一次 |
| `{.x = 1.5}` 到 `int` | ✓（截断） | ✗（¶5.2.1） | 窄化 |
| `{.x{1}}` | ✗ | ✓ | 直接初始化 |

```cpp
struct In { int i, j; };
struct O { In in; int k; };
O o1{.in = {1, 2}, .k = 3};   // OK
O o2{.k = 3};                 // OK: in 从 {} 初始化
O o3{.in.i = 1};              // error: 嵌套指派符（C99 才有）
O o4{.k = 1, .in = {}};       // error: 顺序与声明不符
O o5{{1, 2}, .k = 3};         // error: 混用（In 不是基类）
```

!!! impl
    Clang 把乱序、混用、嵌套指派符都当作 C99 扩展接受，只给出警告（`-Wreorder-init-list`、`-Wc99-designator`），加 `-pedantic-errors` 才报错；可移植代码不要依赖这些扩展。

## 实现视角

!!! impl
    - **没有构造函数调用**：聚合初始化在代码生成上就是逐个元素的存储（或对常量初始化的静态对象，直接写入数据段）。`Point p{1, 2};` 在 `-O0` 下也只是两条存储指令。
    - **`std::is_aggregate`**（C++17）可以检测聚合性；常用于泛型代码区分"用 `T{args...}`"还是"用 `T(args...)`"。C++20 有了圆括号聚合初始化后，这种区分的必要性大大降低——`std::make_unique`、`emplace_back` 直接对聚合可用。
    - **聚合与结构化绑定、反射**：结构化绑定（[[dcl.struct.bind]]）对"所有非静态数据成员都是公开直接成员"的类有效，与聚合的定义相近但不同；许多"静态反射"库（在 C++26 反射之前）利用聚合初始化 `T{any, any, ...}` 是否良构来探测成员个数。
    - **C++20 聚合的类模板实参推导**：`template<class T> struct Agg { T t; }; Agg a{1};` 在 C++20 起可以推导 `T = int`，见 [[over.match.class.deduct]]。

## 历史与演进

!!! history
    - **C++98**：继承 C 的聚合初始化，加上"无用户声明构造函数、无私有成员、无基类、无虚函数"的定义，以及花括号省略。
    - **C++11**："用户声明"放宽为"用户提供"；默认成员初始化器使类不再是聚合；列表初始化把聚合初始化纳入统一框架（窄化检查从此适用于聚合）。
    - **C++14**：[[N3653]] 允许聚合有默认成员初始化器；放宽花括号省略的适用范围（`std::array<int, 3> a{1, 2, 3};` 从此合法）。
    - **C++17**：[[P0017R1]] 允许公开非虚基类；`explicit` 构造函数、继承构造函数使类不是聚合。
    - **C++20**：[[P1008R1]] 回到"用户声明"；[[P0329R4]] 指派初始化器；[[P0960R3]] 圆括号聚合初始化；聚合的类模板实参推导。
    - **当前草案**：基类成员的指派初始化（"聚合基"概念，¶4.1）{{c++26}}。

## 陷阱

!!! pitfall "C++17 → C++20 的破坏性变化"
    给聚合加一行 `S() = default;`（哪怕是为了"文档化"），在 C++20 中就让它不再是聚合，所有 `S s{1, 2};` 都会编译失败。

!!! pitfall "`D d{}` 与 protected 基类构造函数"
    聚合的基类若有 protected 构造函数，`D d;` 合法而 `D d{};` 非良构（注 1）。

!!! pitfall "空基类吃掉初始化器"
    `struct D : Empty { int x; }; D d{1};` 非良构：`1` 被分配给了空基类。要写 `D d{{}, 1};`。

!!! pitfall "引用成员与圆括号"
    `struct R { const int& r; }; R a{42};` 延长临时量寿命，`R b(42);` 不延长，`b.r` 立即悬垂（[[class.temporary]] ¶6.11）。

## 思考题

!!! question "1. 下面的类在 C++17 和 C++20 中分别是不是聚合？`X x{1, 2};` 是否良构？"
    ```cpp
    struct X { int a; int b; X() = default; };
    ```

<details markdown="1">
<summary>答案</summary>

- C++17：`X() = default` 在首次声明时被默认，不是用户提供的，也不是 explicit 的，所以 `X` 是聚合，`X x{1, 2};` 是聚合初始化，良构。
- C++20：`X() = default` 是用户声明的构造函数，`X` 不是聚合。`{1, 2}` 走 [[dcl.init.list]] ¶3.7 构造函数重载决议，只有默认构造函数和拷贝/移动构造函数，没有接受两个 `int` 的，非良构。
</details>

!!! question "2. `struct A { int i; operator int(); }; struct B { A a; int z; }; A a; B b{a};` 中，`a` 归属于哪个元素？若把 `operator int()` 删掉呢？"

<details markdown="1">
<summary>答案</summary>

`B` 的第一个元素是 `A a`，它是聚合。子句 `a` 不以 `{` 开头，但可以（通过拷贝构造函数——恒等转换）形成到 `A` 的隐式转换序列，满足 ¶15.3，所以 `a` 归属于 `b.a`，`b.a` 从 `a` 拷贝初始化；`b.z` 从 `{}` 初始化为 0。`operator int` 在这里无关紧要——删掉它结果不变。

`operator int` 只在子句**不能**转换为子聚合类型时才起作用：例如 `B b{4, a};` 中 `4` 不能转换为 `A`，于是进入 `b.a` 内部初始化 `b.a.i`；随后 `a` 对应 `b.z`，通过 `operator int()` 转换。
</details>

!!! question "3. 为什么 ¶6.2 对未显式初始化的元素用\"从 `{}` 拷贝初始化\"，而不是直接说\"值初始化\"？"

<details markdown="1">
<summary>答案</summary>

两者对大多数类型结果相同，差别在于：

1. **`explicit` 默认构造函数**：拷贝列表初始化会因为选中 explicit 构造函数而非良构，值初始化则不会。标准希望"省略的元素"与"写了 `{}` 的元素"行为一致——而 `A{1, {}}` 中的 `{}` 是拷贝列表初始化。
2. **元素本身是聚合**：从 `{}` 拷贝初始化一个聚合是**聚合初始化**（递归应用 ¶6），不经过（可能被删除的）隐式默认构造函数，规则与外层完全一致。
3. **`std::initializer_list` 构造函数**：类若有接受 `initializer_list` 的构造函数且无默认构造函数，从 `{}` 初始化会调用前者（[[dcl.init.list]] ¶3.7）。
</details>

## 小结

!!! summary
    - 聚合 = 数组，或"无用户声明/继承的构造函数、无私有/保护直接数据成员和直接基类、无虚函数和虚基类"的类（C++20 定义）。
    - 元素 = 直接基类（声明顺序）+ 直接非静态数据成员（不含匿名联合内部成员、无名位域、静态成员）。
    - 显式初始化的元素：由指派符（经关联元素）或子句归属确定；其余元素用默认成员初始化器，否则从 `{}` 拷贝初始化，引用则非良构。
    - 花括号省略：子句不以 `{` 开头、也不能直接转换为子聚合类型时，"钻进"子聚合。
    - 指派初始化器：只能用于类、必须按声明顺序、不能嵌套、不能重复、不能与普通子句混用（当前草案中，基类除外）。
    - 圆括号 `T(…)` 聚合初始化：允许窄化、无花括号省略、无指派、不延长引用成员绑定的临时量寿命。
