!!! tldr
    - 聚合是数组，或者没有用户声明的构造函数、没有私有或受保护的直接数据成员和基类、没有虚函数和虚基类的类。C++20 起，写一行 `S() = default;` 就会让类不再是聚合。
    - 聚合初始化不调用聚合自己的构造函数，而是把列表里的子句按顺序分给各个元素；元素是直接基类加上直接非静态数据成员。
    - 子句既不以 `{` 开头、又不能转换为当前元素的类型时，就钻进这个子聚合继续分配，这叫花括号省略。
    - 没写到的元素用默认成员初始化器，没有的话从 `{}` 拷贝初始化；引用成员没写到是非良构。
    - 指派初始化器 `.x = 1` 只能用于类，必须按声明顺序，不能嵌套，不能重复。

## 什么是聚合（¶1）

```cpp
struct Point { int x, y; };
Point p = {1, 2};       // 没有构造函数调用：p.x = 1，p.y = 2
int a[3] = {1, 2};      // a[2] 从 {} 初始化，即 0
```

**聚合**（[[g:aggregate|aggregate]]）是从 C 继承来的一类简单数据集合。聚合初始化不经过聚合自己的构造函数，而是从外部把初始化器逐个交给每个元素。

¶1 聚合是数组，或者满足下面四个条件的类：

- ¶1.1 没有用户声明的构造函数，也没有继承来的构造函数（[[class.ctor]]）；
- ¶1.2 没有 private 或 protected 的直接非静态数据成员；
- ¶1.3 没有 private 或 protected 的直接基类；
- ¶1.4 没有虚函数，没有虚基类。

每一条都对应从外部逐个初始化行不通的一种情况。声明了构造函数，说明作者想自己控制初始化，绕过它会破坏类的不变式。私有成员和私有基类在外部无法访问。虚函数和虚基类需要构造过程设置虚表指针和虚基偏移。

允许的东西也不少：公开的非虚基类、默认成员初始化器、成员函数、静态成员、用户声明的析构函数和赋值运算符。元素本身可以是有构造函数的类，`struct S { std::string s; int n; };` 是聚合，`s` 照样由 `std::string` 的构造函数初始化。

```cpp run ok
#include <type_traits>
struct A { int x; int y = 2; };          // C++14 起是聚合
struct Base { int b; };
struct D : Base { int d; };              // C++17 起是聚合
struct Del { Del() = delete; int x; };   // C++20 起不是聚合
static_assert(std::is_aggregate_v<A>);
static_assert(std::is_aggregate_v<D>);
static_assert(!std::is_aggregate_v<Del>);
D d{{1}, 2};                             // d.b == 1，d.d == 2
int main() {}
```

### 基类的受保护构造函数

<div class="compare" markdown="1">

```cpp ok
struct B {
protected:
  B() = default;
  int x;
};
struct D : B {};
D d1;   // OK
```

```cpp error
struct B {
protected:
  B() = default;
  int x;
};
struct D : B {};
D d2{}; // error
```

</div>

`D` 是聚合。`D d1;` 是默认初始化，调用 `D` 的隐式默认构造函数，它作为派生类的成员可以访问 `B` 的受保护构造函数。`D d2{};` 是聚合初始化，在 `d2` 的声明处从 `{}` 初始化基类元素 `B`，而那里访问不到 `B()`。注 1 正是说聚合初始化不能访问基类的受保护和私有成员，包括构造函数。

## 元素（¶2、¶12）

¶2 聚合的**元素**（[[g:aggregate-element|elements]]）：

- ¶2.1 数组：各个数组元素，按下标递增；
- ¶2.2 类：先是直接基类，按声明顺序；然后是直接非静态数据成员，按声明顺序，但不包括匿名联合里的成员。

¶12 的注补充，静态数据成员、无名位域都不是元素。匿名联合内部的成员不是元素，匿名联合本身作为一个整体是元素。

```cpp run ok
struct A {
  int i;
  static int s;   // 不是元素
  int j;
  int : 17;       // 无名位域，不是元素
  int k;
} a = { 1, 2, 3 };              // i = 1，j = 2，k = 3
static_assert(sizeof(A) > 0);
int main() { return a.k == 3 ? 0 : 1; }
```

## 子句归属于哪个元素：花括号省略（¶15–¶18）

```cpp run ok
struct S1 { int a, b; };
struct S2 { S1 s, t; };
S2 x[2] = { 1, 2, 3, 4, 5, 6, 7, 8 };   // 省略了所有内层花括号
S2 y[2] = { { { 1, 2 }, { 3, 4 } },
            { { 5, 6 }, { 7, 8 } } };   // 完整的花括号；x 与 y 的值相同
int main() { return x[1].t.b == y[1].t.b ? 0 : 1; }
```

内层花括号可以省略，这叫**花括号省略**（[[g:brace-elision|brace elision]]）。¶15 用**归属**（[[g:appertain|appertain]]）这个概念精确描述它：每个子句归属于聚合的某个元素，或者某个子聚合的元素。

¶15 把子句序列和一个元素序列逐个对齐。元素序列起初就是被初始化的聚合的元素。当前子句满足下面任一条件时，就归属于当前元素：

- ¶15.1 当前元素不是聚合；
- ¶15.2 子句以左花括号开头；
- ¶15.3 子句是表达式，并且能隐式转换为当前元素的类型；
- ¶15.4 当前元素是一个没有元素的空聚合。

都不满足时，当前元素一定是一个子聚合，并且子句不以 `{` 开头、也不能整体转换成它。这时在序列里把这个子聚合换成它自己的元素，用同一个子句从第一个子元素重新判断。子句用完时过程结束；还有子句无处归属，程序非良构，比如 `char cv[4] = { 'a', 's', 'd', 'f', 0 };`。

本机 Clang 对省略花括号的写法会给出 `-Wmissing-braces` 警告，提醒这样写不易读，但程序是良构的。

### 能转换就不往里钻（¶18）

第 3 条让子句优先归属于子聚合本身。¶18 的例子：

```cpp run ok
#include <cassert>
struct A { int i; operator int() { return 7; } };
struct B { A a1, a2; int z; };
int main() {
  A a{5};
  B b = { 4, a, a };
  assert(b.a1.i == 4);   // 4 不能转换为 A，于是钻进 a1：b.a1.i = 4
  assert(b.a2.i == 5);   // a 能转换为 A：b.a2 从 a 拷贝，不再钻进去
  assert(b.z == 7);      // 第三个 a 经 operator int() 初始化 b.z
}
```

### 空的子聚合也要占一个子句（¶17）

第 4 条让空聚合总是占用一个子句。所以后面还有元素要初始化时，空的子聚合必须写出初始化器（¶17 的注）：

<div class="compare" markdown="1">

```cpp ok
struct Empty {};
struct D : Empty { int x; };
D d1{{}, 1};   // OK
```

```cpp error
struct Empty {};
struct D : Empty { int x; };
D d2{1};       // error: 1 归属于
               // 空基类 Empty
```

</div>

### `std::array` 的双层花括号

`std::array<T, N>` 是只含一个 `T[N]` 成员的聚合。`std::array<int, 3> a{{1, 2, 3}};` 是完整的写法，`a{1, 2, 3}` 依靠花括号省略。元素本身也是聚合时，结果可能出人意料：

```cpp
#include <array>
struct Pt { int x, y; };
std::array<Pt, 2> ok{{ {1, 2}, {3, 4} }};   // OK
std::array<Pt, 2> bad{ {1, 2}, {3, 4} };    // error: 初始化器过多
```

`bad` 的外层列表里，`{1, 2}` 以 `{` 开头，所以归属于 `array` 唯一的元素，即内部数组 `Pt[2]`。内部数组从 `{1, 2}` 初始化时，`1` 不能转换为 `Pt`，于是钻进 `[0]`，`1` 和 `2` 分别给 `[0].x` 和 `[0].y`，`[1]` 从 `{}` 初始化。外层的 `{3, 4}` 已经没有元素可以归属，程序非良构。

## 显式初始化的元素（¶4–¶5）

¶4 列表初始化一个聚合时（入口在 [[dcl.init.list#3]] 第 4 项），先确定哪些元素是**显式初始化的元素**（[[g:explicitly-initialized-element|explicitly initialized elements]]）：

- ¶4.2 普通列表中，有子句归属于它或它的子对象的元素；
- ¶4.1 指派列表中，被指派的成员所属的元素（见下一节）；
- ¶4.3 其他元素都不是。注 2 指出 `{}` 不显式初始化任何元素。

¶5.3 对普通列表，如果有子句直接归属于某个元素，就用这个子句拷贝初始化它；如果是花括号省略的情形，就把归属于它的子对象的那些子句收集成一个花括号列表，用这个列表拷贝初始化它。注 4 指出，子句本身是花括号列表时，元素就是列表初始化的，元素是聚合时便递归地应用本节。

聚合初始化只负责分配子句，每个元素怎样从分到的子句初始化，仍由元素的类型决定：

```cpp run ok
#include <cassert>
struct base1 { int b1, b2 = 42; };
struct base2 { base2() { b3 = 42; } int b3; };
struct derived : base1, base2 { int d; };

int main() {
  derived d1{{1, 2}, {}, 4};
  derived d2{{}, {}, 4};
  assert(d1.b1 == 1 && d1.b2 == 2 && d1.b3 == 42 && d1.d == 4);
  assert(d2.b1 == 0 && d2.b2 == 42 && d2.b3 == 42 && d2.d == 4);
}
```

`base2` 有用户提供的构造函数，不是聚合，所以分给它的 `{}` 按 [[dcl.init.list#3]] 第 5 项值初始化，也就是调用 `base2()`。`base1` 是聚合，`{}` 让 `b1` 从 `{}` 初始化为 0，`b2` 使用默认成员初始化器。

元素是拷贝初始化的（[[dcl.init#13]]），所以 `explicit` 构造函数在这里用不上：

```cpp
struct E { explicit E(int); };
struct P { E e; };
P p1{E{1}};   // OK
P p2{1};      // error: e 从 1 拷贝初始化，explicit 构造函数不是候选
```

!!! lawyer "普通子句的窄化检查写在哪里"
    `int a[] = {1, 2.0};` 非良构，这是 [[dcl.init.list#3]] 例 3 里的标准例子，所有实现都会报错。但在当前措辞中，禁止窄化的明文只出现在 ¶5.2.1（指派初始化器的 `= expr` 形式）里，¶5.3 没有对应的句子。C++23 的措辞中有一句通用的规定；按归属模型重写 ¶4–¶5 后，它只保留在了指派的那一支。

## 指派初始化器（¶3–¶5）

```cpp run ok
struct In { int i, j; };
struct O { In in; int k; };
O o1{.in = {1, 2}, .k = 3};   // OK
O o2{.k = 3};                 // OK: in 从 {} 初始化
int main() { return o2.in.i; }
```

C++20 的**指派初始化器**（designated initializer，[[P0329R4]]）按名字指定成员。它来自 C99，但只取了一个子集。各项限制都出于同一个模型：成员按声明顺序初始化，每个成员恰好初始化一次。

| 写法 | C99 | C++ | 原因 |
|---|---|---|---|
| `{.y = 2, .x = 1}` 乱序 | 允许 | 非良构（[[dcl.init.list#3]] 第 1 项） | 初始化的副作用和析构顺序必须与声明顺序一致 |
| `{.in.i = 1}` 嵌套指派符 | 允许 | 非良构，文法只有 `. identifier` | 可以写成 `{.in = {.i = 1}}` |
| `{[3] = 1}` 数组指派符 | 允许 | 非良构 | 与 lambda 的语法冲突 |
| `{.x = 1, .x = 2}` 重复 | 后者覆盖 | 非良构（[[dcl.init#20]]） | 每个成员只初始化一次 |
| `{.x = 1.5}`，`x` 是 `int` | 截断 | 非良构（¶5.2.1） | 窄化 |
| `{.x{1}}` | 不允许 | 允许 | 直接初始化 |

本机 Clang 23 把乱序、嵌套指派符、指派与普通子句混用都当作 C99 扩展接受，只给出警告（`-Wreorder-init-list`、`-Wc99-designator`），加 `-pedantic-errors` 才报错。可移植的代码不要依赖它们。

### 指派的是哪个元素（¶3、¶4.1）

¶4.1 指派列表只能初始化类，不能初始化数组。每个指派符 `.id` 在类 `C` 中按成员查找（[[class.member.lookup]]）的结果必须恰好是一个非静态数据成员，而且只有一个子对象，这个子对象的类型是 `C` 的**聚合基**（[[g:aggregate-base|aggregate base]]）：`C` 本身，或者递归地是某个聚合基的直接基类。

被指派的成员不一定是 `C` 自己的元素。¶3 定义了成员 M 的**关联元素**（associated element）：M 本身是元素时就是 M，否则是包含 M 的那个元素。¶4.1 把每个被指派成员的关联元素算作显式初始化的元素。

这套措辞允许指派基类的成员，也允许先用普通子句初始化基类、再用指派子句初始化成员。它来自 [[P2287R5]]，是 C++23 之后的新措辞。C++20/23 中，指派符只能命名类自己的直接成员，而且一个列表里不能混用两种子句。

```cpp
struct A { int a1, a2; };
struct B : A { int b; };
struct C : A { int a1; };

A v0 = A{1, .a2 = 2};             // error: 普通子句只能归属于基类，而 A 没有基类
B v1 = B{.a1 = 1, .b = 2};        // 显式初始化的元素是 A 和 B::b
B v3 = B{A{1, 2}, .b = 3};        // 同上
B v4 = B{A{}, .a2 = 1, .b = 3};   // error: A 以两种方式初始化
C v5 = C{.a1 = 4};                // C::a1 隐藏了 A::a1；显式初始化的元素是 C::a1
```

¶4 的最后一句规定，一个元素同时经由普通子句和指派子句显式初始化，程序非良构，这就是 `v4` 的错误。截至写作时，本机 Clang 23 还没有实现指派基类成员，对 `v1` 报 field designator 'a1' does not refer to any field，所以这段代码只按标准原文分析。

### 被指派的元素怎样初始化（¶5.1–¶5.2）

- ¶5.2.1 元素是直接非静态数据成员时，用对应子句里的 *brace-or-equal-initializer* 初始化它。注 3 指出形式决定方式：`.m = e` 是拷贝初始化，`.m{e}` 是直接列表初始化。`= e` 形式需要窄化转换时非良构，虽然普通的拷贝初始化允许窄化。
- ¶5.2.2 元素是基类子对象 B 时，把所有关联元素为 B 的指派子句按原顺序收集成一个指派列表，用它拷贝初始化 B。多层基类就这样逐层传下去。
- ¶5.1 元素是匿名联合时，用 `{ D }` 初始化它，`D` 是指向联合内某个成员的那个指派子句；这样的子句只能有一个。

```cpp run ok
struct C {
  union { int a; const char* p; };
  int x;
} c = { .a = 1, .x = 3 };     // c.a == 1，c.x == 3
int main() { return c.a + c.x == 4 ? 0 : 1; }
```

¶5.2.1 的两种形式在 `explicit` 构造函数面前表现不同：

<div class="compare" markdown="1">

```cpp ok
struct E { explicit E(int); };
struct P { E e; };
P p1{.e{1}};   // 直接列表初始化
```

```cpp error
struct E { explicit E(int); };
struct P { E e; };
P p2{.e = 1};  // 拷贝初始化
```

</div>

## 没写到的元素（¶6–¶7）

```cpp run ok
#include <cassert>
struct S { int a; const char* b; int c; int d = b[a]; };
int main() {
  S ss = { 1, "asdf" };   // c 从 {} 初始化为 0；d 用默认成员初始化器，即 b[a]
  assert(ss.c == 0 && ss.d == 's');
}
```

¶6 非联合的聚合中，每个不是显式初始化的元素这样初始化：

- ¶6.1 有默认成员初始化器（[[class.mem]]）的，用它初始化；
- ¶6.2 否则，如果不是引用，就从空列表拷贝初始化，相当于 `T e = {};`；
- ¶6.3 否则，即没有默认成员初始化器的引用，程序非良构。

¶7 的例子说明默认成员初始化器可以用到前面的元素，如上面的 `d = b[a]`。对标量，`int x = {};` 就是 0，所以 `int arr[5] = {1};` 其余元素为 0。C 程序员熟悉的 `= {0}` 在 C++ 里可以直接写成 `= {}`。

¶6.2 写的是从 `{}` 拷贝初始化，而不是值初始化。区别在于 `explicit` 默认构造函数：拷贝列表初始化选中 explicit 构造函数时非良构。这样，省略一个元素和为它写一个 `{}` 的效果完全一样。

```cpp
struct E { explicit E() = default; };
struct A { int i; E e; };
A a1{1, E{}};   // OK
A a2{1};        // error: e 从 {} 拷贝列表初始化，选中了 explicit 构造函数
```

¶6.4–¶6.5 对联合：初始化器列表为空时，如果某个变体成员有默认成员初始化器，就用它初始化这个成员；否则第一个成员从空列表拷贝初始化。

## 数组：未知边界与多维（¶11、¶14、¶16）

¶11 用花括号列表初始化未知边界的数组时，数组的长度就是显式初始化的元素个数：

```cpp run ok
int x[] = { 1, 3, 5 };                   // int[3]
struct X { int i, j, k; };
X a[] = { 1, 2, 3, 4, 5, 6 };            // X[2]，依靠花括号省略
X b[2] = { { 1, 2, 3 }, { 4, 5, 6 } };   // 与 a 的值相同
static_assert(sizeof x == 3 * sizeof(int) && sizeof a == 2 * sizeof(X));
int main() {}
```

未知边界的数组不能用 `{}` 初始化，脚注说明 C++ 没有零长度数组。本机 Clang 和 GCC 把 `int z[] = {};` 作为扩展接受，`-pedantic` 下给出 `-Wzero-length-array` 警告。

注 6 指出，默认成员初始化器不能决定成员数组的长度：构造函数的 *mem-initializer* 会让默认成员初始化器被忽略，那时长度就无从确定。所以 `struct S { int y[] = { 0 }; };` 非良构。

¶14 多维数组按行主序初始化，最右边的下标变化最快（[[dcl.array]]）。¶16 的例子说明花括号省略在多维数组中怎样工作：

```cpp
int x[2][2] = { 3, 1, 4, 2 };                   // x[0][0]=3, x[0][1]=1, x[1][0]=4, x[1][1]=2
float y[4][3] = { { 1 }, { 2 }, { 3 }, { 4 } }; // 只初始化每行第一个，其余为 0
float z[4][3] = { 1, 3, 5, 2, 4, 6, 3, 5, 7 };  // 等同于 { {1,3,5}, {2,4,6}, {3,5,7} }
```

`z` 的初始化器以 `{` 开头，但 `z[0]` 的初始化器 `1` 不是，于是 `z[0]` 连续取走 3 个子句，`z[1]`、`z[2]` 同理，`z[3]` 从 `{}` 初始化。

## 联合（¶21–¶22）

¶21 用列表初始化联合时，至多只能有一个显式初始化的元素：

```cpp
union u { int a; const char* b; };
u a = { 1 };                     // OK: 初始化第一个成员
u b = a;                         // OK: 拷贝
u c = 1;                         // error: 不能从单个 int 初始化联合
u d = { 0, "asdf" };             // error: 两个显式初始化的元素
u e = { "asdf" };                // error: 普通子句只能给第一个成员 a
u f = { .b = "asdf" };           // OK: 指派初始化器可以选择其他成员
u g = { .a = 1, .b = "asdf" };   // error
```

在 C++20 之前，列表只能初始化联合的第一个成员，`f` 的写法是指派初始化器最实用的场景之一。¶22 的注提醒，联合是另一个聚合的成员时，它的花括号同样可以省略。

## 其他规则（¶8–¶10、¶13）

¶8 各元素按元素顺序初始化，前一个元素的所有值计算和副作用都先于后一个。圆括号形式的聚合初始化也是如此（[[dcl.init#15]] 第 6.2.2 项）。

¶9 类聚合也可以用单个不带花括号的表达式初始化，例如 `S s = other;`，这时走 [[dcl.init]] 的普通规则，调用拷贝构造函数。

¶10 聚合初始化会**潜在调用**（potentially invoke，[[class.dtor]]）每个类类型元素的析构函数，匿名联合除外。注 5 解释了原因：初始化第 k 个元素时抛出异常，前面已经构造好的元素必须销毁（[[except.ctor]]）。所以元素的析构函数被删除或不可访问时，聚合初始化就是非良构的，不管实际会不会抛异常：

```cpp error
struct PD { ~PD() = delete; };
struct W { PD p; };
W* w = new W{};   // error: 聚合初始化潜在调用了被删除的 PD::~PD
```

¶13 默认成员初始化器里，如果有一个潜在求值的子表达式是会用到这个默认成员初始化器本身的聚合初始化，程序非良构，否则会无限递归：

```cpp
struct A;
extern A a;
struct A {
  const A& a1 { A{a, a} };   // OK: 两个元素都显式给出，不用默认成员初始化器
  const A& a2 { A{} };       // error: A{} 要用 a2 自己的默认成员初始化器
};
A a{a, a};                   // OK
struct B { int n = B{}.n; }; // error
```

本机 Clang 23 拒绝 `a2` 和 `n`，但给出的理由是类定义完成之前就需要用到默认成员初始化器，这是它更早触发的另一条检查。

<details class="fine" markdown="1"><summary>其余条文</summary>

¶19 的注：聚合的元素可以是带用户声明构造函数的类，这类元素的初始化见 [[class.expl.init]]。

¶20 的注：静态存储期聚合的初始化是静态的还是动态的，见 [[basic.start.static]]、[[basic.start.dynamic]] 和 [[stmt.dcl]]。所有元素都是常量初始化时，整个聚合也是常量初始化的，直接放进数据段，没有运行时代码。

</details>

## 实现视角

!!! impl
    - 聚合初始化在代码生成上就是逐个元素的写入，常量初始化的静态对象则直接写进数据段。
    - `std::is_aggregate`（C++17）可以检测聚合，泛型代码过去用它决定写 `T{args...}` 还是 `T(args...)`。C++20 有了圆括号聚合初始化（[[dcl.init#15]]，[[P0960R3]]）后，`std::make_unique`、`emplace_back` 可以直接用于聚合，这种区分基本不再需要。
    - 在 C++26 反射之前，一些库（如 Boost.PFR）用 `T{any, any, ...}` 是否良构来探测聚合的成员个数。

## 历史

!!! history
    聚合的定义几乎每个版本都在变：

    | 标准 | 构造函数 | 默认成员初始化器 | 基类 |
    |---|---|---|---|
    | C++98/03 | 不能有用户声明的 | （没有这个特性） | 不允许 |
    | C++11 | 不能有用户提供的，`= default`、`= delete` 不算 | 有则不是聚合 | 不允许 |
    | C++14 | 同 C++11 | 允许（[[N3653]]） | 不允许 |
    | C++17 | 不能有用户提供的、explicit 的或继承的 | 允许 | 公开非虚基类（[[P0017R1]]） |
    | C++20 | 不能有用户声明的或继承的（[[P1008R1]]） | 允许 | 公开非虚基类 |

    C++11 改成用户提供，本意是让写了 `= default` 的类仍是聚合，结果留下了一个漏洞：`struct ND { ND() = delete; int x; }; ND a{};` 在 C++11–17 中合法，聚合初始化绕过了被删除的构造函数，私有的 `= default` 构造函数也一样。C++20 改回用户声明，堵上了漏洞，但 `struct S { S() = default; int i; }; S s{1};` 从此非良构。

    其他变化：C++11 起列表初始化把聚合初始化纳入统一框架，窄化检查也随之适用；C++14 通过 [[CWG1270]] 允许在 `T x{…}` 中省略花括号，`std::array<int, 3> a{1, 2, 3};` 从此合法（C++11 只允许 `= {…}` 形式省略）；C++20 加入指派初始化器（[[P0329R4]]）、圆括号聚合初始化（[[P0960R3]]）和聚合的类模板实参推导。

## 常见误解

!!! pitfall "加一行 `S() = default;` 只是写明有默认构造函数"
    C++20 起它让 `S` 不再是聚合，所有 `S s{1, 2};` 都会编译失败。

!!! pitfall "圆括号和花括号初始化聚合是一回事"
    `struct R { const int& r; };` 中，`R a{42};` 延长了临时量的生命期，`R b(42);` 不延长，`b.r` 立即悬垂（[[class.temporary#6]]）。两种形式在窄化、花括号省略和指派上也不同，见 [[dcl.init#15]] 的注 7。

## 思考题

!!! question "思考题 1"
    `struct X { int a; int b; X() = default; };` 在 C++17 和 C++20 中是不是聚合？`X x{1, 2};` 是否良构？

<details markdown="1">
<summary>答案</summary>

C++17：`X() = default` 在首次声明时显式预置，不是用户提供的，也不是 explicit 的，所以 `X` 是聚合，`X x{1, 2};` 是聚合初始化，良构。

C++20：`X() = default` 是用户声明的构造函数，`X` 不是聚合。`{1, 2}` 走 [[dcl.init.list#3]] 第 7 项的构造函数重载决议，候选只有默认、拷贝和移动构造函数，没有接受两个 `int` 的，所以非良构。
</details>

!!! question "思考题 2"
    `struct A { int i; operator int(); }; struct B { A a; int z; }; A a; B b{a};` 中，子句 `a` 归属于哪个元素？删掉 `operator int()` 会怎样？

<details markdown="1">
<summary>答案</summary>

`B` 的第一个元素 `b.a` 是聚合。子句 `a` 不以 `{` 开头，但能隐式转换为 `A`（恒等转换），满足 ¶15.3，所以归属于 `b.a`，`b.a` 从 `a` 拷贝初始化，`b.z` 从 `{}` 初始化为 0。`operator int` 与此无关，删掉它结果不变。

只有子句不能转换为子聚合类型时它才起作用，例如 `B b{4, a};`：`4` 钻进 `b.a` 初始化 `b.a.i`，随后 `a` 归属于 `b.z`，经 `operator int()` 转换。
</details>
