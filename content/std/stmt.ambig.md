C++ 继承自 C 的声明符语法允许在声明符外面加括号：`int (x);` 与 `int x;` 相同。同时，C++ 又有函数式类型转换 `T(x)`（[[expr.type.conv]]）。两者一结合，`T(x);` 这样的语句就有两种读法：

- **表达式语句**：把 `x` 转换为 `T`，然后丢弃结果；
- **声明**：声明一个类型为 `T`、名为 `x` 的变量（括号是多余的）。

[[stmt.ambig]] 规定了这种情况下怎么办：**当成声明**。这与 [[dcl.ambig.res]]（声明内部的"函数声明还是对象声明"，即"最令人烦恼的解析"）以及 [[stmt.pre#7]]（条件中的歧义）采取同一方向："只要能当声明，就是声明"。

## 规则（¶1）

¶1 语法中存在一个涉及表达式语句和声明的歧义：**以函数式显式类型转换为最左子表达式**的表达式语句，可能与**第一个声明符以 `(` 开头**的声明无法区分。此时该语句被视为**声明**（¶4 规定了例外）。

为什么选择声明？一是历史兼容：C 中 `int (x);` 一直是声明；二是若反过来选择表达式，就无法写出带括号的声明符（例如函数指针 `T (*p)(int);`），而后者是必需的。

## 需要看完整条语句（¶2）

¶2（注）如果语句**在语法上不可能**是声明，就不存在歧义，规则不适用。要判断能否是声明，有时需要检查**整条语句**，而不只是开头几个记号。

标准例 1 假设 `T` 是一个 *simple-type-specifier*：

| 语句 | 结果 | 原因 |
|---|---|---|
| `T(a)->m = 7;` | 表达式 | 声明符里不能出现 `->m`（尾置返回类型以外，见 ¶4） |
| `T(a)++;` | 表达式 | 声明符后不能跟 `++` |
| `T(a,5)<<c;` | 表达式 | `(a,5)` 不是合法的声明符；`<<` 也不能出现 |
| `T(*d)(int);` | 声明 | `d` 是指向函数 `T(int)` 的指针 |
| `T(e)[5];` | 声明 | `e` 是 `T[5]` |
| `T(f) = { 1, 2 };` | 声明 | 带初始化器的 `f` |
| `T(*g)(double(3));` | 声明 | `g` 是指向 `T` 的指针，初始化器是 `double(3)` |

最后一行很有意思：作为声明，它把 `double(3)` 作为 `T*` 的初始化器——这在**语义上**是非良构的，但**语法分析**不关心语义，它只要求"能解析为声明"。下面 ¶3 会再次强调这一点。

```cpp ok
struct S2 {
    int m;
    S2(int);
    S2(int, int);
    S2* operator->();
    S2& operator++(int);
    S2 operator<<(int);
};
void f(int a, int c) {
    S2(a)->m = 7;     // 表达式语句：S2(a) 是函数式转换
    S2(a)++;          // 表达式语句
    S2(a, 5) << c;    // 表达式语句
}
```

¶2 注的后半部分（标准例 2）是"剩下的情形都是声明"：

```cpp ok
class T {
public:
    T();
    T(int);
    T(int, int);
};
extern int h;
void f() {
    T(a);             // 声明：T a;
    T(*b)();          // 声明：b 是指向函数 T() 的指针
    T(c) = 7;         // 声明：T c = 7;
    T(d), e, f = 3;   // 声明：三个 T 类型的变量 d、e、f
    T(g)(h, 2);       // 声明：T g(h, 2);
}
```

注意 `T(d), e, f = 3;`：如果看成表达式，它是逗号表达式；但它也能解析为一个声明三个变量的声明，于是就是声明。

## 消解是纯语法的（¶3）

¶3 规定了消解的性质：

1. **纯语法**：除了"某个名字是不是 *type-name*"之外，名字的含义一般**不参与**、也**不受**消解的影响。
2. 为确定一个**限定名**是不是 *type-name*，必要时会**实例化类模板**（例如 `typename` 不可用的地方，`A<int>::X` 是类型还是值要看 `A<int>` 的定义）。
3. **消解先于解析**：被消解为声明的语句，完全可能是一个**非良构的声明**——编译器不会因为"当作声明会出错"而回过头去把它当作表达式。
4. 如果在解析过程中，查找发现**模板实参**中的某个名字绑定到了**正在解析的这个声明**（的一部分），程序非良构，**不要求诊断**（IFNDR）。

标准例 3 展示了第 3 点：

```cpp error
struct T1 {
    T1 operator()(int x) { return T1(x); }
    int operator=(int x) { return x; }
    T1(int) { }
};
struct T2 { T2(int) { } };
int a, (*(*b)(T2))(int), c, d;

void f() {
    // 消解要求把整条语句作为声明来解析：
    T1(a) = 3,
    T2(4),                    // 这里 T2 被声明为一个 T1 类型的变量……
    (*(*b)(T2(c)))(int(d));   // ……于是这里的 T2 不再是类型名，这一部分无法解析
}
```

逐步看：作为表达式，整条语句是合法的（一系列赋值、函数调用组成的逗号表达式）。但它**也能**作为声明的开头被识别：`T1(a) = 3` 是一个带初始化器的声明符，`T2(4)` 看起来像一个名为 `T2`、初始化器为 `4` 的声明符……于是消解选择了声明。一旦 `T2` 被声明为 `T1` 类型的变量，后面的 `T2(c)` 中的 `T2` 就不再是类型名了，最后一部分无法解析——但此时已经无法回头。

这个例子说明了"消解先于解析"的真实含义：编译器（概念上）先决定"这是声明"，再按声明来解析；解析中途出错就是错，而不是回退。

!!! lawyer "实现如何做到"
    实际编译器使用**试探性解析**（tentative parsing）：从语句开头尝试按声明解析，若遇到不可能出现在声明中的记号（如 `->m`、`++`）就判定为表达式。试探阶段通常只做语法判断和"是否是类型名"的查找，不做完整的语义分析——正对应 ¶3 的"纯语法"。像例 3 这样，试探阶段（尚未真正声明 `T2`）认为可以是声明、而真正解析时（`T2` 已被声明为变量）失败的情形，正是"消解先于解析"的产物。Clang 的 `Parser::isCXXDeclarationStatement` 一族函数实现了这一逻辑。

## 尾置返回类型与 auto(x)（¶4）

¶4 一条语法上有歧义的语句，如果能作为**最外层声明符带尾置返回类型**（*trailing-return-type*）的声明，那么只有当它**以 `auto` 开头**时才被视为声明。

背景：C++23 引入了 `auto(x)` / `auto{x}`（衰变复制，[[expr.type.conv]]），于是 `auto(s)` 也可以是一个函数式类型转换。而 `auto f() -> R;` 是带尾置返回类型的函数声明，括号形式 `auto(f)() -> R;` 同样合法。这就产生了新的歧义：

- `auto(s)()->M;` 可以读作"把 `s` 衰变复制，调用其 `operator()`，访问结果的成员 `M`"；
- 也可以读作"声明函数 `s`，无参数，返回类型是 `M`"。

¶4 的规则是：以 `auto` 开头时（并且确实能构成带尾置返回类型的声明），按**声明**处理；**不以** `auto` 开头时（例如 `S(s)()->M;`），即使 `M` 是类型名、语句能被解析为带尾置返回类型的声明，也按**表达式**处理——因为尾置返回类型要求声明说明符是 `auto`，以其他类型开头的"声明"必定在语义上非良构，没理由选它。

标准例 4：

```cpp ok
struct M;
struct S {
    S* operator()();
    int N;
    int M;
    void mem(S s) {
        auto(s)()->M;      // 表达式：在类作用域中 S::M 隐藏了 ::M，M 不是类型名，不可能是声明
    }
};
void f(S s) {
    {
        auto(s)()->N;      // 表达式：N 不是类型名
        auto(s)()->M;      // 函数声明：声明函数 s，返回类型 ::M（以 auto 开头）
    }
    {
        S(s)()->N;         // 表达式
        S(s)()->M;         // 表达式：不以 auto 开头（¶4）
    }
}
```

（`mem` 中 `M` 是成员 `S::M`——一个 `int` 数据成员——而不是类型 `::M`，所以那一句不可能是声明，也就不涉及 ¶4。）

## 实际后果：RAII 守卫的经典 bug

这一节最常见的"受害者"是 RAII 守卫对象：

```cpp ok
#include <mutex>
std::mutex m;
int counter;
void inc() {
    std::unique_lock<std::mutex>(m);   // 声明了一个名为 m 的局部 unique_lock（默认构造，不持有任何锁）！
    ++counter;                         // 没有加锁：数据竞争
}
```

这条语句被消解为声明 `std::unique_lock<std::mutex> m;`：它遮蔽了全局的 `m`，并默认构造一个不关联任何互斥量的锁。程序能编译，却完全没有加锁。若换成 `std::lock_guard`（没有默认构造函数），则会因为"没有匹配的构造函数"而编译失败——这反倒是好事。Clang 对两者都会给出 `-Wvexing-parse` 警告，提示括号被消解为声明符中多余的括号。

修正方法：

| 写法 | 效果 |
|---|---|
| `std::unique_lock<std::mutex> lk(m);` | 推荐：给守卫起名字 |
| `std::unique_lock lk{m};` | 同上，使用 CTAD |
| `std::unique_lock<std::mutex>{m};` | 表达式语句：创建临时锁并**立即**释放——同样错误！ |
| `(std::unique_lock<std::mutex>(m));` | 表达式语句：同样是立即释放的临时对象 |

后两行虽然不再是声明，但临时对象在完整表达式结束时销毁，锁立刻就释放了。守卫对象必须有名字。

## 与 [dcl.ambig.res] 的关系

[[stmt.ambig]] 处理的是**语句级**的歧义："这整条语句是表达式还是声明"。[[dcl.ambig.res]] 处理的是**已经确定是声明之后**，声明内部的歧义："这个声明符声明的是函数还是对象"，以及"这个括号里是参数声明还是表达式"。例如：

```cpp ok
struct Timer {};
struct Widget { Widget(Timer); };
void f() {
    Widget w(Timer());   // [dcl.ambig.res]：声明了一个函数 w，参数是"返回 Timer 的函数（指针）"
    Widget v{Timer{}};   // 花括号消除歧义：对象
    (void)v;
}
```

两者方向一致：都偏向声明。要强制得到表达式或对象，最简单的办法是使用花括号初始化或额外的括号。

## 陷阱

!!! pitfall "`T(x);` 在 x 已声明时"
    在同一作用域中，`T(x);` 是对 `x` 的**重新声明**：如果 `x` 已经声明为其他类型，就是编译错误；在内层块中，它会**遮蔽**外层的 `x`。程序员的本意（创建临时对象或调用转换）完全落空。

!!! pitfall "以为编译器会\"根据语义选择\""
    消解只看"是不是类型名"。即使当作声明会导致语义错误（比如类型没有默认构造函数），编译器也不会改为当作表达式——¶3 的"消解先于解析"。

## 思考题

!!! question "1. 下面每条语句是声明还是表达式？（`T` 是类类型，`x` 是 int 变量）"
    ```cpp
    T(x);           // (a)
    T(x).f();       // (b)
    T(x) + 1;       // (c)
    T(*x);          // (d)
    T(x)(1);        // (e)
    ```

<details markdown="1">
<summary>答案</summary>

- (a) 声明：`T x;`（在 `x` 所在的同一作用域中则是重复声明错误）。
- (b) 表达式：声明符后不能出现 `.f()`。
- (c) 表达式：声明符后不能出现 `+ 1`。
- (d) 声明：`T* x;`。
- (e) 声明：`T x(1);`——用 `1` 直接初始化一个名为 `x` 的 `T`。
</details>

!!! question "2. 为什么 ¶4 只要求\"以 auto 开头\"，而不检查整条语句在语义上是否合法？"

<details markdown="1">
<summary>答案</summary>

因为消解必须是**语法层面**的（¶3）。带尾置返回类型的函数声明，其声明说明符必须是 `auto`（[[dcl.fct]]），这是一个只看记号就能判断的条件，正好可以用来在语法层面排除"必定非良构的声明"这一选项。如果允许语义检查参与消解，就会出现"把语句当声明→发现语义错误→再当表达式"的回溯，而这正是 ¶3 所禁止的。
</details>

## 小结

| 规则 | 内容 |
|---|---|
| 歧义来源 | 以函数式转换开头的表达式语句 vs. 第一个声明符以 `(` 开头的声明 |
| 默认 | 视为声明 |
| 不歧义的情形 | 整条语句在语法上不可能是声明（要看完整条语句） |
| 性质 | 纯语法；只关心名字是否是类型名；必要时实例化类模板 |
| 先于解析 | 消解为声明后，声明非良构就是错，不回退 |
| IFNDR | 解析中模板实参里的名字绑定到正在解析的声明 |
| 尾置返回类型 | 只有以 `auto` 开头时才视为（带尾置返回类型的）声明 |
| 实践 | RAII 守卫必须有名字；`Type(var);` 是声明 |
